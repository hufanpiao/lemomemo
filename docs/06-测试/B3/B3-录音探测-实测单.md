# B3 录音探测（R-68）实测单

- 依据：[B3 任务单](../../09-路线图/B3-任务单.md) 第二节 Q1 的“测法”和“判定”；函数说明见 [B3-voice-probe探测函数](../../09-路线图/B3-voice-probe探测函数.md)；探测页是前端 FA-0（`src/app/dev/VoiceProbe.tsx`）。
- 目的：看 iPhone 录的 AAC、电脑 Edge 录的 WebM 能不能直接传给 Gemini 转写。能传就直传；不能就把这一种格式改成先压 MP3 再传。
- 谁来测：iPhone 由负责人测，20 段，约 30～45 分钟。Windows Edge 由 QA 测，20 段。主持人负责部署预览、告诉大家用哪个模型，测完收表。
- 有效期：voice-probe 到 **2026-11-17 24:00（首尔）** 失效，之后一律回 410。

## 〇、先读：隐私

- **只念下面第二节写好的句子**，一字不改照念就行，念错了重录这一段。录音和转写会送进谷歌免费版接口，可能被人工审阅（R-62）。
- 不要说真实的人名、电话、地址、账号，也不要说任何私事；句子里也没有这些。
- 周围有人说话的话，换个安静的地方。别人的声音被录进去，等于把别人的话也送出去了。
- 探测页不存录音，传完就丢。也不显示账号信息。截图只截结果区。

## 一、iPhone 上怎么操作（负责人）

1. 用 iPhone Safari 打开预览版（地址由主持人发），用 **lemotest 账号**登录。只有白名单里的账号能用；换别的账号，所有请求都会回 404。
2. 登录后，把地址栏末尾改成 **`#/dev-csp/voice`** 打开探测页。页面标题是“Voice probe (R-68)”。
3. 先截一张 **isTypeSupported** 列表的图，记进第三节表头，看哪几种显示 yes。
4. 大按钮上面并排两个模型按钮（`gemini-3.1-flash-lite`、`gemini-3.5-flash-lite`），点 **`gemini-3.5-flash-lite`**（Q6，主持人 11-09 确认，见环境清单 `GEMINI_API_KEY` 那一行；页面默认选的是 3.1，一定要先点 3.5），选中的会变成黑底白字。对照用的“另一个模型”是 `gemini-3.1-flash-lite`。
5. 按住大按钮“Hold to record”，等约半秒，照念一句，念完再松手。一段最长 50 秒，句子都很短，不会碰到上限。
   - 第一次会弹出麦克风权限，点“允许”。
6. 松手后，结果区最上面多出一段（#1、#2……），**同一段录音会按两种标注各传一次**：iPhone 是 `audio/mp4` 和 `audio/aac` 两行，Edge 是 `audio/webm` 和 `audio/webm;codecs=opus` 两行。两行都显示出结果再念下一句。
7. 20 句全部念完后，最多再用另一个模型念第 1～5 句做对照。第二节的 5 句韩文也可以加录，见第四节的额度说明。

## 三、每段怎么记

每段两行结果，**两行各记一行表**。字段都照页面上抄：

- **recorder**：段号那一行 `recorder` 后面的类型，是这台设备实际录出来的格式，例如 `audio/mp4`。
- **标注**：每行开头加粗的那个，例如 `audio/aac`。
- **HTTP**：`HTTP` 后面的数字。正常是 200。
- **result**：HTTP 后面那个词：`ok`、`error`、`timeout`、`quota`、`bad_output`，或者错误码。
- **gemini_http**：Gemini 自己回的状态。格式被拒通常是 400，超时时显示 `-`。
- **字节**：`B` 前面的数字。
- **转写对得上吗**：看灰色那行转写，和念的句子对照，凭感觉填“对 / 大致对 / 不对 / 空”。只凭感觉，不打分（R-167）。标点、数字写成阿拉伯数字还是汉字，都不算错。
- **gemini ms**：选填，用来看耗时。

## 四、遇到这些情况

| 页面显示 | 意思 | 怎么办 |
|---|---|---|
| HTTP 404 | 账号不在白名单、登录过期，或者打开的不是预览版 | 退出重新用 lemotest 登录；还不行就停下，告诉主持人 |
| HTTP 410 | 探测函数过期了（11-17 以后） | 停下，告诉主持人 |
| HTTP 413 | 录音超过 600 KB | 本身就是要量的数据，照记。说明这台设备一段 50 秒以内的录音可能超限 |
| HTTP 429 `daily_limit` | 今天 100 次用完了 | 停下，等太平洋时间零点（首尔时间 17:00）以后接着测 |
| HTTP 503 `try_later` | 服务端暂时连不上 | 等一分钟重录这一段 |
| HTTP 200，result 是 `error`，gemini_http 400 | Gemini 拒了这种格式 | 照记，这就是要找的“格式被拒” |
| HTTP 200，result 是 `timeout` | Gemini 15 秒内没回 | 照记，重录一次也记一行，备注写“重录” |
| `uploading…` 一直不变 | 网络问题，30 秒后会显示失败 | 照记，换网络再录这一段 |

**额度**：每传一次扣 1 次，每段扣 2 次（两种标注各一次），全局每天（太平洋日期）100 次，所有测的人共用。iPhone 20 段是 40 次，Edge 20 段也是 40 次，加起来 80 次。对照 5 段再加 10 次，韩文 5 段再加 10 次，总共正好 100 次。两人同一天测的话，先做完两边各 20 段，对照和韩文放到最后。

## 五、判定（照 Q1）

**每一种标注单独判**，iPhone 的 `audio/mp4`、`audio/aac`，Edge 的 `audio/webm`、`audio/webm;codecs=opus`，各判各的：

- **直传**：这一种标注的 20 段全部 HTTP 200、result 是 `ok`、转写非空，而且测的人看转写对得上。
- **走 MP3**：这一种标注有被拒的（gemini_http 4xx、result 是 `error`），或者转写普遍不对。
- 偶尔一段 `timeout`、重录后正常的，在备注里写清楚，交后端判断。不能自己算“通过”，也不能自己算“不通过”。
- 韩文对照不进判定，只记录。
