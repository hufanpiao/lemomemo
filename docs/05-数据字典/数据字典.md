# 数据字典

数据存在 claude.ai 云端数据库（[ADR-002](../04-决策/ADR-002-用云端数据库保存数据.md)），两个集合：`events`（日程）、`todos`（待办）。文档 id 由数据库生成（页面里是 `doc().id`），不在字段里；记录里即使带了 `id` 字段也会被忽略，页面一律以文档 id 为准（安全审查第 2 条，`platform/claude-db.js` 与 `data/normalize.js`）。

- 依据：v1/v2 源码的写入代码（v1 `add()`，v2 弹出层 `submit`、勾选、改期），[设计方案-v2](../02-设计/设计方案-v2.md) 的“数据字段”，[修改清单-v3](../02-设计/修改清单-v3.md) 和 [PM-B](../03-评审/第二轮/第二轮_PM-B_提醒功能.md)。
- “谁会写”：**页面**＝planner 页面；**Claude**＝在聊天里代记或定时任务。Claude 写入的数据可能缺字段或类型不对，页面读入时按默认值整理（v3 normalize）。
- 时间戳一律是毫秒数（`Date.now()`）；日期 `YYYY-MM-DD`，时间 `HH:MM`（24 小时制，补零）。

## deletedAt 的用法（v3 结构调整起）

- **删除**：页面上的“删除”不再从数据库移除记录，而是写 `{deletedAt: 当前毫秒数, updatedAt}`（`data/write.js` 的 `softDelete`）。v2 的“5 秒后真删”已去掉。
- **撤销 / 恢复**：写 `{deletedAt: null, updatedAt}`（`restore`）。提示条上的“撤销”保留 8 秒，点了就是恢复。
- **读取**：快照进来先经 `data/normalize.js` 整理：正数保留，`0`、空值、乱写的值一律当作 `null`（没删除）。页面上所有列表、计数、“下一件事”、项目名单都只用 `visEv()` / `visTd()`，也就是过滤掉 `deletedAt` 有值的条目。
- **Claude 在聊天里**：删除也写 `deletedAt`，不要真删；查询时同样过滤掉 `deletedAt` 有值的条目。
- **还没做**：“最近删除”界面、超过 30 天的彻底清理（ADR-006）、导出时标出已删除条目。

## 页面对读入数据的整理（data/normalize.js）

| 字段 | 整理规则 |
|---|---|
| title / project / note / rawText | 不是字符串或数字就置空；分别截到 160 / 40 / 200 / 1000 字 |
| date / due | `YYYY-M-D`、`YYYY/MM/DD` 等补零成 `YYYY-MM-DD`；认不出就置空 |
| time | `H:M`（含中文冒号）补零成 `HH:MM`；认不出就置空（当全天） |
| durationMin | 转数字；不是正数就按 60 |
| done / important | 只有 `true`、`"true"`、`1` 算真；字符串 `"false"` 算假 |
| createdAt / updatedAt / doneAt | 转数字；不是数字就按 0 |
| deletedAt | 见上 |
| 其他字段 | 原样保留（例如 v3 的提醒字段） |

## 不做的字段
- `kind`（对片/交付/会议，PM-2 建议）：v2 未采纳。
- `icsFor`（PM-B 建议）：.ics 做不了，不加（[ADR-004](../04-决策/ADR-004-不用ics.md)）。
- `repeat`（PM-D⑤ 重复事项）：v3 暂不做。

## v3 计划中的规则补充（2026-10-23，依据需求澄清和代码复审）
- **remindAt 不再只在保存时计算**：页面在整理数据和时钟每分钟触发时，用 `logic/remind.js` 的纯函数实时推算“实际提醒时间”= max(按 remindMin / remindDays 算出的时间, snoozeAt)。数据库里的 remindAt 只是方便定时任务读取的缓存，以推算结果为准。所以 Claude 从聊天里写入的条目不用自己算 remindAt。
- **缺提醒字段时按默认规则提醒**（[需求澄清 #2](../02-设计/需求澄清-v3.md)）：有时间的日程提前 15 分钟；全天日程前一天 20:00；待办截止当天 9:00，标了重要的前一天 9:00。想关掉，就把 remindMin 或 remindDays 写成 null。
- **只发 60 分钟内的提醒**（[#30](../02-设计/需求澄清-v3.md)）；推送提前 15 分钟发（[#5](../02-设计/需求澄清-v3.md)）。
- **snoozeAt**：只有日期、时间或提醒选项改了才清空（[#28](../02-设计/需求澄清-v3.md)）。
- **deletedAt**：软删除；页面打开时清理 30 天前删除的条目，每天最多一次（[#18](../02-设计/需求澄清-v3.md)）；导出备份包含已删除的条目（[#19](../02-设计/需求澄清-v3.md)）。

## logs（运行日志，v3 新增，[ADR-010](../04-决策/ADR-010-运行日志.md)）

每台设备每天一条文档，文档 id 是 `<YYYY-MM-DD>_<设备号>`：页面的设备号是本机随机生成的（`pv-device`），Claude 写入时用 `claude`，定时任务用 `task`。

| 字段 | 类型 | 含义 |
|---|---|---|
| day | string `YYYY-MM-DD` | 日期 |
| device | string | 设备号 |
| entries | array（最多 500 条，超出时丢掉最早的） | 记录列表，每条见下表 |
| updatedAt | number（毫秒） | 最后写入时间 |

entries 里每一条：

| 字段 | 类型 | 必有 | 含义 |
|---|---|---|---|
| t | number（毫秒） | 是 | 发生时间 |
| kind | `op` / `run` | 是 | 操作 / 运行 |
| act | string | 是 | 动作，例如 `create`、`update`、`done`、`undone`、`reschedule`、`delete`、`restore`、`purge`、`save_failed`、`timeout`、`disconnect`、`reconnect`、`remind_shown`、`remind_ack`、`remind_snooze`、`push_ok`、`push_failed`、`snapshot_ok`、`snapshot_failed` |
| src | `page` / `chat` / `task` | 是 | 来源 |
| coll | `events` / `todos` | 否 | 涉及的集合 |
| id | string | 否 | 涉及的条目编号 |
| fields | string[] | 否 | 修改时改了哪些字段名 |
| code | string | 否 | 错误码（中性错误码，例如 `network`、`timeout`、`forbidden`） |

**不记录**标题、备注、原话、项目名等任何内容。保留 90 天，页面打开时清理。Claude 在聊天里代记、修改、删除时，也往 `<日期>_claude` 这条里追加一条（src 填 `chat`）。

## v3 已实现（T2、T2b、T3，2026-10-23）
- 整理（`data/normalize.js`）：remindMin 只认 0、15、30、60、1440，remindDays 只认 0、1；null 表示不提醒；不合法或缺失时去掉该字段，按默认规则提醒。snoozeAt、notifiedFor、remindAt 统一为正数毫秒或 null。待办一律有 note。
- 写入（`data/write.js`）：编辑只写改过的字段；每次写入都更新 remindAt 缓存；改了日期、时间或提醒选项，并且原来有 snoozeAt 时才清空它；“知道了”写 notifiedFor，“10 分钟后”写 snoozeAt；软删除时 remindAt 清空；30 天前删除的条目在每天第一次打开页面时彻底删除。
- 存储接口新增 `get`、`list`（两个适配器都已实现，契约测试覆盖）。

## 导出备份文件（v3 T10，“导出备份（JSON）”）
文件名 `planner-backup-YYYY-MM-DD.json`（UTF-8），由 `data/archive.js` 的 `backup()` 生成、`platform/download.js` 交给平台保存。数据库里有什么就导出什么（不经过页面的字段整理），已删除的条目也在内并带 `deletedAt`（需求澄清 #19）。

| 字段 | 类型 | 含义 |
|---|---|---|
| app | string | 固定为 `"planner"` |
| format | number | 备份格式版本，目前为 1 |
| exportedAt | number（毫秒） | 导出时刻 |
| counts | object | `{events, todos, logs}` 各自条数 |
| events | array | events 集合的全部文档，每条含 `id` 和全部字段 |
| todos | array | todos 集合的全部文档，每条含 `id` 和全部字段 |
| logs | array | logs 集合的全部文档（运行日志，只有编号和字段名，不含内容） |
| logsError | string | 可选；读不到 logs 时的错误码，此时 logs 为空数组 |
