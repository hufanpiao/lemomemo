# 人员名单

除“产品负责人”外，所有成员都是由主持人（Claude）按角色派出的 AI 助手（子代理）。每人只按分配的角色和任务独立工作，互相看不到对方写的内容，做完交一份报告。报告由主持人核实后再采纳，采纳和不采纳都有记录，见 [评审索引](../03-评审/评审索引.md)。

同一位成员可以接着追问或复查，复查时保持原来的评判标准。

## 每个版本的固定流程

0. **备份**：开始新版本前，先备份云端数据和源码（[ADR-009](../04-决策/ADR-009-每个版本前备份数据和源码.md)），发布前再备份一次。
1. 需求：产品负责人提出，主持人记入 [需求记录](../01-需求/需求记录.md)。
2. 设计 / 评审：按需请产品经理或 UI 设计经理评审，主持人汇总成修改清单。
3. 开发：主持人在 src/ 下开发，遵守 [架构约定](../10-架构/架构约定.md)，同时写单元测试；`python build/build.py` 会自动检查分层规则，不通过就不能发布。
4. 代码审查、安全审查：上线前审一遍。
5. QA 测试：手机宽度（375 px）和电脑宽度（1280 px）、浅色和深色都测，写进 [测试记录](../06-测试/测试记录.md)。
6. UI 复查：界面有变动时，请同一批 UI 设计经理复查。
7. 发布：发布到 claude.ai，写进 [发布记录](../08-发布/发布记录.md)，冻结到 archive/releases/。
8. 实机验收：产品负责人按 [iPhone 实机验收清单](../06-测试/iPhone实机验收清单.md) 在手机上用一遍，发现的问题进入下一个版本。
