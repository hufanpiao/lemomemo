# 负责人操作：设 VAPID 密钥（网页推送用的钥匙）

- 日期：2026-11-03（运维写，B2 任务单 O-1）
- 依据：B2 任务单第三节 O-1、架构审 M9（私钥格式按后端 BE-1 定的 JWK）、B2 安全审查 C-8、C-9；R-282（不另存，丢了重新生成）、R-283（VAPID_SUBJECT 做成参数）
- 脚本：`tools/keys/set-vapid-keys.ps1`（11-03 已用本机假服务从头跑通；**要先经代码审查、安全审查审过，主持人通知后再运行**）
- 预览、正式**各做一次**，两次是两对不同的钥匙。B2 只做预览；正式在 B7a 上线前用同一个脚本 `-Target prod` 再做，**正式那次运行前要先满足下面“正式那次运行前”一节的两个前提**（安全审查 O1-P1、O1-P2）。
- 每次约 15 分钟。你要做四件事：生成临时令牌、运行脚本、粘贴令牌、把脚本打印的**公钥**填进 GitHub 变量。

## 这把钥匙是什么

- 网页推送要一对钥匙：**私钥**放在服务器函数那边（Supabase 的 Edge Function Secrets），**公钥**编进网页里，浏览器订阅推送时用。
- 脚本在你电脑的内存里生成这一对，一次写进 Supabase 三项：
  - `VAPID_PRIVATE_KEY`：私钥（一行 JWK 格式）。**屏幕上不显示、不存任何文件、不经过剪贴板**；
  - `VAPID_PUBLIC_KEY`：公钥。服务器函数每次启动时拿它和私钥核对是不是一对，对不上就一条推送都不发（安全审查 C-9）；
  - `VAPID_SUBJECT`：联系地址，默认 `https://lemomemo.com`。
- 写进去之前，脚本先自检这一对钥匙：用私钥签一条消息，再用公钥验，验不过就停下，什么都不写。
- 公钥是**公开值**，不是密钥。脚本最后把它打印出来（87 个字符，以 B 开头），你把它填进 GitHub 仓库变量。
- **不另存**（R-282）：私钥丢了不用找，重新跑一次脚本换一对就行，见下面“换钥匙”。脚本不会提示你存进密码管理器，也不用存。

## 步骤（预览）

1. **生成临时令牌**：打开 <https://supabase.com/dashboard/account/tokens>，新建令牌：
   - 类型选项目级（Scoped），**只选这一个项目**：预览选 lemomemo-preview（正式那次选 lemomemo-prod）；
   - 到期选 1 天；
   - 权限只勾这两项，其余都不给：
     - Edge Function Secrets：Read-write（写三项钥匙，并核对写进去了）
     - Project Settings：Read（核对项目名，防止贴错环境）
   - 生成后点复制。不要粘贴到别的地方。
   - 这两项权限的名字是照 Supabase 官方文档写的，**没有在真实的令牌页面上核对过**。页面上的写法不一样，或者脚本报 HTTP 401、403，截图发给主持人。
2. **确认剪贴板历史是关着的**：设置 › 系统 › 剪贴板 › 剪贴板历史。脚本会检查这一项（粘贴令牌要经过剪贴板）。
   剪贴板管理软件、远程桌面、手机连接（Phone Link 的跨设备剪贴板）也会读剪贴板，脚本查不出来，运行前先关掉。
3. **运行脚本**：开始菜单打开“Windows PowerShell”，粘贴下面这一行，按回车：

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\claude code\柠檬记APP\tools\keys\set-vapid-keys.ps1" -Target preview
   ```

   看到提示后粘贴第 1 步复制的令牌（屏幕上什么都不显示，这是正常的），按回车。
   等它显示「已写入 VAPID_PRIVATE_KEY、VAPID_PUBLIC_KEY、VAPID_SUBJECT；原有的 … 个 secrets 都在」，下面会单独一行打印**公钥**。
   紧接着还有一行「接口返回：明文」「接口返回：摘要」或「接口返回：不清楚」（三者之一，不含任何值）：这一行**截图或照抄发给主持人**，要记进环境清单（安全审查 O1-P1）。
4. **把公钥填进 GitHub**（在你登录 GitHub 的设备上）：仓库 › Settings › Secrets and variables › Actions › **Variables**（不是 Secrets）：
   - 名字 `PREVIEW_VAPID_PUBLIC_KEY`（正式那次是 `PROD_VAPID_PUBLIC_KEY`）；
   - 值：用鼠标选中脚本打印的那一行（87 个字符，以 B 开头，不要带前后的空格），复制、粘贴。已有就点编辑、换成这一行；
   - 要换电脑填的话，可以把公钥发给自己（公钥是公开值，不怕看见）；**私钥从来不显示，也不要去找**。
5. **收尾**：
   - 回到第 1 步的令牌页，**删掉这把令牌**；
   - 关掉这个 PowerShell 窗口；
   - 第 3 步的「接口返回：…」那一行发给主持人。
6. **最后一步：填好 PREVIEW_VAPID_PUBLIC_KEY 后告诉主持人，由 AI 把开关改成 'true'**：
   - 你只要在聊天里说一句“预览的 VAPID 密钥设好了，PREVIEW_VAPID_PUBLIC_KEY 也填了”；
   - 之后由 AI 做（不用你做）：手动重跑一次 deploy-preview，让新公钥编进预览网页；同一批把 `.github/workflows/deploy-preview.yml` 里的开关 `VAPID_KEY_REQUIRED` 从 `'false'` 改成 `'true'`（以后这个变量为空，预览构建就直接失败）；
   - 开关改成 `'true'` 之前，B2 不能收尾（代码审查 M3，B2 任务单 O-2）。

## 苹果不认 VAPID_SUBJECT 时（R-283）

第一次推送测试时，如果 iPhone 的推送服务回 403、日志说 subject 不对：当天改用 lemomemo.com 的邮箱地址，按上面的步骤重跑一次，第 3 步那一行末尾加 `-Subject mailto:` 再紧跟邮箱地址。例如邮箱是 ops@lemomemo.com 时，整行是：

```
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\claude code\柠檬记APP\tools\keys\set-vapid-keys.ps1" -Target preview -Subject mailto:ops@lemomemo.com
```

- 把 `ops@lemomemo.com` 换成 lemomemo.com 实际能收信的那个邮箱，**不要加尖括号 `<>`**（PowerShell 会把 `<` 当成重定向，命令直接出错）；
- **开头和域名要小写**：`mailto:`、`https://` 小写，网址的主机名、邮箱 `@` 后面的域名只许小写字母、数字、连字符，至少带一个点；网址**不带端口**（不要写 `:443`）。网址的路径只许字母、数字和 `. _ ~ / -`，邮箱 `@` 前面的名字只许字母、数字和 `. _ + -`（这两处大小写都行）。不合这些规则，脚本会提示「-Subject 格式不对」，服务器那边也不认（代码审查 S4、M1，BE1-S1：脚本和后端 vapid.ts 用同一条规则）。

重跑会**连钥匙一起换新**，所以第 4 步的 GitHub 变量也要跟着换，然后照“换钥匙”第 3、4 步做。

## 换钥匙（私钥丢了、怀疑泄露、改 SUBJECT，R-282 ①）

1. **重跑脚本**：照上面第 1～3 步跑一次。脚本会提示「VAPID_PRIVATE_KEY 已有，这次换新」，三项一起换（私钥和服务器侧公钥永远是同一对）。
2. **改 GitHub 变量**：照第 4 步，把 `PREVIEW_VAPID_PUBLIC_KEY`（正式是 `PROD_VAPID_PUBLIC_KEY`）换成这次打印的新公钥。
3. **重新部署**（公钥是构建时编进网页的，不重新部署网页里还是旧公钥）：
   - 预览：GitHub › Actions › deploy-preview › Run workflow，分支选 main，运行；等它变绿（约 10 分钟）。这一步可以请运维代做；
   - 正式：按 `docs/08-发布/正式发布说明-publish.md` 跑一次完整发布（要部署网页，不能用 `-Only functions`）。
4. **换完以后一段时间“推送一轮里超过一半失败”的告警是预期内的**：
   - 用旧公钥订阅的手机和浏览器，推送服务会回 401 或 403。push-dispatch 遇到这两种只给这个订阅记一次失败（`push_fail_count`），**不删订阅**；
   - 用户下次打开 App，App 发现公钥变了，会自动退订、重订、重新认领，之后就正常了（任务单 FA-1）；
   - iPhone 主屏幕版在没有点按的情况下能不能自动重订还没核实。不行的话，设置 › 提醒顶部会提示“推送需要重新打开，点一下”；
   - 所以换钥匙后几小时到几天里，lemo-ops 发来“推送一轮里超过一半失败”不用慌。持续好几天不降，再截图发给主持人。
5. 第 1 步跑完到第 3 步部署完之间，服务器已经是新钥匙、网页还是旧公钥，这段时间新订阅的推送也会失败。所以第 2、3 步跑完脚本后**当天做完**。

## 出错时

- 屏幕上的黄字、红字可以直接截图发给主持人，脚本不会打印私钥和令牌。
- 提示「VAPID_PRIVATE_KEY 可能已换、公钥还没拿到，请立刻重跑本脚本」：写入的请求已经发出去，但没核对完。服务器那边可能已经是新钥匙，你手上没有新公钥。重新生成一把令牌，从第 3 步再跑一次，然后照第 4 步填新打印的公钥、请运维重新部署。
- 提示「成对自检没过」「生成的 … 不是 32 字节」或「.NET 不支持 P-256 曲线」：什么都没写，重跑一次；再失败就截图发给主持人。
- 提示「-Subject 格式不对」：什么都没做。检查开头和域名是不是写成了大写、是不是带了端口或尖括号，照上面“苹果不认”一节的例子改好再跑。
- 提示「LEMO_TEST_API=1 只给测试用」：这个窗口里设着测试用的环境变量，什么都没做。关掉窗口，新开一个 PowerShell 再跑；还提示就截图发给主持人。
- 提示「这个 Supabase 项目叫…，不是 lemomemo-preview」：令牌选错了项目。删掉这把，按第 1 步重新生成。

## 剩下的风险

- 私钥只在脚本的内存里和写进 Supabase 的那一个 HTTPS 请求里出现。Supabase 平台那一侧是否记录请求正文，我们控制不了。
- PowerShell 没法把内存逐字节清零，所以最后要关掉窗口。
- 临时令牌能**读**、改、删这个项目的所有函数 secrets，跑完马上删（安全审查 O1-S2）。
