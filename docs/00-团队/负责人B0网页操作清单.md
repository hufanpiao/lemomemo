# 负责人 B0 第 1～3 天网页操作清单

- 日期：2026-10-28（运维写）
- 给谁：产品负责人本人
- 为什么要你做：这些步骤要登录你的账号、生成或输入密码和令牌、点管理员（UAC）弹窗。按安全规则（R-212），这些只能你本人做，Claude 不能代做。
- 总原则：
  - **密码、令牌、密钥由你自己生成、自己保存**（存进 iPhone“密码”App），直接粘贴到要用的网页里，**不要发给 Claude，也不要截到图里**。
  - 可以发在聊天里的（不是密钥）：Supabase 的 Project ref、Cloudflare 的 Account ID、Turnstile 的 Site Key、anon key（公开的）、截图（看一眼里面没有密钥）。
  - 每做完一节，在聊天里说一句“第 X 节做好了”就行。哪一步找不到按钮，截图问。
  - 网页上的菜单名按 2026-10 写，改版后可能略有不同；中英文界面都写了。
- 名字和权限的总表在[环境清单](../08-发布/环境清单-v4.md)；为什么正式发布要你本机运行脚本，见[正式发布说明](../08-发布/正式发布说明-publish.md)。

## 第 1 天

### ① 本机装三样要管理员的工具（约 40 分钟，中间要重启一次）

详细说明见 [B0 本机开发环境](../07-开发日志/B0-本机开发环境.md) 第三节。

1. 开始菜单右键 →“终端（管理员）”（Terminal (Admin)）→ 弹出 UAC 点“是”。
2. 输入下面一行回车，等它装完：
   ```
   wsl --install --no-distribution
   ```
3. **重启电脑**。
4. 重启后再开一个“终端（管理员）”，输入下面一行回车，弹 UAC 点“是”：
   ```
   winget install --id Docker.DockerDesktop -e
   ```
5. 装完打开 Docker Desktop。第一次打开会让你同意服务条款：个人和小团队免费，点同意（Accept）。登录 Docker 账号那一步可以跳过（Skip）。设置（Settings）› General 里确认 “Use the WSL 2 based engine” 是勾上的。
6. 同一个管理员终端里再输入下面一行（C++ 生成工具，Rust 和 exe 要用；下载约 2～6 GB，二三十分钟），弹 UAC 点“是”：
   ```
   winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
   ```
7. 都装完在聊天里说“第 ① 节做好了”，运维会检查。

### ② GitHub：建私有仓库、加推送钥匙、改设置（约 20 分钟）

你的 GitHub 账号**不在开发电脑上登录**（R-206）。这一节在 iPhone 或另一台设备的浏览器上做 GitHub 网页部分；只有第 3 步要在开发电脑上运行一条命令。

1. 打开 github.com → 右上角“+”→ New repository：
   - Repository name：`lemomemo`
   - 选 **Private**
   - 下面的 README、.gitignore、license **都不要勾**
   - 点 Create repository。把仓库地址（形如 `github.com/你的用户名/lemomemo`）发在聊天里（这不是密钥）。
2. 仓库页 › Settings › Actions › General：
   - Actions permissions：选 “Allow *你的用户名*, and select non-*你的用户名*, actions and reusable workflows”，勾 “Allow actions created by GitHub”，在 “Allow specified actions and reusable workflows” 框里填 `denoland/setup-deno@*`；如果有 “Require actions to be pinned to a full-length commit SHA” 这一项，勾上。点 Save。
   - 往下找 Workflow permissions：选 “Read repository contents and packages permissions”；**不要勾** “Allow GitHub Actions to create and approve pull requests”。点 Save。
3. 推送钥匙（Deploy key，只对这一个仓库有效）：在**开发电脑**上开一个普通 PowerShell（不用管理员），输入：
   ```
   ssh-keygen -t ed25519 -C "lemomemo dev pc" -f "$env:USERPROFILE\.ssh\lemomemo_deploy"
   ```
   问 passphrase 时直接按两次回车（留空：主持人要用它自动推代码）。然后输入：
   ```
   Get-Content "$env:USERPROFILE\.ssh\lemomemo_deploy.pub"
   ```
   屏幕上显示的这一行以 `ssh-ed25519` 开头，是**公钥**，可以复制。（同一文件夹里没有 `.pub` 的那个是私钥，不要打开、不要发。）
4. 仓库页 › Settings › Deploy keys › Add deploy key：Title 填 `开发电脑`，Key 粘贴上一步的公钥，**勾 Allow write access**，点 Add key。
5. 仓库页 › Settings › Code security（或 Security）：把 Dependency graph、Dependabot alerts、Dependabot security updates 都点 Enable。
6. 说“第 ② 节做好了”。主持人会把代码推上去（main 和 develop 两个分支）。

### ③ Supabase：建预览、正式两个项目（约 15 分钟）

1. 打开 supabase.com/dashboard，登录（你只有这一个 Supabase 账号，R-105）。
2. 点 New project：
   - Organization：你的组织（只有一个）
   - Project name：`lemomemo-preview`
   - Database Password：点 **Generate a password**（生成密码）→ 复制 → 立刻存进 iPhone“密码”App，新建一条，名字“柠檬记 Supabase 预览数据库密码”
   - Region：**Northeast Asia (Seoul)**（首尔）
   - Plan / 套餐：Free
   - 其他选项保持默认（后端如果另有说明，以后端为准）
   - 点 Create new project，等一两分钟。
3. 再建一个，步骤一样：名字 `lemomemo-prod`，密码存成“柠檬记 Supabase 正式数据库密码”，同样选首尔、Free。
4. 分别打开两个项目 › Project Settings › General，把 **Project ID / Reference ID**（20 个小写字母）发在聊天里，注明哪个是预览、哪个是正式（这不是密钥）。
5. 说“第 ③ 节做好了”。

### ④ Cloudflare：建两个 Pages 项目，绑预览域名（约 20 分钟）

1. 先在开发电脑上做一个占位页：新建文件夹 `C:\柠檬记占位\`，在里面用记事本新建 `index.html`，内容只写一行 `柠檬记 · 建设中`，保存。
2. 打开 dash.cloudflare.com，登录 → 左侧 **Workers & Pages**（Workers 和 Pages）→ 创建（Create）→ 选 **Pages** 标签 → **上传资源 / Upload assets**（Direct Upload）。**不要选“连接到 Git / Connect to Git”**。
3. Project name 填 `lemomemo-preview` → 创建 → 把 `C:\柠檬记占位\` 文件夹拖进去 → 部署（Deploy site）。
4. 回到 Workers & Pages，同样再建一个 `lemomemo`（正式，先占住名字），也上传占位页。**正式项目这次不绑域名**（上线前再绑）。
5. 打开 `lemomemo-preview` 项目 › **自定义域 / Custom domains** › 设置自定义域 → 填 `preview.lemomemo.com` → 继续 → 激活域（Activate domain）。DNS 记录 Cloudflare 会自动加。几分钟后用手机打开 `https://preview.lemomemo.com` 能看到“柠檬记 · 建设中”就对了。
6. Cloudflare 首页（账户主页）右侧有 **Account ID**（32 位），发在聊天里（这不是密钥）。
7. 说“第 ④ 节做好了”。

## 第 2 天

### ⑤ Turnstile：建预览、正式两个组件（约 10 分钟）

1. dash.cloudflare.com → 左侧 **Turnstile** → 添加组件（Add widget）：
   - 组件名称：`柠檬记 预览`
   - 主机名（Hostnames）：添加 `preview.lemomemo.com`，再添加 `tauri.localhost`
   - 组件模式（Widget Mode）：**托管（Managed）**
   - 预先许可（Pre-clearance）：**否（No）**
   - 创建。
2. **如果 `tauri.localhost` 填不进去**（网页报错或不让保存）：先只留 `preview.lemomemo.com` 建好，把报错截图发在聊天里——这正是 B0 要核实的一项（电脑版 exe 的登录要用到），运维和前端 B 会按架构 5.10 的退路处理。
3. 建好后页面上有两个值：
   - **Site Key（站点密钥，公开的）**：发在聊天里，或者直接填到第 ⑦ 节的 GitHub variable；
   - **Secret Key（密钥）**：复制 → 存进“密码”App“柠檬记 Turnstile 预览密钥”。**不要发给 Claude**。B1 时再贴进 Supabase。
4. 再建一个 `柠檬记 正式`，主机名 `lemomemo.com` 和 `tauri.localhost`，其余一样；Secret Key 存“柠檬记 Turnstile 正式密钥”。
5. 说“第 ⑤ 节做好了”。

### ⑥ 生成两把预览令牌（约 15 分钟）

两把都**只用在预览**；生成后立刻在第 ⑦ 节贴进 GitHub，不用另存（丢了重新生成就行）。

**A. Supabase 预览令牌（只管预览项目）**
1. 打开 supabase.com/dashboard/account/tokens（右上角头像 › Account preferences › Access Tokens）。
2. 点生成新令牌（Generate new token），**不要选 “Create legacy token”**（那种能管全部项目）。
3. 名字：`github-preview-deploy`
4. 资源范围：选 **Selected projects（选定的项目）**，只勾 `lemomemo-preview`。
5. 权限（只开这几项，其余保持“无”）：
   - Project Settings：**读写（Read-write）**（查项目状态、项目暂停时恢复）
   - Edge Functions：**读写**
   - Migrations：**读写**
6. 到期时间：**90 天**。
7. 确认页会显示权限和风险等级，看一眼只有上面三项 → 生成 → 复制（只显示这一次），马上做第 ⑦ 节第 2 步。

**B. Cloudflare 预览令牌（只能编辑 Pages）**
1. dash.cloudflare.com → 右上角头像 › **我的个人资料（My Profile）** › **API 令牌（API Tokens）** › 创建令牌（Create Token）→ 最下面“创建自定义令牌（Create Custom Token）”› 开始使用。
2. 令牌名称：`github-preview-pages`
3. 权限（Permissions）只加一行：**账户（Account）› Cloudflare Pages › 编辑（Edit）**。不要加 DNS、区域（Zone）、Workers 的权限。
4. 账户资源（Account Resources）：包括（Include）› 你的账户。
5. 客户端 IP 地址筛选：不填（GitHub 的出口 IP 不固定）。
6. TTL：结束日期选 **90 天后**。
7. 继续以显示摘要 → 创建令牌 → 复制（只显示这一次），马上做第 ⑦ 节第 2 步。

### ⑦ 填进 GitHub：3 个 Secrets 和几个公开配置（约 15 分钟）

在 GitHub 网页（iPhone 或另一台设备）上：仓库 › Settings › **Secrets and variables › Actions**。

1. 先说明：GitHub 免费版私有仓库没有 Environments，所以都填在 “Repository secrets / variables”。
2. **Secrets** 标签 › New repository secret，依次加三个（Name 照抄，Secret 粘贴）：

   | Name | 粘贴什么 |
   |---|---|
   | `PREVIEW_SUPABASE_ACCESS_TOKEN` | 第 ⑥ 节 A 的 Supabase 预览令牌 |
   | `PREVIEW_SUPABASE_DB_PASSWORD` | “密码”App 里“柠檬记 Supabase 预览数据库密码” |
   | `PREVIEW_CLOUDFLARE_API_TOKEN` | 第 ⑥ 节 B 的 Cloudflare 预览令牌 |

   贴完后清一下手机或电脑的剪贴板（随便复制一个别的字）。
3. **Variables** 标签 › New repository variable，依次加（这些都是公开值）：

   | Name | 填什么 | 从哪里拿 |
   |---|---|---|
   | `PREVIEW_SUPABASE_PROJECT_REF` | 预览项目的 Project ref | 第 ③ 节第 4 步 |
   | `PREVIEW_PAGES_PROJECT` | `lemomemo-preview` | 照抄 |
   | `PREVIEW_SITE_ORIGIN` | `https://preview.lemomemo.com` | 照抄 |
   | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Account ID | 第 ④ 节第 6 步 |
   | `PREVIEW_SUPABASE_ANON_KEY` | 预览项目的 anon（或 publishable）key | Supabase › 预览项目 › Project Settings › API Keys，**只复制 anon / publishable 那一个，不要复制 service_role / secret** |
   | `PREVIEW_TURNSTILE_SITE_KEY` | 预览组件的 Site Key | 第 ⑤ 节 |
   | `PROD_SUPABASE_ANON_KEY` | 正式项目的 anon / publishable key | 同上，换正式项目 |
   | `PROD_TURNSTILE_SITE_KEY` | 正式组件的 Site Key | 第 ⑤ 节 |

   `PREVIEW_VAPID_PUBLIC_KEY`、`PROD_VAPID_PUBLIC_KEY` 现在先不填（B2 推送时再说）。
4. 说“第 ⑦ 节做好了”。之后主持人第一次往 develop 推代码，预览环境就会自动部署；第一次跑的时候运维会看结果，令牌权限不够会告诉你差哪一项（只说权限名，不会要令牌）。

## 第 3 天

### ⑧ Supabase 登录设置：两个项目都改（约 10 分钟）

对 `lemomemo-preview` 和 `lemomemo-prod` 各做一遍：

1. 项目 › **Authentication** › **Sign In / Providers**（登录方式）：
   - **Allow anonymous sign-ins（允许匿名登录）**：**关**；
   - Email 里的 **Secure email change（安全地更换邮箱）**：**开**（换邮箱要新旧两个邮箱都确认）；
   - 点保存。
2. 别的设置（关闭公开注册、验证码 10 分钟、跳转白名单、CAPTCHA）是 B1 的事，到时候运维再给步骤。
3. 说“第 ⑧ 节做好了”。

### ⑨ Gemini 密钥和免费额度（约 25 分钟，[负责人待办](产品负责人待办-v4.md) B0 那两行）

1. 打开 aistudio.google.com → Get API key → 用**两个不同的谷歌项目**各建一把密钥（R-90）：一个项目给正式、一个给预览。复制后：
   - 打开 Supabase › 对应项目 › **Project Settings › Edge Functions › Secrets**（或 Edge Functions 页的 Secrets），Name 填 `GEMINI_API_KEY`，Value 粘贴，保存。预览项目贴预览那把，正式项目贴正式那把；
   - 不用另存（丢了重新生成）。
2. 限定密钥用途：console.cloud.google.com › 选对应项目 › API 和服务 › 凭据 › 点这把密钥 › API 限制：选“限制密钥”，只勾 **Generative Language API** › 保存。两把都做。
3. 在 AI Studio 里查 **gemini-embedding-2** 和 **Flash-Lite** 每分钟、每天能免费用多少次，把数字发在聊天里（数字不是密钥）。
4. 说“第 ⑨ 节做好了”。

### ⑩ Security Advisor 截图（约 5 分钟；等主持人说“迁移已经部署到预览”再做）

1. Supabase › `lemomemo-preview` › 左侧 **Advisors › Security Advisor** → 点 **Rerun linter**（重新检查）→ 等结果出来。
2. 整屏截图，要看得到：项目名、错误和警告的数量、检查时间。截之前看一眼页面上没有任何密钥（这个页面本来不显示）。
3. 发在聊天里。有警告的话，把警告列表也截一张，后端会改，改完再截一次。
4. 正式项目的截图等上线前（B7a）再做。
