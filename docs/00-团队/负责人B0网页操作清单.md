## 第 1 天

### ① 本机装三样要管理员的工具（约 40 分钟，中间要重启一次）

详细说明见 [B0 本机开发环境](../07-开发日志/B0-本机开发环境.md) 第三节。

1. 开始菜单右键 →“终端（管理员）”（Terminal (Admin)）→ 弹出 UAC 点“是”。
2. 输入下面一行回车，等它装完：
   ```
   wsl --install --no-distribution
   ```
3. **重启电脑**。
4. 重启后再开一个“终端（管理员）”，输入下面一行回车，弹 UAC 点“是”：
   ```
   winget install --id Docker.DockerDesktop -e
   ```
5. 装完打开 Docker Desktop。第一次打开会让你同意服务条款：个人和小团队免费，点同意（Accept）。登录 Docker 账号那一步可以跳过（Skip）。设置（Settings）› General 里确认 “Use the WSL 2 based engine” 是勾上的。
6. 同一个管理员终端里再输入下面一行（C++ 生成工具，Rust 和 exe 要用；下载约 2～6 GB，二三十分钟），弹 UAC 点“是”：
   ```
   winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
   ```
7. 都装完在聊天里说“第 ① 节做好了”，运维会检查。

### ② GitHub：建私有仓库、加推送钥匙、改设置（约 20 分钟）

你的 GitHub 账号**不在开发电脑上登录**（R-206）。这一节在 iPhone 或另一台设备的浏览器上做 GitHub 网页部分；只有第 3 步要在开发电脑上运行一条命令。

1. 打开 github.com → 右上角“+”→ New repository：
   - Repository name：`lemomemo`
   - 选 **Private**
   - 下面的 README、.gitignore、license **都不要勾**
   - 点 Create repository。把仓库地址（形如 `github.com/你的用户名/lemomemo`）发在聊天里（这不是密钥）。
2. 仓库页 › Settings › Actions › General：
   - Actions permissions：选 “Allow *你的用户名*, and select non-*你的用户名*, actions and reusable workflows”，勾 “Allow actions created by GitHub”，在 “Allow specified actions and reusable workflows” 框里填 `denoland/setup-deno@*`；如果有 “Require actions to be pinned to a full-length commit SHA” 这一项，勾上。点 Save。
   - 往下找 Workflow permissions：选 “Read repository contents and packages permissions”；**不要勾** “Allow GitHub Actions to create and approve pull requests”。点 Save。
3. 推送钥匙（Deploy key，只对这一个仓库有效）：在**开发电脑**上开一个普通 PowerShell（不用管理员），输入：
   ```
   ssh-keygen -t ed25519 -C "lemomemo dev pc" -f "$env:USERPROFILE\.ssh\lemomemo_deploy"
   ```
   问 passphrase 时直接按两次回车（留空：主持人要用它自动推代码）。然后输入：
   ```
   Get-Content "$env:USERPROFILE\.ssh\lemomemo_deploy.pub"
   ```
   屏幕上显示的这一行以 `ssh-ed25519` 开头，是**公钥**，可以复制。（同一文件夹里没有 `.pub` 的那个是私钥，不要打开、不要发。）
4. 仓库页 › Settings › Deploy keys › Add deploy key：Title 填 `开发电脑`，Key 粘贴上一步的公钥，**勾 Allow write access**，点 Add key。
5. 仓库页 › Settings › Code security（或 Security）：把 Dependency graph、Dependabot alerts、Dependabot security updates 都点 Enable。
6. 说“第 ② 节做好了”。主持人会把代码推上去（只有 main 一个长期分支，架构 8.3）。

### ⑥ 生成两把预览令牌（约 15 分钟）

**A. Supabase 预览令牌（只管预览项目）**
1. 打开 supabase.com/dashboard/account/tokens（右上角头像 › Account preferences › Access Tokens）。
2. 点生成新令牌（Generate new token），**不要选 “Create legacy token”**（那种能管全部项目）。
3. 名字：`github-preview-deploy`（10-28 实际是第三把 `github-preview-deploy-v3`）
4. 资源范围：选 **Selected projects（选定的项目）**，只勾 `lemomemo-preview`。
5. 权限（只开这几项，其余保持“无”）：

7. 继续以显示摘要 → 创建令牌 → 复制（只显示这一次），马上做第 ⑦ 节第 2 步。

### ⑦ 填进 GitHub：3 个 Secrets 和几个公开配置（约 15 分钟）

在 GitHub 网页（iPhone 或另一台设备）上：仓库 › Settings › **Secrets and variables › Actions**。

1. 先说明：GitHub 免费版私有仓库没有 Environments，所以都填在 “Repository secrets / variables”。
2. **Secrets** 标签 › New repository secret，依次加三个（Name 照抄，Secret 粘贴）：

   | `PREVIEW_SUPABASE_DB_PASSWORD` | 第 ③ 节建项目时生成的预览数据库密码（不另存；找不到就在 Project Settings › Database 重设一个新的再贴） |
   | `PREVIEW_CLOUDFLARE_API_TOKEN` | 第 ⑥ 节 B 的 Cloudflare 预览令牌 |

   贴完后清一下手机或电脑的剪贴板（随便复制一个别的字）。

   | `PROD_SUPABASE_ANON_KEY` | 正式项目的 anon / publishable key | 同上，换正式项目 |

### ⑧ 预览 Pages 的三个变量：`SUPABASE_UPSTREAM`、`SUPABASE_ANON_KEY`、`PROXY_SECRET`（约 25 分钟）

网页上的 `/sb/*` 转发（Pages Functions）要这三个变量才能连到 Supabase（架构 0.31 第 11 条）。前两个是**公开值**，第三个 `PROXY_SECRET` 是**密钥**：转发层和服务器函数之间对暗号用，Cloudflare、Supabase 两处要放**同一个值**。

这一节只做**预览**。正式那一套（Pages 项目 `lemomemo`、Supabase 项目 `lemomemo-prod`，`PROXY_SECRET` 另生成一把、值不同）等上线前（B7a）再做，步骤一样，把下面的预览项目名换成正式的、脚本参数换成 `-Target production`。

**A. 两个普通变量（公开值，约 5 分钟）**

先准备两个值（都不是密钥，可以发在聊天里）：
- `SUPABASE_UPSTREAM`：`https://<预览项目的 Project ref>.supabase.co`，ref 是第 ③ 节第 4 步那 20 个小写字母，例如 `https://abcdefghijklmnopqrst.supabase.co`。**结尾不加 `/`**，前面一定是 `https://`；
- `SUPABASE_ANON_KEY`：预览项目的 anon（或 publishable）key，和第 ⑦ 节 `PREVIEW_SUPABASE_ANON_KEY` 填的是同一个。**不要复制 service_role / secret 那个**。

然后：
1. dash.cloudflare.com → **Workers & Pages** → 点 `lemomemo-preview` → **设置（Settings）** → **变量和机密（Variables and Secrets）**。
2. 页面上方如果有环境切换，选 **生产（Production）**（我们部署时用的是 `main` 分支，在 Pages 里算“生产”；不要填到“预览 / Preview”那一栏）。
3. 点 **添加（Add）**：
   - 类型（Type）：**文本（Text）**
   - 变量名称（Variable name）：`SUPABASE_UPSTREAM`
   - 值（Value）：上面那个 `https://….supabase.co`
4. 再点 **添加**：类型 **文本**，名称 `SUPABASE_ANON_KEY`，值粘贴预览项目的 anon key。
5. 点 **保存（Save / Deploy）**。

**B. `PROXY_SECRET`（密钥，约 20 分钟；要你本人在开发电脑上运行脚本）**

值由脚本在你电脑上随机生成，**不经过 Claude**：脚本发现 Claude 还开着就会停下，因为 Claude 能读到终端里的内容。

1. **完全退出 Claude**（桌面 App 右下角托盘里也退出；所有终端里的 claude 也关掉）。
2. 确认 Windows **剪贴板历史**是关的：设置 › 系统 › 剪贴板 →“剪贴板历史记录”关、“跨设备共享”关（开着的话脚本会停下提醒你）。
3. 开一个**新的** PowerShell 窗口（普通的，不用管理员），输入下面一行回车：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\claude code\柠檬记APP\tools\keys\new-proxy-secret.ps1" -Target preview
   ```
4. 脚本先做几项检查，然后显示**一行 64 位的值**（只有 0～9 和 a～f）和它的 SHA-256。**这个值只显示这一次**，窗口先别关，依次做 5～6 步，两处必须一模一样；**不用另存**（R-220，丢了重新运行一遍脚本就行）。
5. **Cloudflare（加密变量）**：用鼠标选中 PowerShell 窗口里那一行值（不要带前后的空格），按回车复制。然后回到 A 的同一页（`lemomemo-preview` › 设置 › 变量和机密 › **生产 / Production**）→ 添加：
   - 类型：**密钥 / 机密（Secret）**，**不要选“文本”**（选“文本”会明文显示在页面上）
   - 名称：`PROXY_SECRET`
   - 值：粘贴
   - 保存。保存后页面上只显示“已加密 / Encrypted”，看不到值，这是对的。
6. **Supabase（函数 secret）**：supabase.com/dashboard → `lemomemo-preview` 项目 → 左侧 **Edge Functions** → **Secrets**（也可能在 Project Settings › Edge Functions 里）→ 添加（Add new secret）：
   - Name：`PROXY_SECRET`
   - Value：再粘贴一次同一个值
   - 保存。保存后页面上如果有 **Digest（SHA-256 摘要）**一栏，和 PowerShell 窗口里显示的 SHA-256 对一下，一样就说明粘贴对了。
7. 回到 PowerShell 窗口按回车：脚本会清屏、清剪贴板。**关掉这个 PowerShell 窗口**。
8. 在聊天里说“第 ⑧ 节做好了”，**不要把值发出来**。主持人第一次往 main 推代码时，预览部署会带上这三个变量（Pages 的变量只对**之后**的部署生效；如果在第一次部署以后才改，要再部署一次才生效，主持人会安排）。

出了岔子（窗口关早了、粘贴时不小心多选了字、两处不一样）：不用找回原值，**重新运行一遍脚本生成一把新的**，Cloudflare、Supabase 两处都换成新值就行。这个值不加密任何数据，换掉没有损失。
