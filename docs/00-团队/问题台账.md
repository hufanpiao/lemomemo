# 问题台账（负责人报的问题，唯一出处）

- 建立：2026-11-11，负责人批准“四道关卡”方案（原话：“按照上面的方案严格执行，开工”）。
- 用法：主持人给负责人说任何进度，只从这张表读，不凭印象。一行一个问题，状态只能按下面的顺序往前走，不许跳关。
- 四道关卡：
  1. **登记**：原话照抄。
  2. **定根因**：有证据（数字、截图、提交号）才算；iOS 专属的，先出“只需负责人截一张图”的诊断版。没根因不改代码。
  3. **独立验证**：修完由没参与修的验证员按本表逐条验，默认不通过；电脑能复现的必须亲眼看到问题没了；复现不了的标“只能真机”。
  4. **交付**：给负责人说“修好 / 上线 / 去看”必须带【交付清单】三栏（已验过 / 只能真机 / 这一版没有），Stop 钩子硬拦。每次只请负责人真机验一项。
- 状态：登记 → 定根因中 → 根因已定 → 修复中 → 待验证 → 验证通过（电脑）/ 待真机 → 负责人确认 → 关闭。
