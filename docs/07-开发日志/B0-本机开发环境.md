## 四、启用本机的提交前密钥检查（每台开发电脑的第一步）

`.githooks/pre-commit` 已在主干上。每台开发电脑在仓库根目录（本机是 `D:\claude code\柠檬记APP`）执行一次（不用管理员）：

```
git config core.hooksPath .githooks
```

之后每次提交都会先跑 gitleaks；没找到 gitleaks 也会拒绝提交。**各个 worktree 共用这一项设置**，在主仓库执行一次，所有 worktree 都生效。

核对：`git config --get core.hooksPath` 应输出 `.githooks`。输出为空就是没启用：钩子不会跑，TC-B0-58“本机提交被拦”在这台电脑上不成立（B0 QA 10-28 在 worktree 里查到的就是空，D-09）。这一步也写在 README“开发第一步”。

## 五、S3 替身：本机怎么起（代替 R2，架构 0.32 第 4 条、8.6；B0 R2 任务单 O-1）

**状态：待 Docker**。本机还没有 Docker Desktop（第三节），下面的 `up` 现在跑不了；`pin` 不要 Docker，已在本机跑通。

**选的是 LocalStack 4.14.0，不是 MinIO**（10-28 运维核实）：
- MinIO 官方镜像（Docker Hub `minio/minio`、`quay.io/minio/minio`）10-28 用 registry 接口匿名拉取都回 401，上游 2025-10 起只发源码，仓库已停止维护；第三方重新打包的镜像（社区 fork）供应链来源不清，没有选。
- 架构 8.6 写的退路是 LocalStack 的 S3。LocalStack 2026.03 起新版本启动要 auth token（要注册账号、CI 里要放 secret，ci.yml 约定不引用 secrets），所以锁在 token 要求之前的最后一个社区版 **4.14.0**（2026-02-26 发布），按多架构清单的 digest 锁：`sha256:3ebc3759…bc364a`（全文在 `tools/ci-tools.lock` 和 `docker-compose.objstore.yml`）。
- 代价：这一版不会再有安全更新（只在本机回环地址和 CI runner 上跑、没有真数据）；**对请求头里的 SigV4 签名默认不校验**，所以“签名算对了没有”不能靠替身证明，`shared/objstore.ts` 的单测要另外按 AWS 公布的签名样例核对（交前端 B）。交安全审查员确认可以接受。

**一条命令起替身**（仓库根目录；要先开着 Docker Desktop）：

```
node build/objstore.mjs up
```

它依次：核对 `docker-compose.objstore.yml` 的镜像和 `tools/ci-tools.lock` 一致 → `docker compose up -d` → 等 S3 就绪 → 建 `images`、`files`、`vault-images`、`vault-files` 四个桶（已有就跳过）→ 在一个临时桶里验四个条件，打印“通过 / 不通过”，任何一条不通过就退出码 1：
1. SigV4 + path-style 写、读回一样的字节（另外报告一句“错误签名会不会被拒”，只报告不判失败）；
2. `PutObject` 带 `If-None-Match: *`：新对象 200，已存在 412，内容不被覆盖；
3. `ListObjectsV2` 分页（5 个对象、每页 2 个，应为 3 页）；
4. `DeleteObjects` 一次删完，再列为 0。

其他：`node build/objstore.mjs down`（停掉并删掉，数据不留）、`pin`（只比对镜像锁定）、`buckets`（只建桶）、`verify`（只验四个条件）。脚本只认本机回环地址（`OBJSTORE_ENDPOINT` 填别的直接退出），不会误打到真 R2。

**接到本机的各处**（任务单第四节的第 4、6 步）：

| 用在哪 | 写什么 |
|---|---|
| `.dev.vars`（`wrangler pages dev dist/web`，`/files` 函数） | `R2_ENDPOINT=http://127.0.0.1:4566`、`R2_BUCKET_PREFIX=`（空）、`R2_FILES_ACCESS_KEY_ID=test`、`R2_FILES_SECRET_ACCESS_KEY=test` |
| `supabase/.env.local`（`supabase functions serve --env-file`，服务器函数） | `R2_ENDPOINT=http://host.docker.internal:4566`（函数跑在 Supabase 的容器里，`127.0.0.1` 指的是容器自己；**待 Docker 实测**，不通就改成 `docker network connect` 把替身接进 Supabase 的网络）、`R2_BUCKET_PREFIX=`、`R2_FN_ACCESS_KEY_ID=test`、`R2_FN_SECRET_ACCESS_KEY=test` |
| 签名的区域 | R2 用 `auto`；替身对区域不挑。`shared/objstore.ts` 把区域做成可配的（或固定 `us-east-1`，R2 文档写它会被当作 `auto`，**未实测**），由前端 B 定 |

`test` / `test` 是 LocalStack 的固定测试值，不是密钥。CI 的 db 任务用同一条命令起、同一套值（`ci.yml` 里 `OBJSTORE_*`、`R2_ENDPOINT`、`R2_BUCKET_PREFIX`），任务结束 `down`。

**10-28 没有 Docker 时做过的自测**：用 moto（另一个 S3 模拟器，装在临时目录，没进仓库）起本机 S3，`buckets` 和 `verify` 全部通过；再开 moto 的签名校验（IAM 鉴权）跑一遍也全过，错误签名回 403，说明脚本自己的 SigV4（含空格、`+` 的键名，带 XML 正文的 POST）算得对。LocalStack 本身的四个条件**等 Docker 装好后在本机和 CI 各跑一次**，结果补进下面的核对记录和过程记录。
