# 架构约定

v3 开工前定下的规矩，用来防止功能越加越多、结构越来越乱。`build/check_arch.py` 会自动检查其中大部分条目；`python build/build.py` 默认先跑这项检查，没通过就不构建。

- 适用范围：第 1–8 节适用于 v3 的 `src/`（原生 JS）；4.0.0（React + TypeScript）适用第 9 节。
- 修改方式：要改这些规矩，先改本文件，再同步改 `build/check_arch.py`，两者保持一致。
- 最后更新：2026-10-24（第七轮第三轮复审后：9.6 补 CI 部署、手动令牌、exe 窗口权限；第二轮复查后：9.2 IndexedDB 读时信任、9.3 A26、9.4 字号例外和“皮肤”分组、9.6 依赖供应链和密钥生成；R-96：第 9 节是 4.0.0 的约定，**第 1–8 节只适用于 v3 和 3.0.1 只读版**）。
- 2026-10-23 版：v3 开工前的结构调整，程序员 1。

## 1. 分层和依赖方向

```
                ┌──────────────┐
                │   app.js     │  启动入口：选适配器、建时钟、接线
                └──────┬───────┘
                       ▼
                ┌──────────────┐
                │     ui/      │  渲染、交互、提示文案、动画
                └──┬────────┬──┘
                   │        ▼
                   │  ┌──────────────┐
                   │  │    data/     │  状态、整理、写入、订阅、事件
                   │  └──┬────────┬──┘
                   ▼     ▼        │
             ┌──────────────┐     │
             │  platform/   │◄────┘   存储适配器、本机偏好、时间来源、提示音和推送
             └──────┬───────┘
                    │
   ui、data 都可以用 ▼            platform 只能用 core
        ┌──────────────┐   ┌──────────────┐
        │   logic/     │──►│    core/     │  logic 只能用 core；core 谁都不依赖
        └──────────────┘   └──────────────┘
```

依赖只能沿箭头方向走，下层永远不知道上层的存在。

| 层 | 可以依赖 |
|---|---|
| core | （无） |
| logic | core |
| platform | core |
| data | core、logic、platform |
| ui | core、logic、platform、data |
| app.js | 全部 |

data 要让界面做事（重绘、弹提示）时，只能**发事件**（`App.data.emit`）。ui 用 `App.data.on("change" | "error" | "notice", fn)` 订阅后自己决定怎么做。

## 2. 每层能做什么、不能做什么

| 层 | 职责 | 不能做（检查规则） |
|---|---|---|
| **core/** | 与业务无关的纯工具：常量 `const.js`、日期 `date.js`、统一时钟 `clock.js`（时间来源从外面注入） | 不碰 `document`、`window`、`localStorage`；不调 `Date.now()` 和不带参数的 `new Date()`；不引用 `App.ui`、`App.data`、`App.platform`、`App.clock`（规则 A1） |
| **logic/** | 业务规则的纯函数：一句话解析、排序、“下一件事”、文案、项目颜色、提醒时刻。“今天”“现在”一律作为参数传入 | 同 core（A1）。在 Node 里不建页面就能测 |
| **platform/** | 和运行环境打交道：存储适配器（`claude-db`，以后的 `rest`）、本机偏好 `prefs`、时间与前台事件 `env`、提示音和推送 `notify`、平台相关的提示文案 | 不能反过来用 `App.data`、`App.ui`（A5） |
| **data/** | 数据状态、字段整理 `normalize`、全部写入 `write`（唯一入口）、订阅与重连 `subscribe`、事件总线 `bus` | 不碰 DOM、`App.ui`、`classList`、`matchMedia`、`innerHTML`（A2）；不直接用 `window.claude`、`localStorage`（A3） |
| **ui/** | 渲染各视图、读表单、提示条、动画停顿、界面状态 `view-state` | 不直接调用存储，即不出现 `store.`、`App.data.store`；写入一律走 `App.data.write`（A4）。不直接用 `window.claude`、`localStorage`（A3） |
| **app.js** | 启动顺序；选存储适配器的**唯一**位置 | 不写业务逻辑 |

另外两条：
- 只有 `platform/` 能碰 `window.claude` 和 `localStorage`（A3）。
- 界面插入文字一律用 `h()` 或 `textContent`。`h()` 的 `html` 参数只允许传常量图标，绝不传数据库内容（安全审查）。

## 3. 新功能放在哪里

| 功能 | logic/ | data/ | platform/ | ui/ |
|---|---|---|---|---|
| **提醒**（v3） | `remind.js`：`computeRemindAt(item, kind, now)` 纯函数 | `write.js` 保存时写 `remindAt`，“知道了”写 `notifiedFor`，“稍后”写 `snoozeAt` | `notify.js`：提示音、推送 | `remind.js`：每次时钟 tick 检查，弹提醒卡片 |
| **主题**（v3） | — | — | `prefs.js` 的 `pv-theme`、`pv-skin` 键 | `theme.js`：按钮、弹出三选一（跟随系统 / 浅色 / 深色）、设 `data-theme`；皮肤用 `data-skin`，见 [ADR-008](../04-决策/ADR-008-皮肤与深浅色分为两个维度.md) |
| **搜索**（v3） | `search.js`：`search(items, query)` 纯函数，匹配标题、备注、原话 | 用 `visEv`/`visTd` 提供数据；“最近删除”里的另算 | — | `search.js`：输入框、结果列表 |
| **导出备份**（v3） | `export.js`：`toBackup(events, todos, now)` 生成 JSON 对象 | 提供全部条目（含已删除，标出 `deletedAt`） | `download.js`：`saveFile(name, blob)`（claude.ai 与 PWA 的实现不同） | 按钮和提示 |
| **重复事项**（以后） | `repeat.js`：`expand(rule, from, to)` 展开成具体日期 | `normalize.js` 整理 `repeat` 字段；`write.js` 处理“只改这一次 / 改全部” | — | 弹出层里的重复选项；列表照常渲染展开后的条目 |

判断口诀：**算什么**放 logic；**存什么、怎么存**放 data；**和环境打交道**放 platform；**长什么样、点了做什么**放 ui。

## 4. 文件大小

- 单个 JS 文件超过 **250 行**就要拆分。检查脚本会给出警告（W1），不算失败，但合并前要处理。
- 单个函数超过约 40 行时，优先拆成几个有名字的步骤，例如 `parseQuick` 拆成日期、时间、标记、项目、标题几步，`renderToday` 拆成几段渲染函数。

## 5. 命名和文件头

**命名**
- 文件名用小写加连字符：`parse-quick.js`、`view-state.js`。
- 每个文件把对外的东西挂到 `App.<层>.<模块>` 上，例如 `App.logic.sort = {byTime, sortTodos, pickNext}`；函数用小驼峰。
- 常量放 `core/const.js`，用全大写加下划线：`TOAST_UNDO_MS`。和 CSS 动画时长对应的常量，要在注释里写明对应哪条 CSS。
- 集合名固定为 `events`、`todos`；种类固定为 `"event"`、`"todo"`，两者用 `App.data.write.collOf(kind)` 互转。
- 本机偏好的键名统一登记在 `platform/prefs.js` 的 `KEYS` 里。

**文件头注释**（每个 JS 文件开头，检查规则 A6、A7、A8、A9）

```js
// 职责：这个文件负责什么（1–3 行）。
// 依赖：core/date.js、logic/items.js          ← 加载时就要用的文件，manifest 里必须排在本文件前面；没有就写“依赖：无”
// 运行时调用：ui/sheet.js、App.clock         ← 可选。只在函数里才调用的模块，不限顺序
```

- “依赖：”写的文件在 `build/manifest.json` 里排在后面时，会报 A7。
- 依赖了不允许的层时报 A8，例如 data 声明依赖 ui。
- 代码里用到了 `App.x.y`，但提供它的文件既没写在“依赖：”里，也没写在“运行时调用：”里，报 A9。
- 依赖可以换行续写，续行也以 `//` 开头。

**manifest**
- `src/` 下每个 `.js`、`.css` 都必须写进 `build/manifest.json`（A10）。顺序按层排：core → logic → platform → data → ui，`app.js` 最后。

## 6. 完成标准

一项改动同时满足下面全部条件，才算完成：

- [ ] `python build/build.py` 通过，其中包括架构检查 0 个错误；新出现的 W1 警告已经处理。
- [ ] `node tests/run-all.mjs` 全部通过：单元测试，加架构检查自检。
  - 新增或修改了 logic、data 里的函数，就要补对应的单元测试，预期值写死在测试里。
  - 新增存储适配器时，要加进 `tests/unit/adapter-contract.test.mjs` 的 `ADAPTERS`。
- [ ] 新增、删除、改名的字段已更新到 `docs/05-数据字典/数据字典.md`，本机偏好的键名也要登记。
- [ ] 新增、删除、改名的文件已更新到 `文件登记册.md`，并且 `python build/check_registry.py` 通过。
- [ ] 改动已写进 `CHANGELOG.md`。
- [ ] 浏览器验证：用 `planner-test` 服务打开 `/dist/test.html`，在 375×812 和 1280×820、浅色和深色下都检查一遍：渲染正常、控制台无报错，改动涉及的流程能走通。
- [ ] 新增违规类型的检查时，在 `tests/arch-fixtures/` 加一段故意违规的示例，并确认 `--self-test` 能拦住它。

## 7. 检查规则一览（`build/check_arch.py`）

| 编号 | 检查内容 | 级别 |
|---|---|---|
| A1 | logic/、core/ 里出现 `document`、`window`、`globalThis`、`navigator`、`location`、`localStorage`/`sessionStorage`/`indexedDB`、`Date.now`、`performance`、`new Date()` 或不带括号的 `new Date`、`Date()`、`App.ui`、`App.data`、`App.platform`、`App.clock` | 错误 |
| A2 | data/ 里出现 `document`、`window`、`location`、`navigator`、`App.ui`、`classList`、`matchMedia`、`innerHTML`、`App.clock`（时钟用 `write.init(clock)` 注入） | 错误 |
| A3 | platform/ 以外出现 `window.claude`、`globalThis.claude`（以及 `self`/`top`/`parent` 上的 claude），或 `localStorage`、`sessionStorage`、`indexedDB` | 错误 |
| A4 | ui/ 里直接调用 `store.` 或 `App.data.store`（写成 `App.data["store"]` 也算） | 错误 |
| A5 | platform/ 里引用 `App.data` 或 `App.ui` | 错误 |
| A6 | 文件头缺少“职责：”或“依赖：” | 错误 |
| A7 | 文件头“依赖：”里的文件在 manifest 中排在本文件后面，或不在 manifest 里；或者文件加载时就用到的模块（不在函数体里的引用）只写在“运行时调用：”里 | 错误 |
| A8 | 文件头声明了不允许依赖的层 | 错误 |
| A9 | 用到了 `App.x.y`，但提供它的文件没写进文件头 | 错误 |
| A10 | src/ 下有 .js、.css 没写进 manifest，或 manifest 里的文件不存在 | 错误 |
| W1 | 单个 JS 文件超过 250 行 | 警告 |
| A11 | `src/styles/components/` 的声明值里写死颜色（`#xxx`、`rgb()`、`rgba()`、`hsl()`、`hsla()`）；颜色只能写在 `src/styles/skins/<皮肤>.css` 的变量里（[ADR-008](../04-决策/ADR-008-皮肤与深浅色分为两个维度.md)）。原为警告 W2，T7 改完 5 处后升级为错误 | 错误 |

检查前会先去掉注释、清空字符串内容，所以注释和字符串里提到这些词不算违规；`x["y"]` 会先改写成 `x.y` 再检查，方括号绕不过去。“加载时”的判断：不在函数体（`)` 或 `=>` 后面的 `{…}`）和箭头函数表达式体里的代码，都算文件加载时执行。`python build/check_arch.py --self-test` 会用 `tests/arch-fixtures/` 里每段故意违规的示例逐条验证规则确实生效。

## 8. 样式文件的分工（v3 T7 起）
- `src/styles/tokens.css`：与皮肤无关的结构变量（字体、圆角、过渡时长）。
- `src/styles/skins/<皮肤>.css`：只定义颜色变量，浅色、深色各一组；深色要写两遍（跟随系统、手动选深色），两组保持一致。v3 只有 `bento.css`。
- `src/styles/components/*.css`：组件样式，只能用变量，不能写死颜色（A11）。新增变量时先加进皮肤文件，并在该文件头注释里说明用途。
- `<html>` 上两个维度：`data-skin`（皮肤）、`data-theme`（`light` / `dark`，跟随系统时不设），由 `ui/theme.js` 设置，偏好存 `pv-skin`、`pv-theme`。


## 9. 4.0.0 的约定（React + TypeScript，R-96，2026-10-24）

> **适用范围**：第 1–8 节是 v3（原生 JS、`App.x` 命名空间、文件头注释、`build/manifest.json`）的规矩，只对 v3 的代码和 3.0.1 只读版有效。**4.0.0 起前端改用 React + TypeScript（strict）+ Vite**（[ADR-017](../04-决策/ADR-017-前端用React与TypeScript.md)），以本节为准；完整的目录和检查规则见 [架构设计-v4](架构设计-v4.md) 第 2 节。

### 9.1 分层

```
shared/（前端和 Edge Functions 共用，纯 TS）
   ▲
src/platform/  ◄──  src/data/  ◄──  src/ui/hooks/  ◄──  src/ui/components/、src/ui/pages/  ◄──  src/app/
（运行环境）       （缓存、队列、同步）  （把 data 接成 hook）     （界面）                          （入口、路由）
                                       src/motion/ 只给 ui 用
```

| 层 | 可以 import | 不能做 |
|---|---|---|
| shared | 只有 shared 自己和 zod | 不能用 DOM、React、Node、Deno 的 API；不能 `Date.now()`、无参 `new Date()`、`Math.random`；“现在”和时区一律从参数传入 |
| platform | shared | 不能 import React、data、ui |
| data | shared、platform | 不能 import React、ui；对外只给 `subscribe` / `getSnapshot` 和写入函数 |
| ui/hooks | shared、data、React | 唯一能同时碰 React 和 data 的地方 |
| ui/components、pages | shared、ui/hooks、ui/state、motion、React | 不能直接 import `platform/supabase/*`，不能直接写 IndexedDB |
| motion | shared（只读令牌）、motion/react | 只给 ui 用 |
| app | 全部 | 不写业务逻辑 |

由 ESLint 的 `eslint-plugin-boundaries` 检查，违反就是错误。

### 9.2 TypeScript
- `strict: true`，另开 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitOverride`、`useUnknownInCatchVariables`、`verbatimModuleSyntax`。
- **不准 `any`**；不准 `@ts-ignore`、`@ts-nocheck`，确实需要时写 `@ts-expect-error: 理由`；非空断言 `!` 尽量不用（警告）。
- **外部来的数据一律先过 zod**（网络响应、Realtime 推来的、AI 输出、URL 参数），不准用 `as` 硬转类型。**IndexedDB 例外**：写入时已经校验过，每条带 `schema_v`，读的时候信任本机数据、只核对 `schema_v`（版本不对就整表重拉），免得冷启动对几千行逐行跑 zod（架构 2.6）。
- 类型从 schema 推导（`z.infer`），数据库类型用生成的 `shared/db.types.ts`，不手写重复的 interface。
- shared 里的 import 写全 `.ts` 后缀、只用相对路径（Deno 要用）。

### 9.3 React
- 只写函数组件和 hooks；`react-hooks/rules-of-hooks`、`exhaustive-deps` 是错误。
- **不准 `dangerouslySetInnerHTML`**，没有例外；图标写成 React 组件。也不准 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`、`eval`、`new Function`。
- 列表的 key 用记录 id，不用下标。
- 数据从 `useCollection` / `useItem` 这类 hook 拿，组件里不 `fetch`、不调 Supabase。界面状态（弹层、提示条队列、横幅队列）放 `ui/state` 的 Zustand；隐私记明文只在隐私记页面的组件状态里，上锁时清掉，不进全局状态。
- 链接一律经 `shared/logic/link.ts` 的 `safeHref()`（用 `new URL()` 看 protocol，只放行 http、https、tel、mailto）；通过了才渲染成 `<a rel="noopener noreferrer">`。JSX 的 `href`、`src` 只能是常量、路由函数或 `safeHref()` 的返回值（ESLint 规则 A26）。
- 界面文字一律 `t(key, params)`（`useT()`），字符串和 JSX 文本里不准写汉字、谚文（check_arch A20）。
- 无障碍：`eslint-plugin-jsx-a11y` recommended；弹层、菜单、开关用 Radix Primitives；每个页面的组件测试跑一次 axe。
- 单个文件超过 300 行、单个组件超过 150 行要拆（警告）。

### 9.4 样式、皮肤和动效
- **字号下限的有意例外**：月历色块标签和“+N”用 9.5 px（R-104，产品负责人明确决定），低于设计规范 11 px 的下限；只有这一处，不准照着用到别处。
- 设置项的分组名以视觉稿为准：“减少透明效果”“减少动态效果”都在**设置 › 皮肤**。`ui.reduce_motion` 不存就跟系统。
- 组件样式用 CSS Modules（`Xxx.module.css`）；颜色只写在 `src/styles/skins/<皮肤>.css` 的变量里（Stylelint 检查，原 A11）；TSX 的 `style` 里不写颜色、不写动效。
- 不用 CSS-in-JS，不用任何会插入内联 `<style>`、`<script>` 的库（CSP）。
- 半透明背景都要有实色后备值，`<html data-rt="1">`（减少透明效果）时切过去；`build/check_contrast.py` 对半透明背景按“最坏底色”算。
- **动效时长和曲线只能用令牌**：CSS 里 `var(--dur-*)`、`var(--ease-*)`；TSX 里用 `src/motion/tokens.ts` 的常量；两边由测试比对一致（A24）。
- **动画 API 只能在 `src/motion/`**：`motion/react`、`element.animate`、`startViewTransition`、`requestAnimationFrame`（A25）。页面只用 `<Appear>`、`<Pressable>`、`<SharedLayout>`、`transition()`、`celebrate()`。
- 状态用 `data-state` 标记；只动 `transform` 和 `opacity`；扛住页面繁忙的动效用完整 `transform` 字符串，不用 `x`/`y`/`scale` 简写；遵守 `prefers-reduced-motion` 和“减少动态效果”（`data-rm="1"`）；键盘触发的高频操作和全局快捷键打字框不加动效。
- 做动效参考已安装的 animate 等动效 skill，冲突时以本节和架构第 17 节为准；每批交付前代码审查员用 review-animations 审一遍。

### 9.5 数据和服务器
- 写入一律先进 outbox（入队即成功）；同一条记录排队中的 patch 收到确认后推进 base_rev（架构 4.2）。
- 数据库事务和触发器里不等外部调用；服务器函数先查、提交，再调外部服务，最后用条件更新写回。
- 服务器函数只记错误码和耗时，不打印请求头和请求体（A23）；客户端 `js_error` 只记“错误类型 + 文件名和行号”（ADR-010）。
- 用 service role 的函数一律先过 `requireActiveUser`。
- “现在”一律从 `platform/clock.ts` 取（已按服务器 `Date` 头校正偏差），传给 shared 的函数。

### 9.6 依赖、密钥和仓库
- 新增 npm 依赖要在 PR 里写明用途、gzip 体积、维护情况和替代方案；锁精确版本；首屏包不超过 150 KB（gzip，B2 起 CI 硬检查）。
- **依赖供应链**（架构 8.3）：一律 `npm ci --ignore-scripts`，需要安装脚本的包列白名单单独 `npm rebuild`；`npm audit --audit-level=high` 和 OSV-Scanner 不过就不能合并；升级由 Renovate 每周开合并 PR，人工分批评审，不自动合并；函数提交 `deno.lock`，部署加 `--frozen`；**构建任务拿不到任何部署密钥**。
- **最要紧的三把钥匙**（VAULT_KEY、PIN_PEPPER、Tauri 签名私钥）由产品负责人本人运行 `tools/keys/` 的脚本生成并直接写入，**不经过 AI**；AI 只写脚本，不碰值（架构 8.4）。脚本不写临时文件，值不进命令行参数和 PowerShell 历史。
- **CI 部署任务只下载构建产物，不跑 npm、cargo**；工具用 `tools/ci-tools.lock` 锁版本和哈希的二进制；Rust 依赖 `Cargo.lock` + `--locked` + cargo audit / deny；exe 的签名任务不编译（架构 8.3）。
- **手动用正式令牌或 service role key**：默认由产品负责人本人在自己的 PowerShell 执行；例外时临时生成，用完立即吊销，记进过程记录（架构 8.4）。
- **exe 的窗口权限**：`main`、`auth`、`quick-add` 三个窗口分开；只有 `auth` 加载 Turnstile，`quick-add` 不连服务器；`withGlobalTauri = false`（架构 5.10）。
- 前端只能读 `VITE_PUBLIC_*` 环境变量；一切 `.env*`（除 `.env.example`）、`.dev.vars`、`.wrangler/` 被 `.gitignore` 忽略；真实密钥只放在 GitHub Environments、`supabase secrets`、`wrangler secret`、Windows 凭据管理器。
- 本机提交前由 `.githooks/pre-commit` 跑 gitleaks（克隆后执行 `git config core.hooksPath .githooks`）。
- 真实数据的本机备份不放在 `D:\claude code\` 下面。
