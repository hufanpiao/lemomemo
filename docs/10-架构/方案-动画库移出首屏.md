# 方案：动画库移出首屏（R-354）

- 日期：2026-11-07　写的人：前端 A（只做了调研，没有改代码）
- 依据：负责人 R-354。B2-UI-a 签完后，紧接着把动画库（motion-dom、framer-motion，即 `motion/react`）移出首屏。工期半天到 1 天；首屏入场动画要过动效关，看起来不能变。
- 状态：已定。主持人 11-07 按推荐定：做法 A；第 7 节四件事全按推荐（appPainted 之后立刻下载；功能包到了以后安全时机重挂一次今天页列表，加焦点守卫，新增一条 e2e；动画壳和功能包合成一块）。

## 0. 先说结论

1. **首屏里实际只剩约 16 KB 的动画库，不是 30 KB**。约 31 KB 的功能包（`feature-bundle`，domMax）在 B2 FA-6 ② 就已经改成异步下载了。实测它是在今天页出现**之后**才开始下载的，不计入首屏（见第 3 节）。留在首屏 main 块里的是 `m`、`AnimatePresence`、`LazyMotion`、`MotionConfig`、`LayoutGroup`、`useIsPresent`、`PresenceContext` 这一层“壳”，再加上 Appear、AppearList 自己的代码。
2. **首屏上动画库什么都不播**。功能包没到之前挂上的元素一律画成停稳的样子（`initial={false}`）；AppearList 第一次画列表本来就不播入场。所以首屏首帧上没有任何 motion 动画需要模仿。“首屏入场动画看起来不变”这一条，等于要求替身输出的 DOM 和 motion 冷渲染输出的 DOM 一模一样。
3. **推荐做法 A**（第 2 节）：Appear、AppearList、AppearItem、SharedLayout 在首屏只留一层很薄的“门面”，功能包没到时画静态元素（就是今天冷启动画出来的样子）。真正的 motion 实现连同功能包合成一块，`appPainted()` 之后下载，到了以后门面在安全的时机换成 motion 实现。
4. **预计节省**：按 e2e 口径，首屏从 **148.8 KB 降到约 134～135 KB**，省 **约 14～15 KB**。上限 16.1 KB 是实测的（第 3 节），门面和加载代码估计要用回 0.5～1 KB。
5. Pressable 不用 motion，它是纯 CSS 变量加 WAAPI，跟这件事无关，不用改。

## 1. 首屏上哪些组件用了 motion，各自做什么

先说首屏的范围：冷启动打开今天页，今天页出现之前开始下载的 JS（`tests/e2e/b2-first-screen-budget.spec.ts` 的口径）。

| 组件（文件） | 首屏路径上谁用 | 首帧做什么 | 首屏画完、功能包到了以后做什么 | 用不用 motion |
|---|---|---|---|---|
| `AppearList` / `AppearItem`（`src/motion/AppearList.tsx`） | 今天页（`TodayPage.tsx:161～210`，过期组、今天的安排）；待办页同样用，但不在首屏 | 套一层 `MotionConfig`、`LazyMotion`、`LayoutGroup`、`AnimatePresence initial={false}`，每行是 `m.li` 或 `m.section`。功能包没到时 `cold`，`initial={false}`，**不播任何动画**，行直接显示。LazyMotion 第一次挂上时，在 useEffect 里开始下载功能包 | 删行：淡出（110 ms），下面的行做 layout FLIP 收上来；加行、撤销、打勾挪组：等一下再淡入；`data-state="entering"`、`"leaving"` 加 `inert`；淡入和 layout 位移走同一个时钟（onUpdate） | 是：这是首屏把壳带进来的主要原因 |
| `Appear`（`src/motion/Appear.tsx`） | 首屏路径上没有直接用的。RemindHost 的横幅和按钮条在首屏画完、浏览器空闲之后才挂；SyncNoticeHost 跟着 after-paint 块下载；Dialog、Popover、日历的选择遮罩都要用户操作以后才出现 | 不出现 | 提示条、弹层、遮罩的进出场（presets 里的 toast、sheet、scrim、popover），退场时加 `inert` | 是。它的代码现在也在 main 里，因为和 AppearList 共用壳，打包时被合进了 main |
| `SharedLayout`（`src/motion/SharedLayout.tsx`） | 首屏不用 | — | layoutId 衔接 | 是（要 domMax） |
| `Pressable`（`src/motion/Pressable.tsx`） | 首屏到处都有（底栏、“＋”、行按钮） | 按下时用 CSS 变量缩放，`data-state` 写 pressed 或 idle | 同左 | **否**：只引了 react 和 CSS |
| `transition`、`fadeSwap`、`animateIn`、`animateOut`、`press`（`src/motion/index.ts`） | 路由切页、页签互切 | 冷启动不播 | View Transition 或 WAAPI | **否**：都是 WAAPI 或 View Transition API |
| 功能包 `feature-bundle.ts`（domMax） | 由第一个挂上的 LazyMotion 触发下载 | 不在首屏（实测在今天页出现之后才开始下载） | 给所有 m 组件装上动画、手势、layout | 是，但已经不在首屏 |

要点：首屏上必须**静态**引入 motion 的只有 AppearList 这一条线。它在首帧什么动画都不播，只是“占好位置，以后功能包到了能播”。

## 2. 可选做法和取舍

### 做法 A（推荐）：薄门面＋首屏画完后懒加载 motion 实现，到了以后在安全时机换上

- **拆成两层**：
  - `src/motion/Appear.tsx`、`AppearList.tsx`、`SharedLayout.tsx` 改成门面，只依赖 react，对外接口（props、导出名）不变，所以 TodayPage、TodosPage、Dialog 等调用方都不用改。
  - 现在的实现原样挪到新文件 `src/motion/motion-impl.tsx`。这一块里有 motion/react 的壳，再把 domMax 也并进来，成为“动画实现＋功能包”一块。
- **功能包没到时门面画什么**：画和现在冷渲染**逐属性一致**的静态元素。
  - AppearList：`<ul|ol|div style="position:relative;isolation:isolate">`。
  - AppearItem：`<li|section|div>`，带 className、data-*、aria-labelledby，不带 `entering` 状态。
  - Appear：`show` 为 true 时画 `<div data-appear class>`，遮罩加 `aria-hidden`。
  - motion 冷渲染会写哪些内联 style（例如 `opacity:1`），实现的第一步用单测把两边的 DOM 序列化对比，一致了才往下做。这是 G10 的关键。
- **什么时候下载**：`main.tsx` 里 `await appPainted()` 之后马上调 `loadMotionFeatures()`（不等 idle，理由见第 7 节第 2 件事）。这时首屏已经画完，不计入首屏预算。到了以后照旧给 `<html>` 写 `data-motion="ready"`，e2e 的等待写法不变。
- **到了以后什么时候换成 motion 实现**：
  - Appear、SharedLayout：在**变成显示的那一刻**决定用哪个实现（`show` 从 false 变 true 时看一次功能包到了没有）。还没到就整次用静态，离开时当场移除（和现在“加载期间离开的当场移除”一样）。首屏没有显示中的 Appear，所以没有需要“换”的实例。
  - AppearList：今天页的列表在首屏就挂着了，功能包到了以后要在安全的时机换一次，换完以后删行、打勾的动画才和现在一样。换法是 AppearList 外壳的 key 加一，子树重挂一次。DOM 输出完全一样，所以画面上看不出来。换之前先查三件事，有一件不满足就推迟到下一帧或下一次空闲：
    - 焦点不在列表里；
    - 没有按住不放的指针；
    - 不在 useHoldView 停一拍的期间。
  - 现在冷挂上的行在功能包到了以后，退场和 layout 照常播；换完以后行为一样，只是换的那一刻多一次重挂。
- **好处**：
  - 首屏省约 14～15 KB。
  - 动画实现一行不改，FA-5 和 FA-6 调好的手感（同一时钟、popLayout、inert）全部保留。
  - 调用方不改。
  - 工期约半天到 1 天，在 R-354 的范围内。
- **代价**：
  - 列表在功能包到了以后要重挂一次，行内的临时状态会丢。目前行内只有 Pressable 的 pressed，按住时会推迟换，所以不受影响；以后有行内状态的话要记住这个限制。
  - 第一次用到动画的时机可能比现在稍晚：现在是今天页挂上后立刻开始下载，改成 appPainted 之后，两者相差通常几十到几百毫秒。功能包到之前用户已经删行、打勾的话，那一下没有动画，这和现在功能包没到时的行为相同，只是这个窗口稍长一点。

### 做法 B：首屏用 CSS 或 WAAPI 做等效入场，motion 在 appPainted 后接管

主持人提到了这种做法。调研结果是**首屏上本来就没有入场动画**（见第 1 节），所以“首屏等效入场”没有东西可做。这个做法落到实处就是做法 A。不另列。

### 做法 C：AppearList、Appear 整个改成自写的 WAAPI 实现，不再用 motion，只有 SharedLayout 留 motion

- **好处**：首屏省得一样多；首屏画完后也不用下载约 47 KB 的 motion，只有 SharedLayout 用到时才下载。全站 JS 也少一大块。
- **代价**：
  - 要自己重写 AnimatePresence（等退场播完才卸载、退场途中重新进场）、layout FLIP（`layout="position"`、收拢晚两帧）、popLayout 定位、同一时钟，以及减少动效下 layout 直接到位。
  - FA-5 和 FA-6 三轮设计审、动效审、代码审解决过的问题都要重新验证。
  - `fake-frames`、`appear-*` 等一批单测是按 motion 的行为写的，要重写。
  - 估计 3～5 天，风险高，**超出 R-354 的工期**。可以以后单独排，不在这次做。

### 做法 D：Pressable 改用 CSS

Pressable 现在已经是 CSS 实现，**没有可省的**，不用做。

## 3. 预计能省多少（按 e2e 口径）

量法：工作区不动，在单独目录构建，用 scratchpad 里的临时 Playwright 配置读首屏明细。

| 量什么 | 结果 |
|---|---|
| 现在的首屏（e2e，chromium 和 webkit 各 3 次） | **148.8 KB**。其中 main 45.1 KB、client（supabase-js）62.5 KB、jsx-runtime 11.9 KB，其余是今天页和关口的小块 |
| `feature-bundle`（domMax）在不在首屏 | **不在**。两个浏览器的“今天页出现之前”清单里都没有它，实测是今天页出现之后才开始下载 |
| motion 落在哪些块 | 壳的特征字符串（`transformPerspective`、`whileInView`、`reducedMotion`）在 main 和 feature-bundle 里；`data-appear` 在 main 里，说明 Appear 和 AppearList 的代码都在 main |
| 把 `motion/react` 换成空桩再构建（只换别名，其余照旧；块清单不变，react 没有多出一份） | main 从 46.0 KB 降到 **29.9 KB**（gzip -9，同 e2e 口径），**省 16.1 KB**，这是上限 |
| 单独打包壳（esbuild，react 外置）对照 | 壳约 8.9 KB，domMax 约 41.3 KB，两者一起约 46.8 KB。main 里实际省得比单独打包的壳多，是因为 motion-dom 有一部分是壳和功能包共用的，现在算在 main 里 |
| 做法 A 的净节省 | 16.1 KB 减去门面和加载约 0.5～1 KB，**约 15 KB**；首屏约 **134 KB**（余量从约 1 KB 变成约 16 KB） |
| 首屏画完后多下载多少 | 壳从 main 挪到动画实现块，约 47 KB 在 appPainted 之后下载（现在是 31 KB 在今天页挂上后下载）。全站 JS 总量基本不变 |

注意：主持人说的“main 里约 30 KB”对应的是 feature-bundle 那一块（31.1 KB）。它已经不在首屏，所以这次能省的是 15 KB 左右，不是 30 KB。

## 6. 验收标准

1. **首屏**：e2e `b2-first-screen-budget` 在 chromium 和 webkit 各跑 3 次，**≤ 136 KB**，目标约 134 KB，比 148.8 少 ≥ 13 KB。`check_first_paint_chunks` 查到首屏闭包里没有 motion 特征串。
2. **首帧不变（G10）**：
   - 冷启动逐帧（今天页，两个浏览器，浅色和深色）和改之前逐帧像素一致，阈值同 G10 那一次；
   - `g-*` 视觉基线全过；
   - 门面和 motion 冷渲染 DOM 的一致性单测通过。
3. **到了以后手感不变**：
   - `b2-motion-list`、`b2-tabbar*`、`b2-vt-taps` 两个浏览器全过；
   - 动效评审对比改前改后的删行、打勾挪组、撤销恢复、弹层进出（逐帧），结论“看不出差别”；
   - `data-motion="ready"` 在 appPainted 之后 2 秒内出现（本机 e2e）。
4. **换实现的守卫**：焦点在行内时不换，或者换完焦点还在原处（新 e2e）；按住期间不换（单测）。
5. **减少动态效果**：`reduced-motion*` 单测全过；在减少动态效果下跑 b2-motion-list 通过。
6. **失败兜底**：动画实现块下载失败时，今天页、弹层照常显示和使用（改过的 `b2-motion-focus-retry`）。
7. **常规检查**：全量 vitest（排除 gen-tauri-key）、typecheck、eslint、stylelint、check_arch 都是 0。

## 7. 需要负责人定的事

1. **目标数字**：实际能省约 15 KB（148.8 → 约 134 KB），不是 30 KB；30 KB 的功能包早就不在首屏了。按这个数做，还是不做了？
2. **下载时机**：
   - (a) appPainted 之后立刻下载（推荐：没有动画的窗口最短，和现在差不多）；
   - (b) 和 RemindHost 一样等浏览器空闲（最多再晚约 2 秒，给同步让带宽，但第一次删行或打勾没有动画的可能性更大）。
3. **今天页列表换实现**：
