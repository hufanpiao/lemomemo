# ADR-008 皮肤与深浅色分为两个维度

- 状态：**已采纳**（2026-10-23）
- 来源：代码复审（[代码复审-结构调整](../03-评审/第三轮-工程/代码复审-结构调整.md) 第三部分）、需求 R-06、R-20、界面预审（[采纳结论](../03-评审/第四轮-界面预审/采纳结论.md) #10、#21）

## 背景
v3 要做深浅色切换，v3.1 要做可切换的多套皮肤。现在 tokens.css 用 `data-theme` 一个属性表达深浅色，而且深色变量写了两遍（跟随系统、强制深色各一份）。如果以后把皮肤也塞进 `data-theme`，皮肤数 × 深浅色的组合会让变量成倍膨胀，结构很快就乱了。

## 决定
1. 拆成两个独立的属性，都设在 `<html>` 上：
   - `data-theme`：深浅色，取值 `light` / `dark`；跟随系统时不设，由 `prefers-color-scheme` 决定。
   - `data-skin`：皮肤，v3 只有默认的 `bento`（便当格 + 马卡龙），v3.1 加入 UI-1 提案的蓝幕、暗房、孔版印刷等。
2. 每套皮肤一个 CSS 文件（`src/styles/skins/<名称>.css`），只定义设计变量，浅色、深色各一组；组件 CSS 里不允许写死颜色，一律用变量（架构检查加一条规则）。
3. 偏好统一由 `platform/prefs.js` 保存：`pv-theme`、`pv-skin`。
4. 界面预审新增的变量正式加入：`--inv`、`--on-inv`（反色提醒卡片）、`--late-bg`（“没赶上”胶囊）、`--red-ink`（红色文字），深色下的 `--yellow` 改为 #E6C84A、`--p1` 改为 #E2C85C。
5. 任何皮肤上线前，都要用脚本实测文字对比度 ≥ 4.5:1。

## 后果
- 好处：加一套皮肤只需新增一个变量文件，组件代码不用改；深浅色和皮肤可以任意组合。
- 代价：v3 要先把现有组件 CSS 里 5 处写死的颜色改成变量，tokens.css 要拆成“结构变量”和“皮肤变量”两部分。
