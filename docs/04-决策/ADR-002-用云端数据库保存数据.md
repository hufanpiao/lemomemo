# ADR-002 用云端数据库保存数据

- 状态：已采纳（v1 起）
- 日期：2026-10-23

## 背景
用户要在电脑和手机上看同一份日程和待办，还希望在聊天里让 Claude 代记。浏览器本地存储只在一台设备上，Claude 也读不到。

## 决定
- 数据存在 claude.ai artifact 自带的云端数据库，页面通过 `window.claude.use("db")` 取得，集合为 `events`（日程）和 `todos`（待办），用 `onSnapshot` 实时同步。
- Claude 在聊天里直接写同一个数据库，用 `source: "chat"` 标出来（v2 起）。
- 只有本机偏好（当前视图 `pv-view`、v3 的主题选择）放 `localStorage`。

## 后果
- 好处：多设备同步、Claude 可读写、无需自己维护服务器。
- 代价：页面依赖 claude.ai 登录，仅本人可见；本地测试只能用模拟数据库（`tests/mock/mock-db.js`），发布后实际读写云端还没验证过（见 [测试记录](../06-测试/测试记录.md)）。
- Claude 写入的数据可能不规范，页面必须先整理字段再用（v3 修复 PM-C①）。
- 字段定义见 [数据字典](../05-数据字典/数据字典.md)；换后端时由数据层适配器隔离（见 [ADR-007](ADR-007-目标形态PWA与独立服务器.md)）。
