# ADR-007 目标形态：PWA 与独立服务器

- 状态：**已被 [ADR-011](ADR-011-v4架构总则.md) 取代**（2026-10-24；方向已落地为 v4：PWA + Supabase 首尔 + Cloudflare + Tauri exe，文中“待用户决定”的问题都已定）
- 日期：2026-10-23

## 背景
用户提出：这个 App 以后要上线到独立服务器，做成电脑和手机共用的软件。目前它只能在 claude.ai 上运行（[ADR-001](ADR-001-单文件发布.md)、[ADR-002](ADR-002-用云端数据库保存数据.md)），受平台限制：仅本人可见、不能下载 .ics（[ADR-004](ADR-004-不用ics.md)）、页面关着时无法推送（[ADR-005](ADR-005-页面关闭时的提醒靠Claude定时推送.md)）。

## 决定
- **目标形态**：用同一套前端代码做成 PWA（渐进式网页应用），可以安装到电脑桌面和手机主屏幕，支持离线使用和 Web Push 推送。
- **现阶段**：先在 claude.ai 上运行（v3）。数据层采用**适配器模式**：UI 只调用统一的数据接口，具体实现放在 `src/scripts/data/`（数据适配器）和 `src/scripts/platform/`（运行环境：claude.ai 或独立服务器），由程序员 1 实现。以后换后端时只换适配器，UI 不用改。
- 构建脚本区分两种目标：`python build/build.py --target claude`（默认，单文件）和 `--target web`（预留，PWA 多文件）。
- 分阶段推进，见 [路线图](../09-路线图/路线图.md)。

## 后果
- 页面关着时的提醒：在独立服务器上可以用 Web Push 真正实现；在 claude.ai 上暂时只能靠 Claude 定时推送。
- 数据字段（[数据字典](../05-数据字典/数据字典.md)）从现在起要按“与后端无关”的标准设计：时间统一用毫秒时间戳或 `YYYY-MM-DD` / `HH:MM` 字符串，不依赖 claude.ai 数据库的特有类型。
- Claude 在聊天里代记的能力，迁出 claude.ai 后需要另想办法（例如给 Claude 一个接口），否则会失去。
- 多一层适配器，v3 的代码量略增。

## 待用户决定的问题
1. **后端技术**：自建（例如 Node + SQLite）还是托管服务（例如 Supabase）。
2. **登录方式**：邮箱验证码、第三方登录，还是只给自己用的简单口令。
3. **域名和 HTTPS**：用什么域名；证书怎么来（PWA 和 Web Push 都要求 HTTPS）。
4. **数据迁移**：怎么把 claude.ai 云端数据库里的数据搬出来（例如用 v3 的“导出备份 JSON”再导入新后端），以及迁移期间两边是否并行。
5. 迁出后是否保留 claude.ai 版，以及 Claude 代记怎么接到新后端。

## 补充：用户的使用环境（2026-10-23 用户确认）
- 主要用 **iPhone**，主要在 **韩国**使用。
- 影响：
  - iPhone 的 Web Push 走苹果的推送服务，在韩国能正常收到。前提是在 Safari 里把页面“添加到主屏幕”，并且系统是 iOS 16.4 以上。
  - 韩国不需要像中国大陆那样办 ICP 备案。Cloudflare Pages、Vercel、Supabase（有首尔节点 ap-northeast-2）在韩国都能稳定访问。
  - 所以“托管服务”路线（前端用 Cloudflare Pages 或 Vercel，后端用 Supabase 首尔节点）成本最低、最省事，作为首选候选；自己租服务器（如 AWS 首尔、Naver Cloud）作为备选。

## 补充：时间表调整（2026-10-23，需求 R-28）
- 产品负责人发现 claude.ai 版即使用“在窗口中打开”，也还是 claude.ai 的页面，不是独立软件。
- 决定：**v3 发布后立即做 v4 独立软件**，即路线图阶段 2（PWA 外壳）+ 阶段 3（独立后端）+ 阶段 4（Web Push 推送）。原定 v3.1 的生日提醒（含阴历）和皮肤选择并入 v4。
- v4 开工前要请产品负责人决定：域名、登录方式（建议邮箱验证码或 Apple 登录）、确认用 Supabase 首尔节点；并按安全审查的迁移清单逐项落实。
