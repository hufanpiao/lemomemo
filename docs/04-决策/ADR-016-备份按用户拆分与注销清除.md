# ADR-016 备份按用户拆分，注销时从所有备份里清除

- 状态：**已采纳**（2026-10-24）
- 日期：2026-10-24
- 来源：需求 R-60；安全审查（架构 v4）高 1、中 8；第七轮整体检查；[架构设计-v4](../10-架构/架构设计-v4.md) 第 6、10 节
- 关联：[ADR-009](ADR-009-每个版本前备份数据和源码.md)（版本前备份的做法继续有效，存放位置按本 ADR）

## 背景
Supabase 免费版没有自动备份；ADR-009 要求本机有完整副本。4.0.0 有朋友的数据：朋友注销时，按 R-60 要从所有备份里删干净；整库 SQL 导出做不到按人删除。备份里是朋友的明文，放在开发目录里会被开发工具读到。

## 决定
1. **服务器备份**：backup-daily 每天首尔时间 00:30，**每个用户单独调用一次**，把各表导出成 JSON（含已删除）、gzip，放到 `backups/<日期>/<user_id>/`，保留 7 天。图片不进服务器备份。不再做整库 SQL 导出。
2. **拉回本机**：Windows 任务计划每天 09:00 运行 `tools/backup/pull.ps1`：经 backup-manifest 拿清单（下载链接 5 分钟有效），每周日用只读 S3 密钥增量同步图片。
3. **存放位置**：`E:\柠檬记-备份\`，**不放在 `D:\claude code\` 下面**，下载后立即用 7-Zip AES-256 加密（或 E 盘开 BitLocker），不进网盘同步。4.0.0 发布前完成（P1）。位置由 R-105 定为 E 盘。
4. **注销**：先停用账号再删数据；删除存储对象、服务器备份、private 里的记录、auth 用户；发邮件通知。管理员不能在 App 里注销。
5. **本机清除**：pull.ps1 按 `deleted_accounts` 清除本机所有历史备份里的这个用户，但要过三道保险：受保护名单（产品负责人自己）、数量闸（一次超过 1 个账号或 20% 就停）、双向对账；任何一道不过只写“需要人工确认”。
6. **凭据**：BACKUP_PULL_TOKEN、S3 只读密钥、加密口令都放在 Windows 凭据管理器；令牌每 90 天换一次。
7. **演练**：4.0.0 上线前在预览环境做一次完整恢复演练，并演练“注销一个朋友测试账号，本机只删了那一个”。

## 后果
- 好处：能按人恢复、按人删除；开发工具读不到朋友的明文。
- 代价：恢复要走导入脚本，不能一条命令还原整库；本机备份要先解密才能看；免费版 1 GB 文件存储里备份也占一份，按 3.4 的用量规则管理。
