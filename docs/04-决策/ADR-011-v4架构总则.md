# ADR-011 v4 架构总则

- 状态：**已采纳**（2026-10-24，架构设计 v4 定稿）
- 日期：2026-10-24
- 取代：[ADR-001](ADR-001-单文件发布.md)、[ADR-002](ADR-002-用云端数据库保存数据.md)、[ADR-005](ADR-005-页面关闭时的提醒靠Claude定时推送.md)、[ADR-007](ADR-007-目标形态PWA与独立服务器.md)
- 详细设计：[架构设计-v4](../10-架构/架构设计-v4.md)

## 背景
v3 跑在 claude.ai 的 artifact 里：只能本人用、页面关着不能准时提醒、数据在 claude.ai 的数据库里、发布单位是一个 HTML 文件（ADR-001、002、005）。产品负责人要求做成独立软件，手机和电脑都能用，可以邀请朋友（R-28、R-47 起），并且在中国大陆也能用（R-66）。ADR-007 定了方向，但具体选型当时还没定。

## 决定
1. **形态**：同一套前端代码做成 PWA（iPhone 主屏幕上显示“Lemo”，R-88），电脑用 Tauri 2 打包成 Windows exe，和手机版在 4.0.0 一起上线（R-63、R-87）。exe 直接加载 `https://lemomemo.com/app/`（同源，B6 技术验证，不行再改成打包本地页面）；4.0.0 的 exe 不做语音（R-90）。
2. **地址**：只用一个域名 `lemomemo.com`。官网首页在 `/`（`/zh/`、`/ko/`），App 在 `/app/`，数据接口经 `/sb/*` 转发到 Supabase（R-66、R-74）。
3. **后端**：Supabase 首尔节点免费版：邮箱验证码登录 + 邀请码注册（只有管理员能发，R-83）、Postgres + 行级权限（每人只能看到自己的）、私有图片桶、Edge Functions（固定在首尔运行）、pg_cron 每分钟查提醒。
4. **前端托管和转发**：Cloudflare Pages + Pages Functions（免费）；监控和保活放在独立 Worker `lemo-ops`。
5. **提醒**：服务器每分钟检查，用 Web Push 推到 iPhone 和 Edge；exe 自己每分钟检查并弹 Windows 通知，点开进入整页提醒（R-85）。
6. **离线优先**：本机 IndexedDB 缓存 + 离线写入队列，联网后补发；冲突按字段判断，规则只在 SQL 里实现一份。
7. **发信**：Resend，发件人 `noreply@lemomemo.com`。
8. **登录防刷**：Cloudflare Turnstile 全局必开。
9. **分层**沿用 v3 的 core → logic → platform → data → ui，新增 `ui/motion/`（动效集中在这里，R-93）；规则见[架构约定](../10-架构/架构约定.md)。
10. **一次发布**：开发分 B0–B7 八批验收，全部做完才上线（R-63）。中国大陆实测是上线后的跟进项（R-95）。

## 后果
- 好处：手机、电脑、朋友都能用；App 关着也能准时提醒；软件和数据分开，更新软件不动数据；全部免费额度内运行。
- 代价：多了服务器、域名、密钥要管（8.4 的密钥表）；免费版有暂停、1 GB 存储、Workers 每天 10 万次请求等上限，要靠监控和保活（架构 6.1）；iPhone 网页推送、离线新建的提醒等受平台限制（风险表）。
- claude.ai 版发布 3.0.1 只读版后冻结，30 天后关闭。
