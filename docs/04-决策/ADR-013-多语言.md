# ADR-013 中韩双语

- 状态：**已采纳**（2026-10-24）
- 日期：2026-10-24
- 来源：需求 R-48、R-75、R-88；架构评审 H1；[架构设计-v4](../10-架构/架构设计-v4.md) 2.4、16.4

## 背景
4.0.0 要给在韩国的朋友用，界面、推送、验证码邮件、官网都要有中文和韩文。v3 里约 215 处中文写死在代码里。

## 决定
1. **词典**：`shared/i18n/zh.ts`、`shared/i18n/ko.ts` 是纯数据（R-96 改成 TS），键名“页面.用途”；`t(key, params, locale)` 找不到键退回中文。两本词典的键必须完全一致——由 TypeScript 类型保证，少一个键编译不过；占位符由测试检查。
2. **logic 只返回键**：业务函数返回 `{key, params}`，由界面或服务器翻译成文字；服务器的推送文案用同一份共享代码和词典生成。
3. **不准写死文字**：ui、logic、data、platform 的字符串里不能出现汉字或谚文（check_arch A20）；解析词表等少数文件写豁免标记。
4. **选哪种语言**：统一用 `pickLocale`——手动选过的优先，其次设备语言里第一个 ko 或 zh，默认中文。登录后以 `profiles.ui_locale` 为准；验证码邮件按 `user_metadata.locale`。
5. **官网**：`/` 在服务端按 cookie 和 Accept-Language 302 到 `/zh/` 或 `/ko/`；爬虫不跳转。
6. **名字**：App 内中文“柠檬记”、韩文“레모”；主屏幕名只能有一个，统一为“Lemo”（R-88）。
7. **排版**：`<html lang>` 跟随界面语言，字体栈按 `:lang()` 分开；按钮不写死宽度（韩文长 20–40%）。

## 后果
- 好处：一套代码两种语言，服务器和前端文案一致。
- 代价：抽取字符串约 1.5–2 人日，韩文翻译和审校另算；每次加文案都要两本词典一起改。
