## 一、它做什么

一次 `{"action":"run"}`：

1. 拿当前时段的锁 `_probe/lock-<floor(现在 / 5 分钟)>`（预览桶 `preview-images`）：先读，已有就回 429；没有就条件写，两个人同时写只有一个成功。run 和 release **共用这一个名额**。**当前和上一时段的锁都不删**：上一时段的锁要留着，别的实例上 `now` 还落在上一时段末尾的晚到请求看到它才会回 429（审查员的三步场景：k 拿锁 → k+1 跑完清旧锁 → 落在 k 末尾的晚到请求仍是 busy，有单测）。时段号小于“当前 − 1”的旧锁在这次运行里顺手清掉（只删 `_probe/lock-<数字>`）。
2. 四个预览桶（`preview-images`、`preview-files`、`preview-vault-images`、`preview-vault-files`）各做一遍，键都在 `_probe/<32 位随机十六进制>/` 下：
   写 `a.txt`（条件写）→ 再条件写一次 `a.txt`（**应回 412，报 `exists`**）→ 读回比对 → 写 `b.txt` → 按本次随机前缀列（应是 2 个）→ 批量删这两个 → 再列（应是 0）。哪步失败就如实报，没清干净就按两个已知的键再清理一次。
3. 正式桶（不带前缀的 `images`、`files`、`vault-images`、`vault-files`）只对一个随机的、不存在的键发 HEAD：被拒（`denied`、403）记为通过；回 404 表示令牌碰得到正式桶，报 `allowed`、不通过。正式桶绝不写、不列、不删。
   **这只是旁证**：403 也可能是别的原因（桶名不对、R2 对 HEAD 的回法）。任务单第五节第 5 项的**主证据是 Cloudflare 后台 R2_FN（预览）令牌的桶范围截图**（只勾了四个 `preview-` 桶），由负责人截图存进 `docs/03-评审/B0/安全/`。
4. **总预算 25 秒**（`TOTAL_BUDGET_MS`），从拿锁到最后一次清理一起算：主步骤（拿锁、清旧锁、四个桶、正式桶 HEAD）只能用到 17 秒，剩下 8 秒留给清理。每个操作（包括读响应体）都和剩余时间赛跑，超时报 `deadline`，**同时中止底下的请求**（`withBudget` 的中止信号经 `index.ts` 并进 fetch，连同没读完的响应体）；每个请求另有 5 秒超时。
   **报 `deadline` 后仍可能有残留**：中止只管本函数这一头，R2 已经收到的写可能照样落盘。所以只要哪次报过 `deadline`，**下线前一定要先 release**，看 `leftovers` 是 0。

`{"action":"release"}`（下线前用）：
- 时段开头 30 秒内（`RELEASE_GUARD_MS` = 总预算 25 秒 + 5 秒余量）回 429，一个请求都不发：上一时段的 run 可能还在跑，这时清 `_probe/` 会删掉它正在用的对象；
- 然后和 run 一样**拿当前时段的锁**，拿不到回 429（带 `Retry-After`）。所以 release 也占掉这个时段的名额，冷却期内连调只花 1 次读，跑过 run 的时段里也调不了 release，反过来也一样；
- 拿到锁才清理：在四个预览桶里按 `_probe/` 列一页，**只删本函数命名的键**（`_probe/<32 位十六进制>/a.txt|b.txt`，加上时段号小于“当前 − 1”的旧锁），再列一次，报每个桶 `_probe/` 下**除锁以外**还剩几个（`leftovers`，应全为 0）。当前和上一时段的锁（最多 2 个几十字节的对象）留着，删函数之后由负责人在 R2 后台删（第五节第 5 步）。

run 的响应（200）只有：`ok`、`region`（函数实际运行的区域，取 `SB_REGION`）、`total_ms`、`old_locks_removed`、每个桶每一步的 `ok` / `status` / `code` / `ms`（列和清理另有本前缀下的个数 `count`）、四个正式桶的 `isolation`。**不含**令牌、endpoint、对象内容、任何键名。

其他响应：404 `not_found`（不是预览）、410 `expired`（过了过期时间）、405（不是 POST）、400 `bad_request`、429 `busy`（带 `retry_after_s` 和 `Retry-After`，是到下一个时段的秒数）、500 `misconfigured`（缺令牌，不说缺哪个）、503 `lock_failed`（连锁都读写不了，带错误码和状态：`network` / `timeout` 多半是连不上，`denied` 是令牌范围不对，`deadline` 是总预算用完）。

## 二、怎么保证只在预览、正式发布不带上去

`supabase functions deploy` 不带函数名时（publish.ps1 第 6 步就是这样调的），部署的是 `supabase/functions/` 下名字合规（不以下划线开头）的函数目录，**再加上 `config.toml` 里 `[functions.<名>]` 声明的函数**（声明可以把入口指到任何地方）。所以 `_preview/` 下的源码不会被当成函数，**前提是**：没有同名顶层目录、配置里没有声明它、别的文件没有引用它。这几条一层层挡：

| 层 | 做法 |
|---|---|
| 仓库里的静态检查 | `build/check_backend.py` **F6**：① `_preview/` 下的目录必须在 `PREVIEW_FUNCS` 里、只放函数目录；② 不准有同名的顶层目录；③ `_preview/` 以外的源码不准 import `_preview/`（静态、动态 import 都认，动态 import 也认反引号）；④ `supabase/` 下除 `functions/_preview/` 本身以外，**任何文件**（config.toml、*.json、迁移、源码，注释也算）出现 `_preview` 就报（按词边界，`vault_preview` 这类表名不算）；⑤ `supabase/` 下其他 `.toml` 里出现 `[functions.<预览专用函数名>]` 就报；⑥ `supabase/config.toml` 用 **tomllib 解析**，按解析结果查 `functions` 表：键里不准有预览专用函数（`[functions.x]`、点号键、内联表、用 `\u` 转义拼出的键名都查得出），任何函数的 `entrypoint` 解析后只能在 `supabase/functions/` 里面、不能进 `functions/_preview/`（`..` 绕出去、转义拼出 `_preview` 都算），解析不了也报。unit.yml 每次 push 都跑，release-build.yml 打正式包前也跑。样例 `tests/arch-fixtures/check_backend/f6-preview-only`、`f6-preview-mention`、`f6-preview-config`、`f6-config-dotted`、`f6-config-inline`、`f3-dyn-backtick` |
| 只有预览生成入口 | `deploy-preview.yml` 的构建任务（无密钥）先跑一遍 `check_backend.py`，不过就停；再用 `check_backend.py --print-preview-funcs` 读名单（名单只写在 check_backend 一处），只给名单里的 `_preview/<名>/` 在**产物里**生成一行的入口 `supabase/functions/<名>/index.ts`（`import '../_preview/<名>/index.ts'`），并在产物的 `config.toml` 末尾加 `[functions.<名>] verify_jwt = false`。仓库里的文件不动 |
| 正式发布再查一遍 | release-build.yml 打正式包前跑一遍完整的 `check_backend.py`。publish.ps1 第 1 步（还没输令牌）用 `check_backend.py --print-preview-funcs` 读名单并检查一次；第 4 步装完工具之后、第 5 步输令牌之前再检查一次（`Assert-NoPreviewFunctions`，只用 PowerShell 查文件）：`supabase\functions\` 下没有和名单同名的目录，`config.toml` 里没有 `_preview`、没有 `[functions.<名>]`。这样不会在输完令牌、db push 之后才失败。另外第 1 步要求工作区干净（含未跟踪文件），本机手动生成的入口也会让发布停下。PowerShell 这层是文本匹配，用转义拼名字绕得过；挡这种写法靠 F6 的 tomllib 检查（unit.yml、release-build.yml） |
| 函数自己再挡一道 | `R2_BUCKET_PREFIX` 不是 `preview-` 就回 404，连令牌都不读（正式环境不设这个变量，是空串）；过了过期时间回 410 |

**publish.ps1 改过**（加了上面两处 `Assert-NoPreviewFunctions`）：按[正式发布说明](../08-发布/正式发布说明-publish.md)第二节要重新过代码审查和安全审查。**B7a 冻结 publish.ps1 时这段要一起复审，并重新记录冻结副本的哈希**（现在还没有登记过冻结哈希，登记册里的状态是“待审”，备注里也写了这一条）。**以后改成“下载 CI 产物部署”时，这个断言要改成查下载下来的产物**，不是查本机工作区。

## 三、怎么调用（任何人都能调，不需要任何密钥）

直接打预览项目（加 `x-region` 固定在首尔；也可以经 `https://preview.lemomemo.com/sb/functions/v1/r2-probe`，那样 `/sb` 自动加 `x-region`，但要另带 `X-App-Version`）。Windows PowerShell 5.1：

```powershell
$u = 'https://yoeqwhygehbaftkppati.supabase.co/functions/v1/r2-probe'
try {
  $r = Invoke-WebRequest -UseBasicParsing -Method Post -Uri $u -Headers @{ 'x-region' = 'ap-northeast-2' } -ContentType 'application/json' -Body '{"action":"run"}'
  "$($r.StatusCode) $($r.Content)"
} catch {
  "$([int]$_.Exception.Response.StatusCode) $($_.ErrorDetails.Message)"
}
```

（10-28 在本机用假配置起函数、按这段命令调过：回 503 `lock_failed` / `network`，400 `bad_request`，正文里没有地址和令牌。没对真 R2 跑过。）

- 如果回 401（`verify_jwt = false` 没生效）：再加两个头 `apikey`、`Authorization: Bearer <预览 anon key>`（anon key 是公开值，仓库变量 `PREVIEW_SUPABASE_ANON_KEY`）。
- 通过标准（P12）：`ok: true`、`region` 是 `ap-northeast-2`；每个桶 7 步全 `ok`，其中 `put_if_absent_again` 是 `code: exists, status: 412`；`list` 的 `count` 是 2、`list_after` 是 0；`isolation` 四个都是 `denied` / 403（旁证）。**把整段响应贴进过程记录**，耗时（`ms`）就是 P12 要记的每步耗时。
- `put_if_absent_again` 报 `overwrote`：R2 不认 `If-None-Match: *`，按任务单第五节第 1 项的退路报架构师。
- `isolation` 有 `allowed`：R2_FN 令牌碰得到正式桶，**立即告诉负责人收窄令牌**（Cloudflare 后台），再告诉安全审查员。

## 四、防滥用和最坏成本

函数里的防护：只认 `preview-`；过期时间；只收 POST；请求体 ≤ 256 字节且只能是 `{"action":"run"}` / `{"action":"release"}`；按时段分键的锁，run 和 release 合起来**每 5 分钟最多一次**（`COOLDOWN_MS`），被挡回时只读一次锁；整次运行 25 秒的总预算。

R2 单价（Cloudflare 公布的标准存储价格）：A 类（写、列）每百万次 4.50 美元，B 类（读、HEAD）每百万次 0.36 美元；每月免费 100 万次 A 类、1000 万次 B 类（整个账号共用，含正式）。

| 情况 | 每次的操作 | 最坏一个月 |
|---|---|---|
| 正常跑一次 | 锁：1 B + 1 A；清旧锁：1～2 A；四个桶各 6 A + 1 B（条件写失败的那次和 DeleteObjects 都按 A 算，偏高估）；正式桶 HEAD 4 B（被拒的请求按收费算）→ **最多约 27 A + 9 B** | 每 5 分钟最多一次 → 最多 8928 次 → 约 24.1 万 A、8 万 B，在免费额度内；就算免费额度已被别的用完，也只多约 **1.1 美元** |
| release 一次（拿到锁） | 锁：1 B + 1 A；四个桶各列一次（A）、有要删的就 DeleteObjects 一次（A）、再列一次（A）→ **最多约 13 A + 1 B** | 和 run 共用每 5 分钟一个名额，一个时段里只会是 run 或 release 之一 → 最坏一个月仍按上一行算（每时段 27 A 封顶），不另外加 |
| release 在时段开头 30 秒内 | 0（不碰 R2） | 0 |
| 同一时段内被挡回（run 或 release） | 1 B（读锁）；同时抢锁输掉的那个多 1 A（条件写回 412） | 受函数调用额度约束（下面） → 最多约 50 万 B ≈ **0.18 美元**（免费额度内是 0） |
| 404 / 410 / 405 / 400 | 0（不碰 R2） | 0 |

**R2 上的最坏成本每月不到 1.5 美元（已有 1 美元账单提醒），真正的风险是函数调用额度：**

> **预览和正式在同一个 Supabase 免费组织里。** 这个函数免 JWT、谁都能调，被人反复调用会吃光**整个组织**每月 50 万次的 Edge Function 调用额度；免费版超额后 Supabase 可能限制整个组织，**正式环境也会受影响**（正式的函数一样停）。
> 所以要求：**上线到删除在同一天内完成**（合并 → deploy-preview 部署 → 调用测完 → 第五节下线），并在[过程记录](../07-开发日志/过程记录.md)里写下部署时间和删除时间。当天做不完就先按第五节删掉，改天再部署。
