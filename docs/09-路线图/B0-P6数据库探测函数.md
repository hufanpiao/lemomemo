## 一、它做什么

一次 `{"action":"run"}`（测试账号 A 的 uid 写死在 `probe.ts` 的 `TEST_UID`，不由调用方传），按顺序（整次总预算 30 秒，超了的那步报 `deadline`，后面的报 `skipped_deadline`）：

0. **拿跨实例的锁**：经 `withScan('fn_ai', …)` 开一个事务，`pg_try_advisory_xact_lock(hashtext('lemo:db-probe'))`；拿不到回 429。整次运行都在这个事务里，提交即放锁，不写任何表。**这一步连不上库时**直接回 200 `{"ok":false,"guard":{"ok":false,"code":…}}`，这就是 ⑥ 不通过的证据。
1. `user_read`：`withUser('fn_ai', A, …)`——`current_user` 是不是 `fn_ai`、`app.uid` 设上没有、A 的 notes 几行、别人的 notes 几行（应 0）。
2. `scan_read`：`withScan('fn_ai', …)`——`app.uid` 为空、`private.scan_embed_queue` 几行几个用户、notes 几行（应 0）。
3. `next_tx`：自开一条和 db.ts **参数一字不差**的连接（`ssl: 'require', prepare: false, max: 1, connect_timeout: 10, idle_timeout: 5`；单测核对两边文本），做 3 轮：一个事务设 `app.uid` 读 A 的 notes，提交后下一个事务读 `current_setting('app.uid', true)` 和 notes——应为空、0 行。
4. `tls_ca`：`ssl: { ca: ca.ts 里的根证书, rejectUnauthorized: true, servername: 连接池主机名 }` 连一次。`ca.ts` 为空时报 `skipped_no_ca`。
5. `plaintext`（只有请求里带 `"plaintext": true` 才做，P6 ⑪）：`ssl: false`、**连接串里的密码换成每次随机的 32 字节假密码**（`probe.ts` 的 `connUrl`）连一次，**应在认证之前被拒**。默认不做。为什么用假密码：postgres.js 里 `ssl: false` 会盖掉连接串的 `sslmode`，服务器一要求明文认证，真密码就直接发出去了；换成假密码以后，就算服务器接受了不加密连接，发出去的也只是假密码。

响应（200）只有：`ok`、`region`、`instance`（本实例启动时生成的随机编号和已运行秒数，看 ⑦ 的“下一次启动”）、`total_ms`、`checks`（每项一个布尔）、`config`（连接串的几个布尔：用户名是 `fn_ai.<ref>`、主机是 `*.pooler.supabase.com`、端口 6543、`sslmode=require`、带了密码；`LEMO_PROBE` 在不在）、每一步的 `ok` / `code` / `ms` 和行数，`tls_ca` 另带根证书的 SHA-256 指纹（公开证书，不敏感）。**不含**连接串、密码、主机名、用户名原文、报错原文：错误只回 SQLSTATE（如 `28P01`）、postgres.js / Node 的大写错误码，或固定的几个词（`tls_cert_untrusted`、`tls_name_mismatch`、`tls_other`、`timeout`、`auth_failed`、`network`、`deadline`、`other`）。

`ok` 只看 P6 的必过项：`login_fn_ai_ref`、`tls_require`、`with_user`、`with_scan`、`next_tx_isolated`（带了 plaintext 时再加“被拒”）。`checks.tls_ca` 单独看：不过有退路（保持 `'require'`，另记待办，报安全审查员）。

其他响应：404 `not_found`（不是预览项目）、410 `expired`、405（不是 POST）、400 `bad_request`（请求体只能是 `{"action":"run"}`，可选再带布尔的 `plaintext`，≤ 256 字节；**带了 `uid` 键一律 400**）、429 `busy`（带 `retry_after_s` 和 `Retry-After`）、500 `misconfigured`（没有 `FN_AI_DB_URL`，或 `TEST_UID` 还是全 0 的占位值；不说是哪一个）。

环境判断（安全审查必改 3）：`SUPABASE_URL` 必须**一字不差**等于 `https://yoeqwhygehbaftkppati.supabase.co`，只许末尾多一个斜杠；带路径、端口、用户名、查询串、大小写不同的一律 404。

## 四、怎么调用（不需要任何密钥）

合并到 main、deploy-preview 跑完（Actions 里这一次是绿的）以后。Windows PowerShell 5.1：

```powershell
$u = 'https://yoeqwhygehbaftkppati.supabase.co/functions/v1/db-probe'
$b = '{"action":"run"}'
try {
  $r = Invoke-WebRequest -UseBasicParsing -Method Post -Uri $u -Headers @{ 'x-region' = 'ap-northeast-2' } -ContentType 'application/json' -Body $b
  "$($r.StatusCode) $($r.Content)"
} catch {
  "$([int]$_.Exception.Response.StatusCode) $($_.ErrorDetails.Message)"
}
```

- 回 401（`verify_jwt = false` 没生效）：加 `apikey`、`Authorization: Bearer <预览 anon key>` 两个头（公开值，仓库变量 `PREVIEW_SUPABASE_ANON_KEY`）。
- 回 429：等 `retry_after_s` 秒再调（同一个实例 60 秒一次）。
- ⑪：Enforce SSL 打开以后，把请求体换成 `{"action":"run","plaintext":true}` 再调一次。**这一次会真的发起一条不加密的连接**，用的是**随机假密码**（不是 fn_ai 的真密码）：被拒时只到握手；万一没被拒，发出去的也只是假密码，认证必然失败（`28P01`），判不通过。
- **把整段响应贴进过程记录**。

## 六、防滥用和成本

- 限频两层：同一个实例 60 秒一次（`COOLDOWN_MS`；失败的一次也占名额）；跨实例同一时刻只有一次在跑（数据库事务级 advisory 锁）。**没有 r2-probe 那种跨实例的“每 5 分钟一次”**：那要一个能写的地方（r2-probe 用的是 R2 的锁对象），本函数只有 fn_ai，不新建表、不写任何数据。所以最坏频率 = 实例数 × 每分钟 1 次，每次开 3～5 条到 Supavisor 的短连接、读几行。
- 预览数据库不按查询计费；真正的风险和 r2-probe 一样是**整个组织每月 50 万次 Edge Function 调用额度**（预览和正式在同一个免费组织，任何人都能调）。所以同样要求：**部署到删除在同一天内完成**，过程记录写下部署时间和删除时间。
