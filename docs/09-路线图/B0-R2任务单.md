## 四、本机怎么跑（不用真 R2）

**为什么不用 wrangler / miniflare 的本地 R2**：它只能经 R2 绑定访问，没有 S3 接口；服务器函数（Deno，跑在 `supabase functions serve`）连不上它，`/files` 和 file-check 会是两份存储，“经 `/files` 上传 → file-check 读到同一个对象”这条主路径就测不了。所以两边都走 S3 接口，本机用一个 S3 兼容的替身（架构 0.32 第 4 条）。

步骤（运维 O-1 写成脚本后以脚本为准）：
1. `supabase start`（本地数据库、Auth、Mailpit，`http://127.0.0.1:54321`）；
2. `docker compose -f docker-compose.objstore.yml up -d`，启动脚本建 `images`、`files`、`vault-images`、`vault-files` 四个桶；
3. `npm run build -- --mode preview` 出 `dist/web/`；
4. `.dev.vars`（从 `.dev.vars.example` 复制，不进仓库）写：`SUPABASE_UPSTREAM=http://127.0.0.1:54321`、`SUPABASE_ANON_KEY=<本地 anon>`、`PROXY_SECRET=<本地随便一个>`、`R2_ENDPOINT=http://127.0.0.1:<替身端口>`、`R2_BUCKET_PREFIX=`、`R2_FILES_ACCESS_KEY_ID` / `R2_FILES_SECRET_ACCESS_KEY=<替身的>`、`FILES_URL_SECRET=<本地 32 字节>`；
5. `npx wrangler pages dev dist/web`（`/sb/*`、`/files/*` 和带 CSP 的页面都在这里）；
6. 服务器函数：`supabase functions serve --env-file supabase/.env.local`，里面同样写 `R2_ENDPOINT`、`R2_FN_*` 指向替身；
7. 测试：`npm test`（单测）、`deno test`（函数）、pgTAP（`files_authorize`）、Playwright E2E、D1、注销生成用例，全部打这一套。

**本机能测完的**：TC-B0-99～115、118、119（**架构 0.33：116 挪 B4b-1、117 挪 B1**，它们要的 file-check、account-purge 在 B0 还没有）；TC-B0-35（0.35 起含原 75 的越界一半）、36、40、43、51、74（**架构 0.35：75 挪 B5**）；第 3.3 节四个 R2 桶的 TC-DEL；D1。
