## 二、硬约束

1. **动效只做最基本的（R-376）**：新功能只做按下反馈、淡入淡出这一类，不打磨，**不走 ②b 动效确认**（开发计划 ②b 暂停）。17.4 的 B4 项“增删有动效、切换只淡入淡出”按这个口径做到最基本即可；**已定**：TC-B4-13 的“人工录屏”一半、TC-B4-15 的“＋”外环挪到最后统一重做时再做（R-376，第六节第 2 条）。现有动效原样不动。
2. **查找只做逻辑（开发计划第 26 行 ②）**：`shared/logic/search.ts` 是纯函数，`core` 里只加本机关键词查找的调用入口；**不做页面搜索框、不加路由、不加界面文案**，界面留给 B4b-3 的“＋”。
3. **AI 分类先查同意、在服务器上查**：`aiAllowed` 不过的一条都不送；回放桩测“Gemini 0 次”（照 BE-6 的做法）；不真调 Gemini 做测试。只有 ai-parse、ai-voice、claude-intake、voice-probe 和 B4 新加的 ai-classify 能读 `GEMINI_API_KEY`（B3 任务单建议的越界规则，B4 加上 ai-classify）。voice-probe 照 B3 下线 8 步删掉时，要同时把它从这份名单里删掉（`build/check_backend.py`）。
4. **改了分类提示词要升版本**：`classify.v1.ts` 照 [B3 任务单](B3-任务单.md) 第 368 行“前置问题” R4（提示词扩展名，代码审建议 9，已由架构师定）的定法，放 `supabase/functions/_shared/ai/prompts/`，只导出字符串常量、不写逻辑，版本只认 `params.ts` 的 `PROMPT_VERSION`；参数用 `params.ts` 同一份（temperature 0）。
5. **永久删除只走 RPC**：客户端不能经 REST 硬删；“全部清空”只清主页面四张表，不含隐私记（R-193）。
6. **插图一律经 `platform/files.ts` 和 `/files`**，页面不许绕开（S-B4 核对项）；照片不存定位（R-108）。
7. 不新加 npm 依赖。**已定 HEIC 不加依赖**（R-377，第六节第 3 条）：靠浏览器自己解码，解不了就提示“请先转成 JPG”。
