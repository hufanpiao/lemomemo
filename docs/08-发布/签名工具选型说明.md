## 二、推荐：锁 exe，zip 一并记下

脚本核对的是**真正运行的那个文件**（`cargo-tauri.exe`），所以锁文件里锁 exe 的哈希；zip 的哈希一并记在注释里，方便以后对照发布页。

1. 负责人同意下载后，由运维和安全审查员**各自独立**从发布页下载 zip，先核对 zip 的 SHA-256 等于上面那串（GitHub 页面上的摘要）；
2. 两人各自解压，**各自算** `cargo-tauri.exe` 的 SHA-256（`Get-FileHash -Algorithm SHA256`），**两人结果一致才写进锁文件**；不一致就停，查原因；
3. 记下 `Get-AuthenticodeSignature` 的结果（预计 `NotSigned`，待实测），写进锁文件那段注释；
4. 写进 `tools/ci-tools.lock` 的一行（哈希等两人算出来再填；文件名列必须是 `cargo-tauri.exe`，脚本按它核对 `-Signer` 的文件名）：

   ```
   # tauri signer：负责人本机生成 exe 更新签名密钥（tools/keys/gen-tauri-key.ps1；B6-exe F10）。CI 不装。
   # 例外：官方没有 checksums 文件，下一行的 SHA-256 是 exe 的哈希，由运维和安全审查员各自从 zip 解压后独立算出、结果一致（<日期>，<两人>）；
   #       zip 本身的 SHA-256 抄自 GitHub 附件页显示的摘要：3e8687fb184bd7f10ebd8642f7715f79f4a605c0694c142a21507e8a24dc0f8b
   #       Authenticode：<实测结果，预计 NotSigned>
   #       空密码实测（<日期>，-Practice 两次直接回车）：<签名工具打印 / 不打印 <empty>；脚本报“密码为空”并停 / 没停>
   #       同一次核对：Ctrl+C 后 finally 清剪贴板 <清了 / 没清>；三个剪贴板排除标记 <GetFormats 列出三个 / 缺哪个>
   tauri-signer  2.12.4   windows_amd64  cargo-tauri.exe  <两人算出的 exe SHA-256>  https://github.com/tauri-apps/tauri/releases/download/tauri-cli-v2.12.4/cargo-tauri-x86_64-pc-windows-msvc.zip
   ```

5. **空密码实测**（上一步锁文件那一行写好以后、负责人运行真钥匙之前做；F10 代码审查复核第 1 条）。tauri-cli 2.12.4 带的 minisign 空密码时会不会在标准输出打印 `<empty>`，读网页确认不了，只能实测。
   脚本不查 Claude（R-298），由负责人自己先退出 Claude，再在新开的 PowerShell 窗口里照步骤文档运行（练习模式生成的钥匙用完就丢，不是真钥匙）：
   - **空密码**：`-Target preview -Practice` 运行，签名工具两次问密码都**直接按回车**。应当报「密码为空」并停，不显示 key id。
     如果没停、走到了「流程走通了」，说明这版签名工具空密码时不打印 `<empty>`，脚本这道检查不起作用：**停，真钥匙先不跑**，告诉主持人改脚本。
   - **同一次顺带核两点**：再用 `-Target preview -Practice -PracticeSave` 运行一次，输入一个不为空的密码。脚本把私钥放进剪贴板、提示“保存好以后回到这里按回车”时，**不要去存**，按顺序做：
     1. 三个排除标记：另开一个 PowerShell 窗口运行
        `powershell -STA -NoProfile -Command "Add-Type -AssemblyName System.Windows.Forms; [System.Windows.Forms.Clipboard]::GetDataObject().GetFormats()"`
        （只列格式名，不显示内容），应当列出 `ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory`、`CanUploadToCloudClipboard` 三个；
        这只能证明三个标记放上了，不能证明系统照着做。不要用 Win+V 核对：脚本要求剪贴板历史关着，Win+V 只会提示历史已关，**不要点“打开”**；
     2. Ctrl+C：回到脚本窗口按 **Ctrl+C**。应当看到绿色的「已清剪贴板、清掉内存里的变量」；**看到绿色那一行之后**，再到另一个窗口运行
        `powershell -STA -NoProfile -Command "(Get-Clipboard | Out-String).Trim().Length"`，应当是 `0`（剪贴板已清）。
   - 三项结果写进锁文件那段注释（上面代码块里的两行），并告诉主持人。任何一项不对都先停，不跑真钥匙。

## 三、和锁文件规则的偏离（例外怎么写）

`tools/ci-tools.lock` 开头的规则是“SHA-256 抄自该版本官方发布页的 checksums 文件，不是自己算的”。tauri-cli 没有官方 checksums，所以 `tauri-signer` 这一行是**例外**：

- 例外写在那一行上面的注释里（见上面第 4 步），写明：哈希是自己算的、谁算的、哪天、两人结果一致；zip 的哈希来自 GitHub 附件页的摘要；
- 第六列“下载地址”指向 zip，不是 exe：`build/ci/install-tool.sh` 不读这一行（CI 不装签名工具），只有 `gen-tauri-key.ps1` 读它的版本、文件名、哈希三列；
- 升级时同样两人独立算、注释同步更新；代码审查员对照 GitHub 附件页的 zip 摘要核对，安全审查员会签；
- 环境清单第七节（偏离架构的地方）补一条记这个例外（等锁文件那一行真正写进去时一起加）。
