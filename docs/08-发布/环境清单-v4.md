**项目级令牌已核实（架构 8.4 第 ① 种情况成立）**：Supabase 2026-10-06 起正式支持“只管选定项目”的个人访问令牌（Scoped PAT），可以按项目选范围、按能力给读或读写、设到期日（最长一年），令牌建好以后权限不能改，要改就删了重建。官方说明：[Scoped personal access tokens are now generally available](https://supabase.com/changelog/scoped-personal-access-tokens-ga)、[Personal access tokens](https://supabase.com/docs/guides/platform/personal-access-tokens)。所以：
- 预览：放一把**只管预览项目**的令牌进 GitHub repository secrets；
- 正式：一把**只管正式项目**的令牌，只放“密码”App。
- 预览令牌先只开三项权限（第四节）；`supabase link` 如果还要读别的（例如 API Keys、Database Config），第一次部署会返回 403，响应里的 `missing_permissions` 写明缺哪一项，运维照着告诉负责人重建令牌（项目级令牌建好后不能改权限）。
- **还要实测**（第一次预览部署时）：`supabase link`、`db push`、`functions deploy --use-api` 用项目级令牌能不能跑通。官方写明“用数据库密码连接的命令不受令牌权限限制”，`db push` 实际靠数据库密码；`supabase whoami` 不支持项目级令牌（我们不用它）。跑不通就按架构 8.4 第 ② 种情况：预览的函数部署改由负责人本机执行。

### 2. 自定义错误页（14.2 第 7 点要求 B0 核实）——**免费版不能用**

2026-10-28 查 Cloudflare 官方文档：Custom Errors（自定义错误规则、错误页资源、Error Pages）**只有付费套餐有**；免费版的可用数量是 0，Error Pages 一栏是“No”。来源：[Custom Errors](https://developers.cloudflare.com/rules/custom-errors/)、[Cloudflare Custom Pages](https://developers.cloudflare.com/support/more-dashboard-apps/cloudflare-custom-pages/)。

所以照 14.2 第 7 点的退路办：**接受 Cloudflare 的默认错误页**，`/` 的语言分流超额报错时，用户看到的是 Cloudflare 的英文错误页，不能放“去 /zh/”的链接；lemo-ops 在用量到 70% 时提前发邮件。另外两点：
- Pages 自己的 404：产物根目录放 `404.html`，Pages 找不到文件时会用它（这是 Pages 的静态功能，免费，和上面的 Custom Errors 无关；前端 B 做官网骨架时放）；
- Pages Functions 免费额度用完时到底返回什么，官方定价页没写（[Pages Functions 定价](https://developers.cloudflare.com/pages/functions/pricing/)只写了“静态资源请求免费不限量”“每天 UTC 午夜重置”）。B7a 前在预览项目上量一次，写进上线与回滚手册。

架构 14.2 第 7 点已按上面的结论改（0.31 第 31 条）；另定 `site/errors/5xx.html` 挂不上去，前端 B 删掉。
