## 结论

**有条件通过，8 / 10。**

- **代码**：门面、换实现、加载这三层分得清楚。实现文件一行没改，FA-5、FA-6 调好的手感原样保留。
  - 换实现的三道守卫（焦点、按住、停一拍）设计对，单测也覆盖了；
  - 门面和 motion 冷渲染的 DOM 用逐属性比对的单测锁住了；
  - 首屏闭包有 `MOTION_MARKS` 拦着，以后有人把 motion 再静态引回首屏会被发现。
- **动效**：动画实现到了以后看不出差别。到之前的表现和原来“功能包还没到”时一样，只是这段窗口长了一点（负责人已按方案第 7 节第 2 件事接受）。
- **扣分**：主要是那一处已知的行为变化。动画实现到之前就已经显示的提示条，这一次关掉时没有退场。它会落在冷启动时真实会走到的路径上（见“二、动效审”第 3 条），和 R-354“看起来不变”的原话有出入，必须报负责人确认，不能由审查默认放行。

## 必改

### M1 “到之前就显示的 Appear 关掉时没有退场”要报负责人确认，不能默认接受（R-354 原话“看起来不变”）

- **现象**：`Appear.tsx` 用 `still` 记住“这一次显示时实现还没到”，从显示到关掉一直画静态的 `<div>`。关掉时整个 div 当场卸掉（门面换成 `impl.Appear show={false}`，那边没有子元素可退场），没有淡出。
- **和原来比**：原来冷挂上的 `m.div` 在功能包到了以后就装上了动画能力，关掉时照常淡出。所以这是新的差别，不是“和原来一样”。
- **会碰到的路径**（`grep '<Appear'`）：
  - `RemindHost.tsx:139～149` 的横幅、按钮条、提示。整页提醒冷启动时，它们在浏览器空闲时挂上，网络慢时可能早于动画实现块（约 47 KB）到达；用户点“知道了”等关掉时，横幅直接消失；
  - `SyncNoticeHost.tsx:147、152` 的冲突卡和“已彻底删除”轻提示。这两个要等同步结果，多数情况晚于动画实现块；网络很慢时可能早到，冲突卡 8 秒后自动收起时直接消失；
  - `Dialog`、`Popover`、日历选择遮罩都要用户先操作，实际上碰不到；`CacheTooNewScreen` 不会关，不受影响。
- **我的判断**：影响只是“这一次少一个约 0.1～0.2 秒的淡出”，功能不受影响、频率不高，**技术上可以接受**。但 R-354 写的是“看起来不变”，这一条是看得见的例外，按用户规则要先报负责人，由负责人定：
  - ① **接受**：在 R-354 记录和方案第 4 节补一条，写明“首屏画完到动画实现到达之间显示的提示条，这一次关掉时没有退场”；
  - ② **修**：成本不高。动画实现到了、且这条提示条“焦点不在里面、没有按住的指针”（复用 `swap-guard.ts` 的 `canSwap`）时，把它换成 `impl.Appear`，并让实现这一次按“已停稳”挂上：给 `AppearBody` 加一个“冷挂”参数，效果同 `cold`，`initial={false}`、`settled=true`。facade-dom 已经证明冷挂的实现和门面 DOM 一致，换的那一下看不出来，之后关掉就有退场。代价是 `appear-impl.tsx` 要加一个参数，“实现一行不改”这条不再成立。

  在负责人定之前，这一项不算完成。

## 建议（不阻塞）

1. **静态外壳给 `LiveCtx` 明确传 false**（`AppearList.tsx`）。现在静态分支不包 Provider，里层的 `AppearItem` 读到的是外层的 `LiveCtx`。按现在的挂法，“外层已换成实现、里层还是静态”的组合推不出来：外层换的时候整个子树重挂，里层挂上时实现已经在了。但如果以后有人在已经换好的列表里，用别的方式挂一个静态的 `AppearList`，里层的行会画成 `m.li`、却没有自己的 `LazyMotion strict`，直接报错。静态分支包一层 `<LiveCtx.Provider value={false}>` 就能防住，代价几乎为零。
2. **焦点一直在列表里时，守卫每 120 ms 轮询一次、一直轮下去**（`AppearList.tsx` 的 `attempt`）。键盘用户可能长时间停在列表里。功能没问题（焦点离开以后就换），但可以改成监听列表的 `focusout`、`pointerup`，再加 `useHoldView` 结束时的回调，事件来了再判断，不用定时轮询。
3. **下载失败以后，这一次会话里不会再有人去试**（`features.ts` 的 `loadMotionFeatures`）。原来每个新挂上的 `LazyMotion` 都会调一次加载函数；现在只有 `main.tsx` 调一次，失败以后 `pending` 清空，但没有第二个调用方。注释里写的“下一次调用再试一次”在运行时没人触发。浏览器本来就会缓存失败的动态 import，实际后果一样，都是这次会话没有动画、刷新后恢复，所以不阻塞。建议把注释改成和实际一致，或者在 `online` 事件里再调一次。
4. **`watchPointers` 在第一个静态列表挂上后的 effect 里才装**。冷启动画完之前就按住不放的指针（极少见）不会被记下，那时换实现可能正好在按住期间，丢一次 Pressable 的按下态。可以提前到 `main.tsx` 的 `appPainted` 之前装。影响很小。
5. **`SharedLayout` 门面只在挂上那一刻看一次**（`useState(motionImpl)`），挂着期间实现到了也不换。现在只有开发用的 `CspLab` 用它，没有影响。以后正式页面要用的话，记得加换实现的逻辑。

## 二、动效审（按 review-animations 的标准：目的、时长曲线、可打断、退场、减少动态效果、首帧不跳）

两种情况分开看：A 是动画实现到之前，B 是到了以后。

1. **删行**。
   - A：行当场消失，下面的行直接补上，没有淡出和收拢。原来功能包没到时也是这样，只是现在这段窗口从“今天页挂上到功能包到”变成“首屏画完到动画实现到”，稍长一点，块也从 31 KB 变成约 47 KB。
   - B：换完以后，淡出 110 ms、下面的行 FLIP 收上来、离开的行加 `inert`，和原来同一份实现。
   - 结论：看不出差别。
2. **打勾挪组**。
   - A：圆圈的填满是 CSS 动画，照常播；停一拍以后行直接跳到新的组，没有淡入。
   - B：和原来一样。停一拍期间不会换实现，不会把这一拍打断。
   - 结论：看不出差别。
3. **撤销恢复**。
   - A：行直接出现。
   - B：等一下再淡入，和原来一样。
   - 结论：看不出差别。
4. **弹层进出**（Dialog、Popover、遮罩、提示条）。
   - A：门面在“变成显示那一刻”决定用哪个。实现没到就静态显示（原来冷挂也不播进场，所以入场一样），关掉时没有退场（原来有），见 M1。
   - B：变成显示时实现已经在了，整次交给实现，进场、退场、`inert`、停稳后清 transform 都和原来一样。
   - 结论：只有 A 的退场一处有差别。
5. **减少动态效果**：门面按 `useReducedMotionPref` 选 `opacity: 1` 或 `opacity: 1; transform: none`，和实现冷渲染一致（facade-dom 两种设置各比一遍）。换上实现以后照旧读同一个设置。
6. **首帧（G10）**：首屏首帧上本来就没有 motion 动画，门面输出的 DOM 和原来逐属性一致，首帧不会变。冷启动逐帧对比和 `g-*` 视觉基线要在八关第⑦关跑，本审没跑。
