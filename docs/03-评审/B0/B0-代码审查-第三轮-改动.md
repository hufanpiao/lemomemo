## 三、login-probe 的健壮性

| 关注点 | 现状 |
|---|---|
| 只连本机 | `login-probe.mjs:16～23`：API、Mailpit、DB 三个地址都过 `new URL().hostname` 白名单（127.0.0.1 / localhost / [::1]），任何一个取不到或不在名单就 `exit(1)`，在建连接之前。非特殊协议（`postgresql://`）的 hostname 也能正确取出。合格 |
| 不碰密钥 | 只用 `supabase status -o json` 的本地演示 key，不打印；出错时打印的是 GoTrue 的响应文本，不含 key。合格 |
| 失败时退出码 | 每项 `check` 记数，最后 `exit(failed ? 1 : 0)`；中途抛错被 `catch` 记一项失败；`supabase status` 失败或 JSON 不对在 try 外抛出，Node 也以 1 退出；`finally` 里再抛（删用户、`sql.end()`）是顶层 await 未处理的拒绝，同样 1 退出。Mailpit 收不到信等 10 秒后返回空，后续项失败，不会挂死。**合格**。⑤ 的拨回发码时刻依赖 GoTrue 用 `recovery_sent_at` 判有效期，GoTrue 改判法时探针会报不符合而不是悄悄通过，失败方向对 |
| 清理建的用户 | `finally` 里逐个 admin DELETE（`:133`），中途 `throw` 也会走到。**但删除的结果没检查**（低 2） |
| 发信限额 | 每次 3 封（A、K、A 重发；未知邮箱和 429 那次不发信），和注释一致。CI 每次是新起的实例，30 封/小时用不完；ci.yml 里别的步骤没有打 `/auth/v1/otp` 的（`sb-forward.preview.test.ts` 是预览 e2e，不在 ci.yml）。**本机**和 QA 共用同一个实例的 30 封/小时（低 3） |
| CI 位置 | 放在 `db reset` 之后、gen types 和 `test:db` 之前：建的用户删掉后对后面各步没有影响（前提是删成功，见低 2）。CLI 版本 CI 与本机同为 2.120.0（`tools/ci-tools.lock:36`），`MAILPIT_URL` 等键名和后端本机实测一致；`supabase start -x studio` 没排除 Mailpit |

## 四、问题

| # | 严重度 | 文件:行 | 问题 | 建议 |
|---|---|---|---|---|
| 低 1 | 低 | `build/check_backend.py:359` | `set default` 的正则用 `re.search` 在**原文 `r`**（含注释）上只找第一个。我实测两种写法会漏：① 同一句 `alter table app_config alter column features set default '{…note off…}', alter column features set default '{…note on…}'`，只查了第一个；② 语句里注释先写了 `-- 旧：alter column features set default '{}', …`，查的是注释里的 `{}`，真的那个（note on）没查。反过来，字面量后面跟行尾注释（`'…' -- 全关`）会被误报成“不是字面量”（失败方向，不危险）。都要人故意这么写，D1 真库还有 23 号样例那道兜底，所以只算低 | 在遮住注释和字符串内容的 `t` 上 `re.finditer` 找结构（`t` 和 `r` 等长，字符串里的 `''` 也保留），每个匹配都查，字面量内容按同一位置从 `r` 取；建表那条 `features jsonb … default` 同理。样例里补“一句两个 set default”和“注释里先出现”各一处 |
| 低 2 | 低 | `supabase/tests/auth/login-probe.mjs:133` | 清理时 admin DELETE 的返回码没看：删失败（例如以后 B1 加了指向 `auth.users` 却不 cascade 的表）时探针仍报“全部符合”、退出 0，测试用户留在 CI 库里接着跑 `test:db`，在 QA 本机库里越积越多 | 检查每个 DELETE 是 200，否则记一项失败；最后再 `select count(*) from auth.users where email like 'probe-%-' || stamp || '@test.local'` 断言为 0 |
| 低 3 | 低 | `login-probe.mjs:11`、`ci.yml:131` | 注释只说“计入每小时 30 封”。本机一小时跑约 10 次就会用光整个实例的额度，之后 QA 手工登录也会 429 `over_email_send_rate_limit` 至多一小时，容易被误判成登录坏了 | 注释补一句“本机和手工测试共用这 30 封；QA 测登录期间别反复跑探针”；或在实测清单里写上 |
| 低 4 | 低 | `login-probe.mjs:15、96、100、137` | 几处小事：① `stdio` 把 `supabase status` 的 stderr 丢了，失败时只看到 “Command failed”，看不出是没起还是没装；② Windows 上 CLI 若是 npm 装的 `supabase.cmd`，`execFileSync` 不经 shell 会 ENOENT（CI 和后端本机都是 exe，不影响）；③ `body.Text ?? body.HTML`：Mailpit 的 `Text` 为空字符串时不会退到 `HTML`，现在靠 Mailpit 把纯 HTML 信转出文本才过，换成 `` `${Text}\n${HTML}` `` 和 `codeOf` 同一口径更稳；④ 用 `process.exitCode` 代替 `process.exit` 避免 Windows 管道下输出截断；⑤ 文件头 ⑥ 没写实际也查了 `exp - iat = 600`，地址白名单实际也认 `[::1]` | 顺手改，不卡 |
