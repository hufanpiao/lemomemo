## 一、四人一致的结论

| 议题 | 结论 |
|---|---|
| 登录现在做还是以后做 | **和独立软件一起做，不要往后拖。** 理由：数据一上服务器，就得靠登录来限定“只能本人读写”。以后再补，要给每张表加“这条数据属于谁”、重写权限、再搬一次数据，返工约 3–5 人日，现在做只多约 1 人日 |
| 登录方式 | **邮箱 6 位验证码。** 不用“点邮件里的链接登录”，因为在 iPhone 上会跳到 Safari，进不了主屏幕 App |
| 网页后台管理页面 | **不做。** 一个人用，Supabase 自带的控制台就够了；软件里另做“设置 → 数据与备份”。做后台反而多出一个高权限入口 |
| 隐私记 | **在本机加密，服务器只存看不懂的密文；首次设密码时给一份恢复码。** 忘了密码又丢了恢复码，内容就永久找不回。隐私记不进全局搜索、不交给 AI、不推送、不写日志 |
| AI 分类 | 由服务器端函数调用 Claude 小模型，密钥不放在软件里。AI 只能从已有分类里选，用户手动改过的不再改，拿不准就标“未分类”。设置里做开关，默认开。每月费用不到 1 美元（未按最新价格核实） |
| 手机端 | **iPhone 用 Safari“添加到主屏幕”（PWA），不用付苹果的费用。** 推送要 iOS 16.4 以上，并且要从主屏幕图标打开 |
| 电脑端 | **用 Tauri 打包成 exe**（安装包约 10 MB），开机自启用它的插件。不签名的话，第一次运行时 Windows 会提示，点“仍要运行”就行。**更新包必须签名** |
| 后端 | **Supabase 首尔节点**：登录、数据库、图片、定时推送都在里面，免费版就能起步 |
| 底部导航 | **今天 / 日历 / 待办 / 随手记，外加“＋”。** 日程改名“日历”，页内分周、月、生日；设置放右上角 |
| 参考 App 学什么 | 学：月历（带农历、节气）、纪念日和倒数日、全局搜索高亮、节假日、“稍后”。不学：甘特图、农历宜忌、AI 多步代办、大面积粉蓝渐变 |
| 搬家后最容易漏的 | ① 在聊天里让 Claude 代记会失效，要单独开一个“只能新增”的接口给 Claude；② 每日备份、提醒这两个 Claude 定时任务要改到新服务器 |

## 三、回答用户的四个疑问

1. **数据怎么分类**：
   - 你看到的是 5 类：日程（有时间）、待办（能打勾）、随手记（没时间，可带图）、隐私记（上锁的随手记）、生日和纪念日（每年一次）。
   - 随手记可以一键转成待办或日程，原来那条留着并标“已转”。
   - 日程和待办用“项目”分组，随手记用“分类”，两套暂时分开。
   - 数据库里共 9 张表：日程、待办、随手记（隐私记也在这张表里）、生日、分类、图片、设置、推送订阅、日志。每张表都带“属于谁”和“最近删除”字段。
2. **软件架构**：
   - iPhone、网页、电脑 exe 共用一套前端，现有代码约 60% 能直接用；
   - 网页文件放在 Cloudflare Pages，自带 HTTPS；
   - 后端用 Supabase 首尔节点；
   - AI 分类和推送由服务器端函数负责；
   - 每分钟扫一次到点的提醒，用 Web Push 推到手机和电脑。
3. **要不要网页后台**：不要（见上）。
4. **怎么发布**：
   - 网页和 PWA：发到预览地址测试，通过后切到正式地址；用户打开时提示“有新版本，点击刷新”。
   - exe：自动打包，内置自动更新。
   - 版本号规则：大改（换平台、要搬数据）升第一位；新功能升第二位；修问题升第三位，比如 3.0.1。
   - 每次发版照旧：先备份，再评审、测试，最后冻结存档。

## 八、第三轮：用户提供的“零成本上线全家桶”视频（2026-10-24）

视频是用户本人提供的：《一分钱不花完成独立产品从0上线》，时长约 2.5 分钟，原文件在用户的 Downloads 文件夹里，没有复制进项目。视频推荐的免费工具有：
- 网页托管：Cloudflare Pages / Vercel
- 后端：Cloudflare Workers / Supabase
- 数据库：Cloudflare D1 / Supabase Postgres / Turso
- 文件存储：Cloudflare R2 / Supabase Storage
- 登录：Supabase Auth / Clerk
- 发邮件：Resend

主持人的选择：

| 环节 | 选用 | 不选 | 理由 |
|---|---|---|---|
| 网页托管 | **Cloudflare Pages** | Vercel | 带宽不限，可以用于商业；Vercel 免费版禁止商业使用。Cloudflare 免费送一个 `xxx.pages.dev` 地址，所以域名可以先不买 |
| 后端、数据库、登录 | **Supabase**（首尔节点） | Workers、D1、Turso、Clerk | 登录、数据库、权限（RLS）、定时任务、推送函数一站齐全，不用把几家服务拼起来。免费版有 500 MB 数据库，文字记录用不完 |
| 图片 | **先用 Supabase Storage**，以后再考虑 R2 | — | 免费 1 GB，单张压到约 300 KB，能存三千多张；和登录权限天然连在一起。存满了再把图片迁到 R2（免费 10 GB，下载流量也免费） |
| 发邮件 | **先用 Supabase 自带的发件**；买了域名后改用 Resend | — | 视频旁白说 Resend 要用自己的域名，所以“域名可以先不买”只在不用 Resend 时成立。Supabase 自带发件的频率很低（具体条数**待核实**），但只有一个人、每台设备登录一次后能保持很久，够用。要稳定再买域名（约 10–15 美元/年），接 Resend（每天免费 100 封） |

视频没讲到、但我们需要的：
- **推送**：用 Web Push，免费；定时任务用 Supabase 自带的 pg_cron，免费。
- **AI 分类、语音转文字**：不免费，按用量计费，估计每月 1–2 美元以内。浏览器自带的语音识别可以作为免费方案，AI 也可以做成开关。
- **桌面 exe 和代码仓库**：Tauri 免费；GitHub 私有仓库免费，自动打包每月也有免费额度。
- **免费版的注意点**：
  - Supabase 免费版 7 天没人访问会暂停（数据不丢），每天在用就不会暂停；
  - 免费版没有自动备份，每日备份要我们自己做；
  - 免费版能不能一直撑住，按实际用量再看，需要时再升级。

## 九、第四轮：以后推荐给朋友用（R-44）

- **不用另建数据库，也不用每人一个数据库。** 所有人共用一个 Supabase 数据库，每条数据都带一个“属于谁”的字段（user_id）；行级权限（RLS）由数据库自己保证：每个人只能读写自己的数据。原方案已经是这样设计的，现在只是把它定为硬性要求。
- **4.0.0 从第一天起就按多用户来做**，几乎不增加工作量。以后开放给朋友用，不用改结构，也不用搬数据。
- **注册方式**：先不开放注册，用**邀请码**。你给朋友发一个邀请码，朋友用邮箱注册；陌生人注册不了。这也符合安全审查员“关闭注册”的建议。
- **真正给别人用之前要补的事**：
  1. 买域名，并接上 Resend。朋友注册和登录都要收验证码，Supabase 自带的发件不够用。
  2. **隐私记要改回“靠密码加密”。** 现在定的是服务器校验密码，这样你作为管理员理论上能读到朋友的隐私记。朋友用之前，要么改成加密方案（朋友忘了密码就找不回内容），要么明确告诉朋友这一点。
  3. **AI 费用**：每个人每天限定调用次数；AI 开关默认可以关掉。
  4. **隐私政策和同意书**：要写清收集了什么、存在哪里（首尔），以及 AI 调用会把数据传到美国处理。按韩国个人信息保护法，给别人用就成了“个人信息处理者”，需要这些材料（具体条款**待核实**）。
  5. **注销账号时删除全部数据**，也要能导出自己的数据。
  6. **简单的管理功能**：看有多少用户、发邀请码、停用账号。先放在 Supabase 控制台里做，人多了再考虑做后台。
  7. 写一份给朋友看的安装说明：iPhone 添加到主屏幕、Windows 安装 exe。

## 十、AI 是怎么调用的（回答产品负责人提问）

```
手机 / 电脑上的软件
   │ ① 保存随手记，或者长按“＋”说完一句话
   │   （语音先在手机上转成文字：浏览器自带识别；不稳定就上传音频，由服务器转文字）
   ▼
Supabase 服务器函数（Edge Function）
   │ ② 核对是谁登录的，再看今天还剩多少次调用额度
   │ ③ 带上只存在服务器里的 AI 密钥，把这段文字发给 AI 接口
   ▼
AI 接口（推荐 Claude Haiku）
   │ ④ 返回一小段固定格式的结果，例如
   │    {类型: 日程, 日期: 10-25, 时间: 15:00, 标题: NEOX 会议}
   │    或 {分类: 工作}
   ▼
服务器函数检查结果是否合规（只能从固定的类型和分类里选）→ 写进数据库 → 软件上弹出识别卡片，用户确认
```

- **密钥只放在服务器**：软件里没有密钥，拆开 exe 或网页也拿不到。每个用户每天限定次数，防止被刷。
- **哪些内容不发**：隐私记永远不发。“AI 识别”开关关掉以后，只用本地规则（就是现在 v3 的一句话识别），一分钱不花。
- **钱谁出**：所有人的调用都走你的 AI 账号，由你付费。按次计费，没有月租。
- **Claude 会员订阅不能用来抵 API 费用**：会员（Pro/Max）只能在 claude.ai 和 Claude App 里用；软件要调用的是 API，需要在 Anthropic 控制台另外开账号、预充值（最低充值金额**待核实**）。
- **可选的 AI 服务商**：

| 服务商 | 优点 | 缺点 |
|---|---|---|
| **Claude Haiku（推荐）** | 中文、韩文理解好；官方声明 API 数据不用于训练 | 要付费 |
| Google Gemini | 有免费额度 | 免费版的数据可能被用来改进产品（**待核实**），不适合放私人内容 |
| OpenAI 小模型 | 价格相近，还能顺便用它的语音转文字 | 要多开一个账号 |
| 国内低价模型 | 很便宜 | 数据会传到中国境内的服务器，隐私和合规更麻烦 |

- **语音转文字**：Claude 不能直接听语音，所以要先转成文字。先用浏览器自带的识别，免费，在 iPhone 上由苹果处理。不够准或不稳定时，再接按分钟计费的语音转文字服务。
- **服务器函数做成“可换 AI 服务商”的结构**：以后换哪一家都只改一个文件。

## 十一、产品负责人定的原则：“隐私不用太考虑，只要好用就可以”（R-46，2026-10-24）

按这条原则，下面这些默认值从“隐私优先”改成“好用优先”：

| 项目 | 原来的方案 | 改成 |
|---|---|---|
| 推送内容 | 脱敏：只写时间和条数 | **直接写标题**，例如“15:00 NEOX 会议”“明天是妈妈生日” |
| 生日推送 | 默认不显示名字 | **默认显示名字** |
| 隐私记 | 不进搜索、不交给 AI、不推送 | 解锁后**能搜索，也能用 AI 分类**；“隐私记”的作用变成防止别人翻看手机，不再防服务器 |
| 语音记录 | 先用浏览器识别，不行再上传服务器 | **哪种识别更准就用哪种**，以识别准确为准 |
| AI 服务商 | 只考虑声明“不用于训练”的 | **按好用和价格选**；Gemini 免费额度也可以考虑，用来省钱 |
| 图片定位信息 | 上传前去掉 | **保留**（以后可以按地点找照片） |

**不改的底线**：这几条不影响好用，却决定数据会不会泄露或被删，必须保留。
- 行级权限：每个人只能看自己的数据；
- AI 密钥只放在服务器上；
- 邀请码注册；
- 每天自动备份；
- 更新包签名。

给朋友用以后，按第九节补上隐私说明。
