# 第六轮 下一版规划会：架构师意见

- 日期：2026-10-24　依据：README、架构约定、ADR-005/007/009/010、路线图、数据字典、`src/scripts/`、`build/build.py`
- 网络资料都在文末注明来源，没查到的写“未核实”。

## 一、结论（先看这里）

1. **整体方案**：做一套网页程序（PWA，可以“安装”的网页），手机、网页、电脑三端共用。iPhone 上“添加到主屏幕”使用，不用付苹果的费用。电脑版用 **Tauri**（把网页包成 exe 的小工具）打包，开机自启也靠它。后端用 **Supabase 首尔节点**，登录、数据库、图片、定时任务都在里面。
2. **登录现在就做**。以后再补，要给每张表加“这条数据属于谁”、补权限规则、再搬一次数据，返工大约 3–5 人日，还容易出错。现在做只多花约 1 人日。
3. **下一版的版本号叫 4.0.0**。换平台、换数据库属于不兼容的大改，所以第一位加 1；之后修 bug 升第三位，例如 4.0.1，加功能升第二位，例如 4.1.0。
4. **不做网页版后台管理页**。个人使用时 Supabase 自带的控制台就够了，软件里再加一个“设置 → 数据与备份”页面。
5. **分 4 期做，合计约 26–36 人日**（开发主要靠 AI，已含评审和测试）。第一期先把“登录 + 搬数据 + 关着页面也能推送”做完，摆脱对 claude.ai 的依赖。

## 二、整体架构

### 方案比较

| 方案 | 手机端 | 电脑 exe | 费用 | 推送可靠性 | 开发量 | 结论 |
|---|---|---|---|---|---|---|
| A. PWA + Tauri 外壳 | 加到主屏幕 | Tauri，安装包约 10 MB | 苹果 0 元 | iOS 一般 | 最少，一套代码 | **推荐** |
| B. PWA + Electron 外壳 | 同上 | Electron，安装包约 100 MB 以上 | 同上 | 同上 | 与 A 相近 | 体积大，不选 |
| C. Capacitor（网页包成原生 App） | TestFlight / App Store | 仍需 A 或 B | Apple 开发者账号 99 美元/年 | 好（原生推送） | +5–8 人日，还有苹果审核 | 留作备选 |
| D. 原生 App（Swift 等） | App Store | 另写一套 | 同上 | 最好 | 翻倍 | 不选 |

后端比较：**Supabase**（数据库、登录、文件、函数、定时任务一站齐全，有首尔节点，免费版可起步）> Firebase（离韩国近的节点在东京，数据库是文档型，现有设计能用，但统计查询弱）> 自己租服务器（Node + SQLite，最灵活，但备份、安全更新都要自己管，不适合第一次上线）。

### 架构图

```
 iPhone（主屏幕 PWA）   电脑浏览器 / Tauri exe（开机自启、托盘、本机通知）
          └───────────┬──────────────┘
          同一套前端（core→logic→platform→data→ui）
          本机缓存 IndexedDB + 离线写入队列 + Service Worker
                      │ HTTPS
        Cloudflare Pages（放网页文件，自带域名证书）
                      │
 ┌──────────── Supabase 首尔节点 ─────────────┐
 │ 登录 Auth（邮箱验证码 / Apple 登录）        │
 │ 数据库 Postgres + 行级权限（只能读写自己的） │
 │ 文件存储 Storage（图片，私有桶）             │
 │ 函数 Edge Functions：AI 分类、发推送         │
 │ 定时 pg_cron：每分钟扫一次到点的提醒         │
 └──────┬──────────────────────┬───────────────┘
        ▼                      ▼
  Claude API（小模型，分类）  Web Push（苹果 / 谷歌 / 微软推送服务）
```

### 各端怎么装、有什么限制

- **iPhone**：用 Safari 打开网址，点“分享 → 添加到主屏幕”。不需要开发者账号，0 元。推送要求 iOS 16.4 以上，并且必须从主屏幕图标打开、点允许。iOS 上推送订阅偶尔会失效，软件里要有“推送自检”按钮。网页没有自动安装提示，第一次要教用户操作。如果实测推送不可靠，再走方案 C：TestFlight 也要 99 美元/年的账号。
- **exe**：Tauri 2 在 Windows 上打包出 `.msi` 或 `.exe` 安装包。开机自启用官方的 autostart 插件（写入系统的启动项），设置里放开关。未签名的安装包第一次运行时，Windows SmartScreen 会提示“已保护你的电脑”，点“更多信息 → 仍要运行”即可。自己用可以接受。要去掉这个提示得买代码签名（例如微软 Trusted Signing，价格未核实）。exe 里面的浏览器内核收不到 Web Push，所以靠“开机自启 + 程序内定时检查 + 系统通知”提醒；也可以退一步，用 Edge 把网页“安装为应用”，Edge 同样支持登录时自动启动。
- **麦克风**：独立域名下可以用语音输入；iOS 主屏幕模式下语音接口不稳定，保留键盘听写作为后备。

## 三、登录：现在做

- **理由**：所有表从第一天起就有 `user_id`（这条数据的主人），加上行级权限（数据库自己保证每人只能看到自己的数据），之后的图片、推送、AI 函数都按这个字段走。
- **以后再补的代价**：每张表加 `user_id`，把旧数据补上主人；所有权限规则重写；图片路径按用户重新整理；推送订阅重新绑定；前端加登录、退出、换账号的流程。约 3–5 人日。没有登录期间，数据库只能对所有人开放，等于裸奔，不能接受。
- **建议登录方式**：邮箱验证码，免密码。Apple 登录等以后上 App Store 再加。登录一次后，各设备长期保持登录。

## 四、数据怎么分

每张表都有这些公共字段：`id`（uuid）、`user_id`、`created_at`、`updated_at`、`deleted_at`（沿用现有软删除）、`rev`（每改一次加 1，用来发现多设备冲突）。

| 表 | 主要字段 | 复用情况 |
|---|---|---|
| events 日程 | title、date、time、duration_min、project、note、source、raw_text、remind_min、remind_days、remind_at、notified_for、snooze_at | 字段全部复用数据字典，只是驼峰命名改成下划线 |
| todos 待办 | title、done、due、important、project、note、done_at、提醒四字段 | 同上 |
| notes 随手记、隐私记 | title（可空）、body、is_private、category_id、category_by（ai/manual）、tags[]、image_ids[]；隐私记另加 enc_body、iv | 新表；软删除和日志规则沿用 |
| birthdays 生日 | name、calendar（solar/lunar）、month、day、is_leap（闰月）、birth_year（可空）、remind_days 默认 [7,1]、next_date（下一次的阳历日期，缓存）、notified_for | 新表；提醒逻辑沿用 remind.js 的思路 |
| categories 分类 | name、color、sort、preset | 新表；随手记和隐私记共用。`project` 仍然只用于日程和待办 |
| attachments 图片 | note_id、path、bytes、w、h、encrypted | 新表 |
| settings 设置 | 每人一行 JSON：皮肤、深浅色、默认提醒、免打扰时段、一周从周几开始、AI 开关、自动锁定时间 | 原 localStorage 中跨设备的项搬进来；`pv-device` 等本机项仍留在本机 |
| push_subs 推送订阅 | device、endpoint、keys | 新表 |
| logs 日志 | 沿用 ADR-010 格式，加 user_id | 复用 |

- **阴历生日**：用韩国天文研究院（KASI）的数据做阴阳历换算，放在 logic 层，写成纯函数；每年算出当年对应的阳历日期，写入 `next_date`。
- **月历**：只是界面上的一个视图，不用加表。
- **AI 自动分类**：保存随手记后，前端调用 Supabase 的函数，由函数再调用 Claude 的小模型。密钥只存在服务器端，前端拿不到。模型只能从用户现有的分类里选一个，不许自己新造，避免越分越乱。用户手动改过的分类，AI 不再覆盖。网络断开或调用失败时，先按本地关键词规则归类，标为“未分类”或“待分类”，联网后自动重试。成本按小模型估算：每条几百字的记录不到 0.001 美元，每月几百条也不到 1 美元（未按最新价格核实）。
- **查找**：数据量小，数据库用模糊匹配（pg_trgm）就够了，中文也能搜。隐私记只在解锁后在本机搜。

## 五、隐私记的密码

- **在本机加密，服务器只存看不懂的密文**。第一次进入时设置密码，手机或电脑用这个密码算出密钥，再用浏览器自带的加密功能（WebCrypto AES-GCM）加密正文和图片。服务器、Supabase 的工作人员、AI 都看不到内容。
- **忘记密码**：设置密码时同时生成一个“恢复码”（24 个字），提示用户抄在纸上，或存进 iPhone 的密码 App。恢复码也丢了，数据就再也找不回来。这一点必须当面讲清楚，并写进说明书。
- **和 AI 的关系**：隐私记默认**不送 AI**，只能手动选分类，可以用本地关键词给出建议。如果用户愿意送，就要一条一条单独确认，送出去的是明文。
- 解锁后闲置 5 分钟自动上锁，时间可以在设置里改。这个密码不同于登录密码，丢了也不影响登录。

## 六、要不要后台管理页

不需要。查数据、看用户、看图片、导出表格、看函数日志，Supabase 控制台都能做。软件里另做“设置 → 数据与备份”：导出 JSON、导入、查看运行记录、推送自检、各设备登录情况。等以后要给别人用、需要客服处理时，再考虑做后台。

## 七、怎么发布

| 端 | 发版 | 更新 |
|---|---|---|
| 网页 / PWA | 代码推送到 GitHub 后，Cloudflare Pages 自动发布；先发到预览地址测，再切到正式地址 | Service Worker 发现新版本时，提示“有新版本，点击刷新” |
| exe | GitHub Actions 自动打包，上传到 GitHub Releases | Tauri 自带的更新插件自动检查并提示更新 |
| iPhone | 和网页是同一个 | 自动更新 |

**版本号**：第一位是不兼容的大改，比如换平台、改数据结构需要搬数据；第二位是新功能；第三位是修问题。各端共用一个版本号，界面的“关于”页显示出来。

**从 claude.ai 搬数据**：① 按 ADR-009 先完整备份；② claude.ai 版暂停写入，停掉 Claude 的定时推送任务；③ 用 v3 的“导出备份 JSON”导出数据；④ 运行导入脚本：把 id 换成 uuid，补上 user_id，字段改名；⑤ 核对每张表的条数，抽查 10 条；⑥ claude.ai 版只读保留 2 周，然后下线。注意：搬走以后，Claude 在聊天里代记的能力会消失，以后要另外给它接一个接口。

## 八、现有代码能复用多少

- **直接复用（约 60%）**：core 全部；logic 层的一句话解析（中文、韩文）、提醒、搜索、排序；data 层的 normalize、write、log、事件总线；ui 层各组件和皮肤样式；架构检查和测试体系。
- **要扩展**：`collOf`、`kindOf` 要支持 notes、birthdays；data 层多一个本机缓存加离线队列。
- **要新写**：platform 层的 `supabase` 存储适配器，它沿用 `store.js` 写好的接口约定，要加进适配器契约测试；推送、登录、加密模块；ui 层的登录、随手记、隐私记、生日、月历、设置页。
- **`build.py --target web` 怎么落地**：输出到 `dist/web/`，包括 index.html、打包好的 app.js 和 css、`sw.js`、`manifest.webmanifest`、图标；`App.BUILD.target="web"`，由 app.js 选用 supabase 适配器；supabase-js 下载到项目里，不走外部 CDN。Tauri 直接把 `dist/web/` 打进 exe。

## 九、风险和遗漏

1. **费用**：域名约 10–15 美元/年。Supabase 免费版 7 天没人用会自动暂停，数据不会丢；免费版的自动备份能力有限（细节未核实），要么自己做每日导出，要么正式使用后升级 Pro（25 美元/月）。
2. **备份**：每日快照要从 Claude 定时任务改成 Supabase 定时导出，再同步一份到网盘。
3. **多设备冲突**：同一条记录在两台设备上同时改，后写的会覆盖先写的。用 `rev` 发现冲突，随手记出现冲突时保留两份。
4. **离线**：iOS 闲置 7 天可能清掉本机缓存（网络资料，未核实），所以云端才是“正本”。
5. **图片体积**：上传前在本机压到长边 1600 像素、约 200 KB；单张限 10 MB。
6. **韩国个人信息保护法**：只自己用时基本不受影响。一旦给别人用，就需要隐私政策和同意流程；AI 分类会把内容发到美国处理，属于跨境传输，要告知用户。生日记录的是别人的信息，也要谨慎。
7. **推送**：iOS 网页推送不如原生 App 稳定，第一期就要在真机上验收。
8. **工作量**：功能翻了一倍多，一定要分期做，每期都按现在的评审流程走。
9. **功能文档**：建议放在 `docs/11-功能说明/`，每个功能一页，写清操作步骤、截图位置、版本号。每期完成时一起更新，以后直接用来写演示视频脚本和说明书。

## 需要产品负责人决定的事项

1. **手机端**：PWA 加到主屏幕，还是付 99 美元/年上 TestFlight。推荐先用 **PWA**，推送不可靠时再改。
2. **登录**：推荐**现在做，用邮箱验证码登录**。
3. **后端**：推荐 **Supabase 首尔节点**，先用免费版，正式使用后升级 Pro（25 美元/月）。
4. **域名**：需要买一个，例如 .com 或 .kr，约 10–15 美元/年。推荐**买**，并交给 Cloudflare 管理。
5. **exe 要不要签名**：推荐**先不签**，遇到 SmartScreen 提示时手动点“仍要运行”。
6. **隐私记送不送 AI**：推荐**默认不送**。
7. **忘记密码怎么办**：推荐**只用恢复码，接受丢了就无法恢复**。
8. **版本号**：推荐**下一版叫 4.0.0**，之后按“新功能升第二位、修问题升第三位”的规则。
9. **claude.ai 版搬家后**：推荐**只读保留 2 周后下线**，Claude 代记功能以后再接。
10. **后台管理页**：推荐**不做**，用 Supabase 控制台加软件内的设置页。
