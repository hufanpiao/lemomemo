# 第六轮 · 安全与隐私（下一版规划会，独立意见）

**总结论**
1. 登录**这一版就做**。数据一上服务器就必须有登录，否则行级权限（RLS）没法限定“只有本人”。
2. 隐私记用**端到端加密**，同时给一份**恢复码**。
3. AI 分类走服务端，隐私记**绝对不发**。
4. **不做网页后台**。
5. 更新包**必须签名**。

## 1. 登录
- **时机**：现在做。以后再补，就得给已有数据回填 user_id、重写权限，风险更大。
- **方式**：首选**邮箱 6 位验证码**，再加 **Apple 登录**作为第二种方式。不用魔法链接：iPhone 上点邮件里的链接会在 Safari 里打开，登录不到主屏幕的 App 里。不用密码：要防撞库、要做找回。Passkey 最安全，但 Supabase 的 Passkey 还是实验性的 Beta（[来源](https://supabase.com/docs/guides/auth/passkeys)），等它正式发布再加。
- **账号设置**：自己的账号建好后，关闭新用户注册。开 TOTP 两步验证。Supabase 账号本身也要开两步验证。
- **会话**：访问令牌 1 小时过期，刷新令牌每次用后轮换。30 天没用就要重新登录。
- **桌面端**：令牌存进 Windows 凭据管理器，不写成普通文件。
- **丢手机**：在电脑上点“退出所有设备”（全局登出），再改邮箱密码。隐私记有加密，丢了的手机上读不出来。
- **换手机**：重新登录，再输入一次隐私记密码。

## 2. 隐私记的密码

| | A 只在界面上锁 | B 服务端校验 | **C 端到端加密（推荐）** |
|---|---|---|---|
| 安全性 | 差：数据库、缓存、备份里都是明文 | 中：服务器、备份、我们自己都能读 | 高：服务器和备份里只有密文 |
| 忘记密码 | 能重置 | 能重置 | **找不回**。只能靠恢复码，恢复码也丢了，内容就永久丢失 |
| 搜索 | 能 | 能 | 只能在解锁后的本机上搜 |
| AI 分类 | 能（但不应该） | 能（但不应该） | 不能。只能手动分类，或以后用本机模型 |
| 多设备 | 自动 | 自动 | 密文照常同步，每台设备输一次密码 |
| Face ID / Windows Hello | 能 | 能 | 桌面能：Windows Hello 保管本机密钥。iPhone 网页版能不能用 Face ID 派生密钥**未核实**，先只用密码 |

- **推荐 C 的做法**：密码 8 位以上，在设备上用 Argon2id 或 PBKDF2（60 万轮）派生密钥。第一次设密码时显示一串恢复码，让产品负责人抄下或打印。
- **密码错几次**：错 5 次后等 30 秒，之后每多错一次等待时间翻倍，只在本机计数。服务器上只有密文，没法暴力试密码，真正的防线是密码强度。
- **自动上锁**：切到后台立即上锁，或者 3 分钟不操作也上锁。
- **截屏和后台**：切到后台、在多任务界面里，隐私记内容要模糊。桌面版打开 Tauri 的内容保护，截屏和录屏都是黑的。iPhone 网页版挡不住截屏（平台限制）。
- 隐私记的内容、图片、标题都要加密。不推送，不写进运行日志。

## 3. AI 分类
- **发给谁**：Anthropic Claude API（Haiku 级，便宜）。按官方说法，API 内容不用于训练，30 天内删除（[来源](https://privacy.claude.com/en/articles/7996866-is-my-data-used-for-model-training)）。另有说法称已改为 7 天，**未核实**。
- **密钥放哪**：只放在 Supabase Edge Function 的环境变量里。exe 和网页都能被拆开看，所以前端绝不能放密钥。每个用户每天限制调用次数。
- **绝对不发**：隐私记（内容、标题、图片都不发），以及备注里的密码、卡号。
- **发什么**：只发随手记的文字，默认不发图片。
- **开关**：做。“AI 自动分类”默认开，能关；关掉后改为手动分类。设置页要写清楚“内容会发给 Anthropic（美国）”。
- **防提示注入**：AI 只能返回分类名，必须从固定清单里选，不能触发任何动作。

## 4. 图片
- **存哪**：Supabase Storage，用**私有桶**。路径按 `用户id/文件名` 存，桶也要配 RLS。
- **访问**：只用签名链接，有效期 10 分钟，不公开图片地址。
- **EXIF**：**必须去掉**，尤其是定位。做法是上传前在设备上重新编码，自然就把 EXIF 去掉了。
- **大小和格式**：原图最大 10 MB，压缩到长边 2048 像素、约 1 MB。只收 JPEG、PNG、HEIC（转成 JPEG），拒收 SVG。
- 隐私记的图片先在设备上加密，再上传。

## 5. 推送
继续脱敏。生日推送**默认不显示名字**，只写“今天有 1 位朋友生日”，设置里可以改成显示名字。名字会经过苹果的推送服务，还会留在锁屏和通知中心。iOS 的“显示预览”建议设为“解锁时”。隐私记永不推送。

## 6. 网页后台
**不做。** 个人使用，Supabase 控制台就够了。做后台会多出几个攻击面：一个高权限登录口、一把要放在服务端的 service_role 密钥、一套管理接口（还容易出越权漏洞）、一个新域名。

用控制台时注意：
- service_role 密钥不进代码、exe、截图和聊天，泄露了立刻更换；
- 每张表和存储桶都开 RLS，增、删、改、查四种操作都写策略；
- 上线前看一遍 Security Advisor，并用另一个测试账号确认读不到本人数据。

## 7. 桌面与手机
- **代码签名**：不签名的话 SmartScreen 会拦。自用可以先不签。要签的话，Azure Artifact Signing 便宜，但韩国个人能不能申请**未核实**，否则买 OV 证书。
- **更新包签名**：**必须做**。Tauri 更新器会用内置公钥校验更新包，不通过就不装。私钥离线保存并备份，丢了就再也发不了更新（[来源](https://v2.tauri.app/plugin/updater/)）。更新地址只用 HTTPS。
- **开机自启**：用当前用户级别的启动项，不要管理员权限。设置里可以关，启动时最小化。
- **本地缓存**：普通数据靠 Windows 登录密码和 BitLocker 保护。隐私记只缓存密文，解锁后的明文只放在内存里。退出登录时清空缓存。
- **丢设备**：用另一台设备点“退出所有设备”。iPhone 用“查找”远程抹掉。
- **iPhone 端**：如果上 App Store 并提供第三方登录，苹果要求同时提供 Apple 登录。

## 8. 合规（PIPA）
- **纯个人自用**：二手资料说个人或家庭用途可以豁免，具体条款**未核实**。注意两点：生日记里记的是别人的个人信息，自用问题不大；日程里如果记了客户信息，属于业务用途，要先确认公司政策。
- **给别人用以后**：就成了“个人信息处理者”。要准备隐私政策，取得同意，告知数据转移到国外（AI 调用会到美国），做加密和权限控制，发生泄露要通报，还要支持注销时删除数据。
- **首尔节点的意义**：数据存在韩国，速度快，以后的合规说明也更简单。但 AI 调用仍然算转移到国外。

## 9. 备份与迁移
- **迁移**：claude.ai 里没有隐私记，所以隐私记一出生就是加密的，这正合适。在新 App 里登录后导入 JSON，走正常权限，不用 service_role 密钥。核对条数后，删掉本机的明文 JSON，或者放进加密盘。claude.ai 版只读保留 30 天，然后删除。
- **新后端的备份**：隐私记在备份里只是密文。另外要备份每个用户的密钥参数（盐值、加密后的密钥），恢复码和备份分开放。每日快照要改成用本人的令牌读取，令牌存在 Windows 凭据管理器里。
- **Claude 代记**：用一把单独的、可以吊销的令牌，只允许新增随手记，不能读取。

## 10. 上线前必过清单
**P0（不过不上线）**
- 所有表和存储桶都开 RLS，并用第二个账号验证读不到数据；
- service_role 密钥和 AI 密钥不出服务端；
- 关闭注册，开两步验证；
- 隐私记加密实测：数据库里看到的是密文，恢复码能用；
- 更新包签名；
- 图片去掉 EXIF，图片桶私有；
- 推送脱敏；
- 迁移数据核对。

**P1**
- 内容安全策略（CSP）和只用 textContent 显示；
- 调用频率限制；
- 自动上锁和后台模糊；
- 退出时清空缓存；
- 自动备份。

**P2**
- 代码签名；
- Passkey；
- 登录告警。

## 需要产品负责人决定
1. **登录方式**：推荐邮箱验证码加 Apple 登录，这一版就做。
2. **隐私记方案**：推荐端到端加密。要接受“忘了密码又丢了恢复码，内容就找不回”。
3. **AI 服务**：推荐用 Claude API，默认开、可关，只发随手记的文字。
4. **生日推送显示名字**：推荐默认不显示。
5. **网页后台**：推荐不做。
6. **exe 代码签名**：推荐先不签，更新包签名必须做。
7. **自启动**：推荐默认开、可关。
8. **claude.ai 旧版**：推荐迁移后保留 30 天，然后删除。
