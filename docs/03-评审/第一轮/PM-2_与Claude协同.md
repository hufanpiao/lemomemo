# PM-2 与 Claude 协同

**判断**
页面已经能读写云端数据库，Claude 也能从聊天里写进来。缺的是两边对一条记录的共识：记录没有来源、没有项目、没有状态，Claude 读到的只是一堆标题。真正有用的是“一句话录入”和“统一字段”，这两件事能省掉每天的输入摩擦；“帮我排今天”“智能建议”在条目少、又不能推送的前提下，多半是噱头。

**建议（按优先级）**

1. **统一字段**
   - 价值：后面所有功能的地基。现有字段只有 title/date/time/note/due/important。建议补上 `source`（page/chat/quick）、`project`（如 NEOX、SignPlex）、`kind`（对片/交付/会议）、`durationMin`、`updatedAt`、`rawText`（用户原话）。
   - 成本：低，改两个 add() 加一处渲染。旧数据缺字段时按默认值处理。

2. **一句话快速添加**
   - 价值：最高频、最实在。输入“下周三两点和 NEOX 对片”，拆成日期、时间、标题、项目。拆完先显示一张可改的预览卡，确认后才写入，避免改错日期。
   - 成本：中。在页面里调用 Claude 需要把今天的日期和星期一起发过去，返回固定格式的 JSON。还要做一个本地正则兜底，覆盖“明天/周五/3点”这类简单说法，这样不用每次都调用 Claude，频率限制和首次授权也就不成问题。

3. **标出 Claude 从聊天加的条目**
   - 价值：中。条目旁加一个小“聊”字标记，点开能看到原话。用户能放心，误记也好追查。
   - 成本：很低，靠第 1 条的 `source` 和 `rawText`。

4. **按项目筛选、看截止节点**
   - 价值：中高。创意工作是按项目推进的，看“NEOX 还剩什么”比看“今天”更有用。
   - 成本：低，纯前端，不调用 Claude。

5. **“帮我排今天”**
   - 价值：低到中。只有在一天事情多、而且待办填了时长时才有意义，否则输出的只是常识。可以先做成按钮，结果作为建议显示，不自动改动数据。
   - 成本：中。等第 1 条字段稳定、数据积累够了再做。
