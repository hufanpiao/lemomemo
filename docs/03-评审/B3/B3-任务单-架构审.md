## 二、架构师定案

### Q2：B3 的 intent 怎么出 —— 定 (a)，加三条

照任务单 (a)：`parse.v1.md`、`voice.v1.md` 不让模型判断意图，`responseSchema` 里不放 intent；ai-parse、ai-voice 校验通过后在服务器上包成 `{intent: 'record', confidence, items, quota_left}`。理由：① 句库第 76 行写明 B3 不评 intent，让模型输出它等于加一个不评测的自由度，反而可能把记下句判偏；② 1.3 要的是“状态机留扩展点”，扩展点在结构和类型上，不在模型上；③ B4b-3 换 v2 提示词时本来就要全量重跑测试集 ①③，不多花一次评测。

另加三条：

1. `shared/schema/ai.ts` 的外层结构 B3 就按第 7 节 intent 那一层定，**运行时枚举只放 `record`**；B4b-3 放开枚举是改这一处。
2. **客户端遇到不认识的 intent 一律当 `ai_failed` 处理、退回本机规则、原话不丢**（不是“空实现”）。状态机的 `switch` 写成穷举、`default` 走退路，有单测。理由：B4b-3 上线后，还开着旧版页面的人可能拿到 `search`，版本门 426 有窗口期。

## 三、Q1 审查：R-68 探测函数的安全够不够

## 四、Q3 审查：“＋”加按住事件（R-352 ④ 已定）

### 可行性

可行，**而且可以做到 `GlassBar.module.css`、`GlassBarFx.*`、`src/motion/glass-*.ts`、`base.css` 一个字不改**：

- `GlassBar.tsx` 的“＋”是 `Pressable`，`Pressable` 已经把 `onPointerDown / Up / Leave / Cancel` 原样转出去（`src/motion/Pressable.tsx`）。`GlassBarProps.add` 只加可选的按住回调（建议一个对象 `hold?: { onStart, onMove, onEnd, onCancel }`），在 `GlassBar.tsx` 里转给 `Pressable`。不加 DOM 节点、不改 className、不加 `data-*`。
- 350 ms 判定、上拖取消和锁定的位置计算、计时都在 `src/features/plus/` 里做，状态放 ref，**按住和移动期间 GlassBar 不重新渲染**（不然会碰到液滴和果冻的布局副作用）。
- 现在 `.fab` 是 `touch-action: manipulation`，竖着拖可能被浏览器当成滚动、发 `pointercancel`，上拖取消和锁定会断。**不改 CSS 的做法**：按下时 `setPointerCapture`；在“＋”上挂非被动的 `touchmove` 监听，按住期间 `preventDefault()`；`contextmenu` 一律 `preventDefault()`。5.1 说的“350 ms 起禁系统长按菜单、文字选择和放大镜”在页面根上做（`src/features/plus/` 给 `<html>` 打标记，样式写在 plus 自己按需加载的 CSS 里，不碰 `base.css`）。
- **如果真机 P3-01 证明 iOS 必须在 `.fab` 上写 `touch-action: none` 或 `-webkit-touch-callout: none` 才行**：这两条不改像素，但属于改 `GlassBar.module.css`，超出 R-352 ④“只加事件”。那时停下来，主持人问负责人，不能先改。

## 七、首屏 150 KB 的影响

- 现状 149.8 KB（R-351），B2-UI-a 签字时目标 145～147 KB（`check_size.mjs` 口径：入口和它静态 import 的 chunk，gzip 后合计）。B3 能用的余量就是 3～5 KB，而且这是全部后续批次共用的。

- 每个合并前跑 `node build/check_size.mjs` 并贴数（任务单 Q4 已写），签字时在开发自测里写 B3 前后两个数。超了不放宽上限（R-351），先在 B3 里挪，挪不动报主持人。
