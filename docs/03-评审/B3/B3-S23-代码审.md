### plus-hint 订阅（重点）

- **不会重复计次。** `counted` 在同一个同步段里赋值，StrictMode 下 effect 跑两遍，或者 hashchange 和首次检查同时到，拿到的都是同一个 Promise，打开次数只加一次。读写出错时 `counted` 会清掉，这一次不扣次数。
- **订阅和取消订阅没有问题。**
  - `useSyncExternalStore(watchPlusHeld, plusHeldNow, …)`：传的是模块级的固定函数，不会每次渲染都重新订阅；返回的退订函数会把监听删掉。
  - `markPlusHeld` 只在第一次（`heldNow` 从 false 变 true）时通知一次，之后 `plusHintThisLaunch` 直接返回 false。不会形成环，也就不会死循环。
- **hashchange 监听不泄漏。**
  - 结果拿到（不是 null）就把监听摘掉；组件卸载时，cleanup 也会摘掉。
  - 只有本机库一直没准备好（一直停在登录页）时，监听会一直挂到组件卸载为止。这是有意的设计：登录以后换页，靠它再查一次。
  - 位置那个 effect 的 resize、hashchange、MutationObserver 和计时器，在 cleanup 里都会清掉。
- **按住以后当场收起。** `held` 一变成 true，就返回 null，位置那个 effect 也跟着停掉。

### R-367 按设备分两套文案

- **首帧就是对的那一句，不会先出错的再跳。** `isAppleMobile()` 是同步读 UA 和 maxTouchPoints，第一次渲染就能拿到结果，所以首帧就是正确的文案。iPadOS 用桌面 UA（Macintosh 加触点数大于 1）时，也认成 Apple 移动设备。本项目没有 SSR，不存在服务端渲染和客户端渲染文案不一致的问题。
- **exe 照旧不显示。** `useMicDenied` 在 exe 里一律返回 false，所以今天页那一行不画；MicCard 在 exe 里由调用方不挂（R-90），这一点没变。

### 建议（不挡合并）

- R1 `usePlusHint.ts` 的 check：读写出错时，`plusHintThisLaunch` 返回 false，hook 就把 hashchange 监听摘掉了，这次启动不会再查。这和 plus-hint.ts 注释里写的“出错不记结果，下次再查”对不上。好在次数没扣，下次打开 App 时照常会出，影响很小。建议改注释，或者出错时返回 null，让 hook 换页时再查。
- R2 `useAppleMobile` 写了两份：`plus/hooks/useAppleMobile.ts` 一份，`today/hooks/useMicDenied.ts` 里又一份。两个功能之间不能互相 import，所以分开写是合理的；但它只是包了一层同步函数，两处都可以直接调 `isAppleMobile()`，省掉这层包装。
