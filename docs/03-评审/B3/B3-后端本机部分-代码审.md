## 必改项

### M1　跨午夜的时刻：日子记错，而且判成“有把握”

| 原话（说话时刻） | 现在的结果 | 应该是 |
|---|---|---|
| 今晚1点吃药（10:00） | 日程 10-28 **13:00**，有把握 | 10-29 01:00（或者判没把握） |
| 晚上1点睡觉（10:00） | 10-28 **13:00**，有把握 | 同上 |
| 凌晨1点吃药（**23:30**） | 10-28 **01:00**（22.5 小时以前），有把握 | 10-29 01:00（或者判没把握） |

原因：`time-words.ts` 的 `applyPeriod` 里，“晚上”只在 12 点时算次日，1～5 点按 `EVENING` 加 12；“凌晨 / 새벽”没说日子时一律记今天，不看现在几点。韩文“밤 1시”已经正确（`NIGHT` 会算次日），中文“今晚 / 晚上 + 1～5 点”和“没说日子的凌晨”这两种还不对。改完以后在 `parse-split.test.ts` 里用 23:xx 的时钟加回归测试（中文、韩文各几句）。

### M2　跨午夜的起止：时长丢了，存成默认 60 分钟

“晚上11点到凌晨1点值班”“밤 11시부터 새벽 1시까지 야간 근무”：开始 23:00 是对的，`duration_min` 却是 null（保存时落成默认 60 分钟），而且判有把握。原因：`takeTime` 的起止分支里，结束时刻早于开始、而结束写了时段词时不再重试，`dur` 直接给 null。应该按跨到次日算（120 分钟），补上中韩各一条测试。

### M3　句子里还剩一个日期、时刻或星期时照样判“有把握”，星期的数字还漏进了标题

| 原话 | 现在的结果（全部判有把握） |
|---|---|
| 下周一到周三出差 | 待办“到**周3**出差”11-02 |
| 周五下午到周日去釜山 | 待办“到**周7**去釜山”10-30 |
| 明天10点和周五3点开会 | 日程“和**周53点**开会”10-29 10:00 |
| 明天上午10点开会和下午3点去银行 | 日程“开会和 **3点**去银行”10-29 10:00 |
| 下周三、周四出差 | 只剩一条“出差”**10-29**，“下周三”那件没了 |

原因有三个：
1. `text.ts` 的 `protectWeekdays` 把“周一”改成“周1”，没被取走的那部分不会换回汉字，于是“周3”进了标题；
2. `confidence` 只看 `doubts`，不看标题里还有没有剩下的日期、时刻、星期；
3. `split.ts` 文件头写着“只有日子或时刻、没有事由的段由调用方并进下一段”，`parseSplit` 实际是把这种段丢掉（只把日子带给下一段），所以“下周三、周四”第一段的日子被第二段自己的“周四”覆盖了。

改法建议：标题收尾时把 `周[1-7]` 换回汉字；标题里还剩“数字 + 点 / 시 / 号 / 日 / 월”或者 `周[1-7]` 的，加一个没把握的原因（例如 `leftover`）；照文件头的说法把只有日子的段并进下一段，或者把文件头改成实际做法，并判没把握。上面 5 句都要进测试。TC-B3-17 的线是“有把握却错了全库最多 2 句”，这几类都是日常很常见的说法。

### M4　测试：几组是重复的，只测了桩，没测到真正的行为

- `tests/edge/ai-parse.test.ts` 里 ai-parse、ai-voice 各有两条 TC-B1-10，`tests/edge/claude-intake.test.ts` 里 token-admin 也有两条 TC-B1-10，每对的“管理员停用”和“没有 profiles 行”**测试体一模一样**：都是注入一个直接回 403 的 `authenticate` 桩，测的只是“桩回什么就原样转发”，`requireActiveUser` 碰不到“没有 profiles 行”的情况。claude-intake 的两条 TC-B1-109（停用、冷静期）同样一模一样，都是 `usable: false`。
- 要么删掉重复的那条，把剩下那条的名字改成“鉴权失败原样转发”；要么注入真的 `requireActiveUser` / `isUsable`，配一个假的 admin（profiles 行不存在、`disabled_at` 有值、`disabled_reason = deletion` 各造一份），让测试真的走到判断逻辑里。

## 建议（不卡这一轮，下一轮复审时看）

1. **重复说法把同一段里的日子吃掉了**：“从下周一开始每天跑步”“明天交报告 每天跑步”都记成今天。原因是 `parseClause` 认出 `takeRecur` 以后就不再取日期，“下周1”“明天”留在标题里。这两句会判没把握、在线时交给 AI，但离线、没同意 AI 或额度用完时存的是本机结果，日子是错的。
2. **注释和行为对不上**：`parse-split.ts` 第 148 行写的是“韩文的留着（M28‘和老李 점심’的점심是事由）”，现在实际结果是“和老李”，점심被去掉了；M28 也没有测试。后端正在改这一块，改完请把注释、`time-words.ts` 文件头和测试统一。
3. **claude-intake 写库不是原子的**：events、todos、anniversaries 分三次 insert，前一张表写成功、后一张失败时回 503，Claude 重试会写出重复的条目；每天 200 条的计数在写库之前就扣了，失败也不退。可以改成一个 RPC 一次写完，或者在 503 里带回已经写进去的 id。
4. **claude-intake 的回包没有提示**：没有 `recur`（R-163“只记了最近一次”）和 `arrange`（R-200“具体时间请自己排”）。聊天这一路也应该把这两条带回给 Claude。
5. **AI 给了空列表**：`{items: []}` 校验通过后被包成 `record`，条目为空。建议当 invalid 处理、退回本机规则，保证原话不丢。
6. **X-Projects 超过 4 KB**：服务器把 base64 截到 4096 字符以后 JSON 解不开，结果是**全部丢掉**，和任务单写的“超了截断”不一样，测试（`decodeProjects(... 'x'.repeat(4096))` 得到 `[]`）还把这个行为固定了下来。要么按项截断，要么在任务单和架构第 6 节里改成“超了忽略，截断由客户端做”。
7. **ai-parse 读请求体**：`readJson` 在没有 Content-Length 时把整段读完才比长度，而且拿 UTF-16 长度和字节上限比。可以直接用 ai-voice 的 `readCapped`。
8. **常量重复写了一份**：`parse-core.ts` 的 `TEXT_MAX / PROJECTS_MAX / PROJECT_LEN`、`AiKindLike`、`InvalidReasonLike` 和 `shared/schema/ai.ts` 各写了一份（为了不 import gen，这个做法可以理解）。建议加一条单测核对两边的值相等，防止以后改了一边忘了另一边。
9. **提示词文件的扩展名**：现在是 `prompts/parse.v1.ts`、`voice.v1.ts`，任务单写的是 `.md`。照现在的写法没问题，在任务单或架构里把口径改一下就行。
10. **add.ps1 的测试只做了静态正则检查**，没有用假的连接码对本机 `127.0.0.1:884x` 的假服务端真跑一遍（团队规则“交付脚本先跑通”）。
11. **今天已经过去的时刻**：15:00 说“11点开会”、周三 14:00 说“周三下午1点开会”，都记成今天、已经过去的时刻，还判有把握。产品口径没写到这种情况，建议至少加一个没把握的原因，或者请架构师定一下。
12. **gen 副本过期**：`supabase/functions/_shared/gen/logic/parse/time-words.ts` 比 `shared/` 旧（gen 不进 git，是构建产物）。本地 `deno check` 和部署之前要先重跑 `build/copy_shared.mjs`。
