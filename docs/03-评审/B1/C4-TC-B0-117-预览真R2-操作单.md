## 第 4 步：注入 7 天并立即跑一次 account-purge（负责人，SQL Editor）

**整段全选再执行**：粘贴后按 Ctrl+A 全选再点 Run，不要只选一部分。

这一段分两句：前面的 DO 块做检查和注入，后面那句发请求。**发请求那句不依赖 SQL Editor 是不是把整段放在一个事务里**（安全审查 R1）：
- 它只在“A 那一行的 `purge_after` 刚被挪到过去（5 分钟以内）、没被认领、`pending_deletions` 只有这一行、Vault 是预览地址”时才选出 1 行、发 1 次请求；

- 两处邮箱都写成字面量，不用 `set_config` 传值（逐句提交时传不过去）。

```sql
-- C4 第 4 步：注入 7 天并立即触发一次 account-purge。<A_EMAIL> 有 2 处（DO 块开头、最后那句的 where），都要换
do $c4$
declare
  a_email constant text := '<A_EMAIL>';
  b_email constant text := 'hufanp+lemotest@gmail.com';
  a uuid;
  b uuid;
  n int;
begin
  -- ① 占位符必须已换掉
  if a_email like '<%' then
    raise exception 'lemo C4: A 的邮箱还是占位符 <A_EMAIL>，整段已拒绝执行';
  end if;
  if a_email = b_email then
    raise exception 'lemo C4: A 和 B 是同一个邮箱，整段已拒绝执行';
  end if;

  -- ② 只有预览库能跑：Vault 里的 functions_url 必须是预览项目 ref 拼出来的地址（tools/keys/set-cron-secret.ps1 写的格式）
  if coalesce((select decrypted_secret from vault.decrypted_secrets where name = 'functions_url'), '')
       <> 'https://yoeqwhygehbaftkppati.supabase.co/functions/v1' then
    raise exception 'lemo C4: 不是预览库（functions_url 不是 yoeqwhygehbaftkppati），整段已拒绝执行';
  end if;
  if not exists (select 1 from vault.decrypted_secrets where name = 'cron_secret') then
    raise exception 'lemo C4: Vault 里没有 cron_secret，触发不了 account-purge，整段已拒绝执行';
  end if;
  -- ②b 只能在几乎没有用户的库上跑：预览现在 2 个账号，加上 A 是 3 个（安全审查 R5）
  if (select count(*) from auth.users) > 3 then
    raise exception 'lemo C4: 账号数超过 3（现在 % 个），不像预览库，整段已拒绝执行', (select count(*) from auth.users);
  end if;

  -- ③ heartbeat 有记录：account-purge 的定时任务真跑过（Vault 两条和函数侧的 CRON_SECRET 是对上的）
  if not exists (select 1 from private.heartbeat where name = 'account-purge') then
    raise exception 'lemo C4: private.heartbeat 里没有 account-purge 的记录（定时任务从没跑通过），整段已拒绝执行';
  end if;

  -- ④ A、B 都在，各只有一个
  select id into a from auth.users where email = a_email;
  select id into b from auth.users where email = b_email;
  if a is null then raise exception 'lemo C4: 找不到 A（%）', a_email; end if;
  if b is null then raise exception 'lemo C4: 找不到 B（%）', b_email; end if;

  -- ⑤ pending_deletions 只有 A 这一行：account-purge 会处理所有到期的行，不能顺带删掉别人
  if (select count(*) from private.pending_deletions) <> 1
     or not exists (select 1 from private.pending_deletions where user_id = a) then
    raise exception 'lemo C4: private.pending_deletions 不是只有 A 这一行（现在 % 行），整段已拒绝执行',
      (select count(*) from private.pending_deletions);
  end if;

  -- ⑥ A 确实是自己申请的注销（profile 停用、原因是 deletion），A、B 都不是管理员，B 没在注销
  if not exists (select 1 from public.profiles where user_id = a and disabled_at is not null and disabled_reason = 'deletion') then
    raise exception 'lemo C4: A 的 profile 不是“申请注销”状态（第 3 步没做成？），整段已拒绝执行';
  end if;
  if exists (select 1 from private.admins where user_id in (a, b)) then
    raise exception 'lemo C4: A 或 B 是管理员，整段已拒绝执行';
  end if;
  if exists (select 1 from public.profiles where user_id = b and disabled_at is not null) then
    raise exception 'lemo C4: B 已被停用，对照不成立，整段已拒绝执行';
  end if;

  -- 注入满 7 天：把 A 的删除时刻挪到 1 分钟以前；清掉认领（account-purge 选“到期且没被认领”的行）
  update private.pending_deletions
     set purge_after = now() - interval '1 minute', purge_started_at = null
   where user_id = a;
  get diagnostics n = row_count;
  if n <> 1 then raise exception 'lemo C4: 注入改到了 % 行（应为 1），整段已拒绝执行', n; end if;
end
$c4$;

-- 触发：net.http_post 的参数和定时任务（迁移 20261029171000 第 13～18 行）一样，原样照抄；
-- 只有注入刚生效时才选出 1 行、发 1 次（R1）。<A_EMAIL> 在 where 里，第 2 处
select net.http_post(
      url := (select decrypted_secret from vault.decrypted_secrets where name = 'functions_url') || '/account-purge',
      headers := jsonb_build_object('content-type', 'application/json', 'x-region', 'ap-northeast-2',
                   'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'cron_secret')),
      body := '{}'::jsonb, timeout_milliseconds := 5000) as request_id,
       u.id  as a_id,
       now() as 触发时刻
  from auth.users u
  join private.pending_deletions p on p.user_id = u.id
 where u.email = '<A_EMAIL>'
   and p.purge_after < now()                              -- 注入生效了（原来是 7 天以后）
   and p.purge_after > now() - interval '5 minutes'       -- 而且是刚注入的（不吃以前某次留下的注入）
   and p.purge_started_at is null                         -- 没被认领
   and (select count(*) from private.pending_deletions) = 1
   and (select decrypted_secret from vault.decrypted_secrets where name = 'functions_url')
         = 'https://yoeqwhygehbaftkppati.supabase.co/functions/v1';
```

执行成功会返回**一行**：`request_id`（一个数字）、`a_id`、`触发时刻`。**三样都记下来**，第 5 步要用：A 被删以后就不能再按邮箱查到 id 了；`触发时刻` 用来判断心跳是不是这一次写的。

- 报错、错误文字以 `lemo C4:` 开头：上面某道检查没过，注入没生效、没发请求。照文字处理或找主持人。
- 没报错但**返回 0 行**：没发请求（注入没生效，或者不满足最后那句的条件）。先看最后那句的 `'<A_EMAIL>'` 是不是漏换了：漏换的话换好以后**整段**重跑一次就行（DO 块会重新注入，检查照样全跑）。不是这个原因就不要改条件硬发，找主持人。注意：DO 块成功、最后那句没发时，A 已经是“到期”状态，就算什么都不做，当天 18:30 UTC 的定时任务也会删掉 A。
- 返回了不止一行：不可能（A 的邮箱、`pending_deletions` 的主键都是唯一的）；真出现就截图，找后端。
- 排查时**不要** `select * from net.http_request_queue`：请求头里有 `cron_secret`，会显示在屏幕上、进截图（R6）。要看结果只查 5.1 的 `net._http_response`（只有响应，没有请求头）。

## 第 5 步：核对（负责人 + 主持人）

**以心跳时刻为准，不按“等多少秒”**（安全审查 R2）。account-purge 是把所有到期账号处理完以后才写心跳（`core.ts` 第 290～299 行），所以“心跳时刻晚于第 4 步的 `触发时刻`”才说明这一次完整跑完了。触发那句的 `timeout_milliseconds := 5000` 是照定时任务原样抄的：函数跑得超过 5 秒时 pg_net 会记“超时”，但超时以后函数会不会被掐断没实测过，所以响应只作参考，`timed_out = true` 本身不算失败。

### 5.0 等心跳（每 30 秒跑一次，最多 3 分钟）

```sql
-- C4 第 5.0 步：等心跳（只读）。<触发时刻> 换成第 4 步返回的值（原样带时区）
select at, at > '<触发时刻>'::timestamptz as 是这一次的, detail
  from private.heartbeat where name = 'account-purge';
```

- 每 30 秒跑一次，**直到 `是这一次的 = true`**，最多等 3 分钟（函数墙钟上限 150 秒）。
- `是这一次的 = true` 以后看 `detail`：**通过的判据是 `purged = 1`、`failed = 0`**。第 4 步第 ⑤ 道保证这次只可能处理 A，所以 `purged = 1` 就是 A。然后做 5.1、5.2。
- 顺带记下 `detail` 里的 `ms`：`ms` 大于 5000 而且 `purged = 1`，就证明了“pg_net 超时以后函数照样跑完”，写进结果。
- **3 分钟后还是 `false`：不要再触发**，跳到 5.3 的最后一条。

### 5.3 没通过时

- 响应或心跳 `failed = 1`、日志里有 `r2_not_empty`：真 R2 上删了以后再列不为 0。A 的认领已释放，`pending_deletions` 那一行还在。**不要再触发**，截图日志，找后端。这就是 P0 不通过。
