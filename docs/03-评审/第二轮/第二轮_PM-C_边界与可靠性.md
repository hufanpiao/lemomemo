# 第二轮 · 独立 PM-C 边界与可靠性（代码审查，未实际运行）

**高**
1. **字段不规范会让整页崩溃，或被悄悄当成错的值**（onSnapshot 直接用 d.data()）：
   - project 是数字时，projVar 里的 toLowerCase 会抛错，整个 render 停掉；
   - 没有 title 时，scheduleDelete 里的 `item.title.length` 会抛错：没有撤销提示，5 秒后照样删掉；
   - done 或 important 写成字符串 "false" 时会被当成“是”；
   - due 写成 "2026-9-5" 这种格式时，字符串比较会把顺序弄错。
   - 修：快照进来时统一做一次 normalize（日期、时间补零，布尔和数字转对类型）。
2. **编辑后保存会悄悄改掉数据**（openSheet 加上 submit）：
   - durationMin=45 不在下拉选项里，保存后变成 60；
   - time 是 "9:00" 时时间框认不出，保存后变成全天；
   - submit 会发送全部字段，把另一台设备期间的修改覆盖掉。
   - 修：只 update 改过的字段；选项里没有的时长动态加进去。
3. **删除后撤销靠不住**（flushDeletes、scheduleDelete）：
   - 一切到后台就立即删除，但撤销提示还在；这时点撤销，界面会恢复，等云端删完条目又消失；
   - 连续删两条时，提示被覆盖，第一条没法撤销。
   - 修：已经提交的删除，撤销时用原数据重新 set 回去；待撤销的项排成队列。
4. **parseQuick 会解析错的说法**：
   - “周五十点开会”：五十被当成 50，结果是周五 00:00；
   - “下午三点二十”：结果是 15:00，标题变成“二十…”；
   - “明天3点对片”：结果是 03:00；
   - “今晚12点”：结果是中午 12:00；
   - “第3-5集”、“预算3.5万”：被当成 3 月 5 日；
   - “6点前交稿”：被记成日程，不是带截止的待办；
   - “下个月5号”：结果是本月 5 号；
   - “3号楼开会”：被当成 3 号这个日期。
   - 修：中文数字只在明确的时间格式里转换；1–6 点没写时段时提示确认；日期分隔符两侧要排除小数。

**中**
5. **跨天**：selDay 和 weekStart 只在打开时设一次，过了午夜还选中昨天；手机切回前台不会重绘。修：在 visibilitychange 时检测日期变化，并 render。
6. **时间轴**（renderTimeline）：
   - 23:00 开始、2 小时的日程，色块会溢出到下面的面板；
   - 跨夜日程第二天不显示，nextThing 也认不出昨晚还在进行的事；
   - 重叠 5 项以上时每列太窄，没法读；
   - time 是 "9:00" 时排序错，分列也跟着错。
   - 修：裁到当天并标“次日”，超过 3 列折叠成“+N”。
7. **键盘焦点丢失**：每次快照和每分钟的 render 都重建全部 DOM，焦点掉到 body；关弹层时要还原的元素也已经不在了。修：按 data-id 恢复焦点。
8. **页面跳回顶部**：每次 resize 都执行 go()，里面有 scrollTo(0)；手机地址栏收起时会触发 resize。是否真会触发要看嵌在 claude.ai 里的表现。修：resize 时只调 placeInd。
9. **写入失败的提示不对**：离线时按钮可能一直停在“保存中…”；条目已在另一台设备上被删时，update 失败却提示“检查网络”。

**低**
10. **无障碍**：
    - 弹层没有焦点陷阱；
    - 屏宽小于 380px 时导航按钮没有名字（文字被隐藏，又没有 aria-label）；
    - “下一件事”卡片的标题不能用键盘打开；
    - 撤销提示 3–5 秒就消失，键盘和读屏用户来不及点。
11. **其他**：
    - 全天胶囊 .ad 遇到很长的标题可能横向溢出；
    - 项目匹配用 indexOf，“UI”这种短项目名会误命中；
    - “不重要”会被标成重要。
