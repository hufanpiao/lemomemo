## 二、新增内容的问题

### 严重
无。

### 中

**M1　隐私记页面里按"＋"怎么做，5.14 没写，而且和现有规则冲突**
- **证据**：
  - 5.14 第 3、4 点只写了隐私记页面"只查隐私记""能总结（另查 ai.vault）"；
  - 在隐私记页面里按"＋"**记下**、**判断意图**、**存草稿**这三件事都没写；
  - 规则那边：A18 不准 `features/vault/data` 碰本机缓存、队列和日志；A1 / A27 规定 plus 只能 import vault 的 `index.ts`，而 `index.ts` 只能导出懒加载页面、设置分区、今天页卡片和类型。
- **为什么**：
  - **意图判断**：本机规则没把握时会调 ai-parse 或 ai-voice。在隐私记页面里，这等于把隐私记的明文送给谷歌；而 ai-parse、ai-voice 现在不知道自己处在隐私记的场景，不会去查 `ai.vault`。
  - **记下**：隐私记只能经 vault 函数写入，不能进 outbox，所以离线时没法记，现在也没写离线怎么办。
  - **草稿**："改成记下"之前原话会存进草稿，如果草稿写进 IndexedDB，就违反了"隐私记明文不进本机缓存"。
  - **代码边界**：plus 要在隐私记页面里记下、查找、总结，就必须调 vault 的能力，但按 A27，vault 的 `index.ts` 不能导出这类函数。
- **建议**：
  - 5.14 加一节"隐私记页面里的＋"：
    - ai-parse、ai-voice 加 `scope: vault` 参数，服务器另查 `ai.vault`，不满足就只用本机规则；
    - 记下走 vault 函数，离线时提示"隐私记需要联网才能记"，原话只留在内存里；
    - 草稿只在内存里，上锁就清掉。
  - A27 加一个受控例外：vault 的 `index.ts` 可以导出一个 `plusAdapter`（record / search / summarize 三个函数，懒加载），或者在 core 里定义"＋ 的场景接口"，由 vault 注册实现；加一条违规样例。

**M2　判断成"查找"时不保存，原话只在内存里，iPhone 上可能丢**
- **证据**：5.14 第 2 点写"原话在卡片关闭前一直留在内存里，关闭后存进草稿"。
- **为什么**：R-116 要求绝不丢记录。iPhone 主屏幕模式的 App 切到后台后随时可能被系统杀掉；如果这时卡片还开着，原话就没了。D-15 的"本该记下却被判成查找为 0 条"只管测试集，保证不了实际使用。
- **建议**：判断为查找或总结时，**立刻**把原话（语音则是转写）写进本机草稿（普通页面写 IndexedDB 的 drafts store；隐私记页面按 M1 只留内存）；用户点"改成记下"或者草稿过期（例如 24 小时）时再清掉。界面不用改。

**M3　按 A27，"＋"的结果卡片没法复用各功能的条目组件**
- **证据**：
  - 5.14 第 3 点：结果卡片"按类型分组，每条能点开"，要显示日程、待办、随手记、附件缩略图；
  - A1 / A27（:829、:841）：功能之间只能 import 对方的 `index.ts`，而 `index.ts` 不能导出组件。
- **为什么**：plus 要画别的功能的条目行，只有两条路，一是自己再写一份，二是违反 A27。今天页的小卡片已经有专门的登记机制，结果卡片却没有对应的机制。开发时一定会碰到这个问题，然后各自绕开。
- **建议**：
  - 在 A27 的允许列表里加"结果行渲染器登记"：每个功能在 `index.ts` 里登记 `resultRenderer: React.lazy(...)`，plus 按 kind 取用；
  - 或者把只读的条目行组件（EventRow、TodoRow、NoteCard）放进 kit；
  - 二选一写进 2.1，并在 `tests/arch-fixtures/` 里放样例。

**M4　关键路径几乎全在前端 A 一人身上；B3、B4 的部分工作会被 B4b-3 推翻**
- **证据**：1.3（:654-679）主线 B1 → … → B4b-3 → B6 全部串行，都由前端 A 负责。
- **为什么**：
  - 106 人日的合计和 82 开发、21 返工、3 韩文的拆分，我核算无误，按批的估计也基本合理。
  - 但前端 A 这条线上的开发日是 B0 的一部分 + 7+10+5+5+8+11+6+9+3+3 ≈ 77 天，加上 25% 返工约 **95 天以上**。所以"日历时间短于 106 天"实际只短一点，前端 B 和后端并行能缩短的时间很有限。
  - 另外，R-116 取代了 B3 的"点一下打字、按住录音"状态机，也取代了 B4 的随手记查找框。按现在的顺序，这两块先做好，到 B4b-3 再改写，会有返工。
- **建议**（都不改负责人定的批次顺序）：
  - B3 起录音状态机就留出 `intent` 扩展点；B4 的查找逻辑写在 `shared/logic/search.ts` 和 core 里，不做页面搜索框的界面，这两部分界面直接等 B4b-3；
  - 1.3 的工期说明里写一句"日历时间约 95～100 天，关键路径在前端 A"，让负责人知道实际的上线时间；
  - 可以把 B6 里不依赖 App 主体的部分（例如对比度检查脚本、皮肤变量）交给前端 B 提前做。

### 轻

- **L1　迁移拆分后，函数的引用顺序要写明。**
  - `0001_core.sql` 的 settings 触发器 `enqueue_anniv_defaults()` 引用的 anniversaries 表要到 `0005` 才建。plpgsql 函数运行时才解析表名，没问题；但如果写成 `language sql`，创建时就会报错。
  - 建议写明这类函数一律用 plpgsql，或者把这个触发器挪进 `0005_anniv.sql`。
  - 另外，"授权白名单在 3.3 C 和附录 A 一字不差"现在分散在 7 个文件里，CI 比对时要先汇总。
- **L2　ai-summarize 按 id 由服务器取内容，没同步上的条目会漏掉。** 时间类的列表来自本机缓存，可能包含还在 outbox 里的新条目，服务器按 id 查不到，`cited` 就会缺。建议调用前先把 outbox 发完，或者服务器对查不到的 id 返回 `missing[]`，界面注明"N 条还没同步，没算进总结"。
- **L3　"模糊时先保存再给查找结果"会查到刚保存的那条。** 建议查找时排除这一批的 batch_id。
- **L4　时间类查找规则补两句。** 日程按 4.6 换算到设备当前时区后的日期列出；"没有截止日期的待办不列"在结果卡片的"理解成：…"那一行写明，免得用户以为漏了。
- **L5　直连数据库绕过了 RLS。** 6.2 要求所有直连 SQL 都按 JWT 里的 user_id 过滤，但只靠人遵守。建议加一条函数测试："用 A 的 JWT 调这 8 个函数，传入 B 的 id，一律查不到"。另外，经 Supavisor 事务模式连接时，postgres.js 要关掉预编译语句（`prepare: false`），否则可能报错，**需在 B0 核实**。
- **L6　vault-preview 的几个小改进。**
  - ms_preview 先在 `private.vault_preview` 登记，再写对象，这样中途崩溃时，sweep 一定能按登记删掉明文，不必依赖"未登记且超过 2 分钟"这条兜底；
  - pg_cron 每分钟先用 SQL 判断有没有待清理的登记，有才调函数。这样可以省下每月约 4 万次函数调用，现在总量还在 50 万的免费额度内，只是没必要；
  - 第 16 项（删对象后签名链接还能不能取到）的结论出来前，安全签字条件已经写了，这样可以。
- **L7　B0 行有残留措辞。** B0 行还写"合计约半天，含在 9 人日里"，B0 现在是 10 人日（:663）。
- **L8　纪念日头像的路径要进约束。** `<user>/anniv/<id>/<avatar_id>.webp` 进 images 桶，但 images 桶的 insert 策略原来按 note_images 的路径设计。建议在 3.3 的存储策略和 D1 的 `pathPrefix` 里写明 anniv 这一段路径的正则，不能只靠前缀判断。
