## 二、新问题（按严重程度排序）

### 严重

**N1 服务器端不执行 AI 同意：朋友不勾，随手记和隐私记照样会发给谷歌**
- **证据**
  - 5.2 的 ai-classify（第 806–809 行）只按 `ai_status=pending` 取数据，再查额度，**没有检查**这个用户的 `ai.enabled`、`ai.vault` 或 `consent_ai_at`。
  - notes 表的 `ai_status` 默认就是 `'pending'`。
  - 15.5（第 1572 行）写"不勾：`ai.enabled = false`"，但这只是客户端可以改的一条设置。
  - `consent_ai_at` 由谁写仍然没定：不在客户端可更新的列里（第 585 行），public 也"只有四个 RPC"（第 635 行）。这是上一轮复核就留下的问题。
- **后果**：朋友没同意，或者关了"隐私记交给 AI"，cron 照样把文字和解密后的隐私记送给 Gemini。这直接违背告知和同意，在 PIPA、PIPL 下都站不住。
- **改法**
  - ai-classify、ai-parse、ai-voice、claude-intake 走 AI 之前，一律在服务器上检查：`consent_ai_at` 不为空，`ai.enabled` 为 true；隐私记另外检查 `ai.vault`。不满足就当作本地规则处理。
  - 新增 RPC `record_consent(policy_ver)`（security definer，只写本人那一行），加进白名单和第 3.3 节 D 的 RPC 清单。
  - 补测试：没同意的账号，cron 一条都不送。
  - 这些都不改变 R-82 的默认值。

### 中

**N2 告知页没有"同意"的选择，也缺"人工审阅"这句话**
- **证据**：视觉稿第 1144–1150 行只有一个"知道了，继续"按钮，没有勾选框，也没有"不同意"的路径；文案里没有"可能经人工审阅"。架构 15.5 要求有勾选框和这句话。另外，勾选框是否预先勾选还在等负责人确认（第 200 行）。
- **改法**：照 15.5 补上勾选框（不预先勾选）、"不同意也能用"的路径和"人工审阅"这句话。勾选与否是否计入 PIPA 的"单独同意"，由负责人确认后定稿。

**N3 exe 直接加载远程 `/app/`：网站一旦出问题，就等于电脑本机被攻破**
- **证据**
  - 第 1028 行：`remote.urls: ["https://lemomemo.com/app/*"]`，给远程页面开放了"自启、托盘、热键、通知、**更新、凭据存储**"这些命令。
  - 凭据管理器里同时存着 BACKUP_PULL_TOKEN、S3 密钥、Claude 连接码（第 1299 行），能拿到所有人的备份。
  - 第 1239 行说"`tauri.conf.json` 的 CSP 照抄作兜底"。但 Tauri 的 CSP 只对它自己打包的本地页面生效，对远程页面不起作用，这个兜底实际不存在（需核实，我这次没查 Tauri 文档）。
- **后果**：网页出现 XSS、npm 依赖被投毒、Cloudflare Pages 被人改了内容，任何一种都会直接拿到 exe 的本机能力。如果凭据存储命令是通用的"按名字读写"，还能读走全站备份令牌。
- **改法**
  - Rust 端的 secureStorage 只能读写一个固定前缀（例如 `lemomemo.session.*`）的条目，不接受调用方传入名字。
  - 备份和 S3 的凭据改用 pull.ps1 专用的另一个前缀，或者放在另一个 Windows 用户下。
  - 更新检查和安装由 Rust 端自己做，不把 updater 命令开放给页面 JS。
  - 架构里删掉"CSP 兜底"这句，承认 exe 的安全头完全依赖网页的 `_headers`。
  - B6 加一条验收：远程页面调不到凭据前缀以外的任何条目。

**N4 npm 依赖供应链只靠锁文件，没有审计**
- **证据**：第 381 行只写了"`package-lock.json` 进仓库、锁精确版本、CI 用 `npm ci`，靠锁文件和代码审查守住"。CI 流程（第 1274–1277 行）里没有依赖审计、没有自动升级的评审流程、没有限制安装脚本。函数用 `npm:zod@版本`（第 484 行），没提 deno.lock。
- **后果**：React、Vite、Radix、motion 带进来几百个间接依赖，`postinstall` 脚本会在有部署密钥的 CI 任务里执行。投毒的包进了前端产物，还会连带 exe（N3）。
- **改法**
  - unit.yml 加 `npm audit --audit-level=high`（或 OSV-Scanner）。
  - 用 Dependabot 或 Renovate，按批升级，每批要人评审。
  - `npm ci --ignore-scripts`，确实需要安装脚本的包单独列白名单。
  - 构建和部署拆成两个任务：构建任务拿不到任何部署密钥，只把产物交给部署任务。
  - 函数提交 `deno.lock`，部署时加 `--frozen`。
  - 新增依赖要在 PR 里写明理由。

**N5 两个 Supabase 组织需要两个用户账号**
- **证据**：第 1288 行，以及账号注册清单第 2 节。
- **改法**：预览组织用第二个 Supabase 账号（另一个邮箱别名），并写进账号注册清单。或者先核实 Supabase 能否发只限单个项目的令牌，再决定。

### 轻

- **N6 Turnstile 脚本加载在 App 页面里**：`script-src https://challenges.cloudflare.com`（第 1232 行）作用于整个 `/app/`。第三方脚本和登录令牌在同一个来源下。建议把登录和注册做成单独的页面（例如 `/app/auth/`，带自己的 CSP），主 App 的 CSP 不放行 Cloudflare 的脚本。
- **N7 视觉稿与 5.6 不一致**：第 990 行的"✓ 邀请码有效"、第 989 行的"这个邮箱还没注册"，都和"start 一律返回 {ok}、不泄露信息"冲突。按 5.6 改视觉稿。邮箱枚举可以接受，但要写明这是有意接受的。
- **N8 invite-signup 第 ③ 步的顺序**：先占用邀请码，再 `createUser`，两步不在同一个事务里（第 950–955 行）。要写清两件事：`createUser` 失败时退回邀请码；`generateLink` 只对刚建出来的用户调用，邮箱已存在时直接报错。
- **N9 zod 校验覆盖不到客户端直接写库**：客户端直接写 REST 时不经过 zod，只靠数据库约束。logs 表的 device、kind、act、src、code 这些文本列没有长度上限（附录 logs 表），row_quota 只限条数、不限大小。建议给这几列加上长度检查。另外，React 的 JSX 里，凡是 `href` 都应只接受 safeHref 的返回值，建议加一条自定义 ESLint 规则。
- **N10 15.7 的法务口径**：Gemini 从"委托"改为"向第三方提供"；补上敏感信息（定位）、影响评估（PIPL 第 55 条）、泄露通知、必填和选填分开、锁屏显示标题（即上面的 M9 和轻 10）。
- **N11 待核实的技术声明**：Supabase 的 S3 密钥能否只读；Tauri 的 CSP 对远程页面是否生效；Turnstile 在大陆能否通过（是可用性风险，已列为上线后的跟进项）。
