## 二、0.19 的新问题

### 严重

**S1 `thumb_path` 没有约束，service role 会替人读别人的图片并送给 AI**
- **证据**：
  - 附录 A：note_images 新加的 `thumb_path`（2414 行）没有任何 check；
  - note_files 的 `thumb_path`（2423 行）也没有约束，而且是客户端可写列（2433 行）；
  - 5.13 第 5 点：ai-media 用 service role 按 `thumb_path` 读缩略图送给 Gemini，隐私记的缩略图还从 vault-images 读。service role 不受 RLS 和存储策略限制。
- **后果**：任何一个登录用户，把自己那一行的 `thumb_path` 改成别人的对象路径（包括别人隐私记的缩略图）就行。ai-media 会读出别人的图片送给谷歌，再把描述和标签写回攻击者自己的行，随增量同步落到攻击者本机。这是**跨用户泄露**。对象路径是 uuid，较难猜，但路径不是密钥，不能当作防线。
- **改法**：
  - 两张表都加约束：`thumb_path` 的第一级目录必须是本人的 user_id，并且符合 `<user>/<note>/<id>.t.webp` 的格式；
  - 最好不让客户端写 `thumb_path`，改由服务器按 id 拼出路径；
  - 服务器函数一律用"行里的 user_id + id"自己拼对象路径，不信任行里存的路径字符串；vault-images 缩略图也一样；
  - 加一条 RLS / 函数测试：B 把 `thumb_path` 指向 A 的对象，ai-media 拒绝，或者读到的是 B 自己的路径。

### 中

**M1 检查做完以后，文件内容还能被换掉**
- **证据**：
  - 2433 行：客户端可以 update `path`、`kind`、`mime`、`bytes`、`sha256`；
  - files 桶给了 delete 权限（3.3 G 部分），没有 update 策略，但"先删掉、再在同一路径上传另一份内容"是可以的；
  - `check_status=ok` 不会因为这些改动而重置。
- **后果**：可以把 `kind` 从 docm 改成 docx，或者把已检查的对象换成没检查过的内容，然后进入预览解析（docx-preview / SheetJS），并显示成"不含宏"。另外，`note_id` 可以改，而 `guard_note_file` 只写了在 insert 时检查（3.3 A 部分），可以把文件挪到隐私记下面。
- **改法**：
  - update 只授权 `name`、`deleted_at`；
  - `path`、`kind`、`mime`、`bytes`、`sha256`、`note_id` 不允许修改，用触发器或者不授权来保证；
  - `guard_note_file` 在 insert 和 update 时都检查；
  - 客户端预览前核对下载到的 blob 的 sha256 和行里一致，不一致就不预览；
  - file-check 记下对象的 etag 或版本号，补扫时发现对象变了，就退回 pending。

**M2 随手记移进隐私记时，文档附件的明文会留下**
- **证据**：
  - vault import（1128 行）只清 notes 表的明文列和图片；
  - 5.13 第 6 点只为图片写了"描述在两边之间搬"；
  - `note_files` 规定只能挂普通随手记，但触发器只在 note_files 自己写入时执行，import 改的是 notes，触发器不会执行。
- **后果**：移进隐私记以后，原来那条的 `note_files` 还在，`text_excerpt`（最多 2 万字抽出的正文）、`ai_desc`、`ai_tags`、文件名都是明文，会同步进本机 IndexedDB；向量的 `is_vault` 还是 false，锁着时也能查到。这违反"隐私记的明文不进本机缓存"（4.1）和"锁着时查不到隐私记"。
- **改法**（二选一，写进 5.5 和 5.13）：
  1. 有文档附件的随手记不能移进隐私记，提示"先删掉附件"；
  2. import 在同一个事务里删掉这些附件、文件对象、对应的向量。

  补一条函数测试。另外，普通图片的 `thumb_path` 对象也要随图片一起挪进 vault-images。

**M3 删除以后，向量和描述成了孤儿**
- **证据**：
  - 5.13 第 6 点说"30 天清理时随行一起删（外键 on delete cascade）"；
  - 但附录里 `private.note_vectors`（2438 行）只有到 `auth.users` 的外键，`note_id` 和 `source_id` 都没有外键；
  - `private.vault_media_ai`（2445 行）也只有到 `auth.users` 的外键，没有到 note_images 的外键。
- **后果**：30 天清理把行硬删以后，向量（包括隐私记那份不加密的）和加密的描述永久留在库里，和"最近删除 30 天"、15.7 第 7 项的承诺不符。
- **改法**：
  - `note_vectors (note_id, user_id)` 加复合外键到 notes，并且 `on delete cascade`；图片、文件那一类的 `source_id` 另加外键，或者由 3.4 的清理任务显式删除；
  - `vault_media_ai.image_id` 加外键到 note_images，并且 `on delete cascade`；
  - 3.4 写上"孤儿向量清理"，补测试。

**M4 关掉"隐私记交给 AI"或撤回同意以后，已经存下的数据怎么处理没写**
- **证据**：5.13 只写了"关掉以后不再送"，没写已经算好的向量怎么办。
- **后果**：隐私记的向量不加密，这是负责人以"参与 AI"为前提接受的风险。用户关掉 `ai.vault`，自然以为隐私记从此不在 AI 那套东西里了，但 `is_vault=true` 的向量和 `vault_media_ai` 还在。
- **改法**：
  - `ai.vault` 改成 false 时，用 settings 触发器或下一轮 ai-embed 删掉这个人 `is_vault=true` 的向量；`vault_media_ai` 可以留着（它是加密的），但要写明；
  - 撤回同意时，删掉全部向量，`ai_desc` 和 `ai_tags` 是保留还是删除，在 15.7 写清楚；
  - 设置页的小字照实写。

### 轻

- **L1 docx 预览和 CSP 规则冲突**：
  - docx-preview 会插入 `<style>`，DOMPurify 产出的 HTML 要放进 iframe，只能用 srcdoc；而 srcdoc 会继承主页面的 `style-src 'self'`，A22 又禁止 innerHTML，**没有例外**；
  - 要写明做法：用一个单独路径的预览文档，带自己的 CSP（`script-src 'none'`，样式可放宽），或者给 A22 加一个只限这一个模块的例外；
  - **不准**为了它放宽主 App 的 `style-src`。
- **L2 file-check 的写法自相矛盾**：
  - ZIP 的中央目录在文件末尾，"用 Range 读对象开头"读不到，要改成读末尾；
  - 服务器的压缩比检查只能看 ZIP 里声明的大小，声明可以造假；
  - 所以客户端预览库（JSZip / fflate）解压时也要按真实字节数设上限，防止有人绕过客户端、上传一个造假的 ZIP 炸弹，把其他设备的预览卡死。
- **L3 `save_attachment` 和文件名**：
  - Rust 端要先解析 URL，再比对来源和路径，拒绝 `..` 和百分号编码绕过，不能只比字符串前缀；
  - 另存的文件名还要去掉 `: * ? " < > |`（`:` 在 NTFS 上会写成备用数据流）、Windows 保留名（CON、NUL 等）和末尾的点与空格；
  - 数据库的 name 约束（2424 行）也补上这些字符。
- **L4 微软预览**：
  - iframe 的 `allow-popups` 除非实测需要，否则去掉；要保留的话，exe 里弹出的新窗口一律交给 `open_external`；
  - 每台设备第一次预览 PPT 的提示，做成二选一按钮："预览（交给微软）/ 只下载"；
  - 没同意 AI 的朋友，这一步不在 AI 同意范围里，要靠这个选择来覆盖；
  - 15.7 第 4 项"出境"要补上微软，以及谷歌新增的那些内容（现在只在 3b 写了）。
- **L5 15.7 要更如实**：
  - 384 px 的缩略图上，证件号码等可能仍然看得清。缓解措施"只送缩略图"不能写成"保护了内容"；
  - 第 5 项和告知页要直接写"证件照、病历这类照片也会交给谷歌"；
  - 第 16 项影响评估要把唯一识别信息（身份证号、住民登录号）、健康信息列为可能出现的敏感信息；
  - 第 7 项要补本机附件备份保留多久、向量保留多久。
- **L6 视觉稿没跟上**：`docs/02-设计` 里搜不到"图片和附件"。告知页、设置 › 语音与 AI 要按 15.5 改：加粗、单独一行列出送哪些东西、"预览 PPT 交给微软"那一行。这是开放给朋友前必须完成的 UI 项。
- **L7 `vault_media_ai` 的加密参数**：AAD 写明是 `user_id|image_id`；加 `enc_key_id` 列，和隐私记正文一致，方便以后换密钥。
- **L8 孤儿对象**：files 桶允许任意内容以"image/webp"的类型上传，只靠每天的孤儿清理。可以接受，但 3.4 的清理范围要写上 files 桶和缩略图。
