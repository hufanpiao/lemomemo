**N3　Radix Dialog 可能和"不准插入内联 `<style>`"的 CSP 冲突（需核实）**
- **证据**：
  - :378 选用 Radix 的 Dialog 和 DropdownMenu；
  - :1241 和架构约定 9.4 写"不准用任何会生成内联 `<style>` 的库"，CSP 是 `style-src 'self'`（:1232）。
- **为什么**：Radix Dialog 的滚动锁依赖 react-remove-scroll，它的依赖里有 get-nonce，说明可能会插入 `<style>` 标签并支持 nonce（这是我的推断，需要看源码核实）。同类组件库 Base UI 的文档明确说，这类组件会插入内联 `<style>`，严格 CSP 下要给 nonce 才行。
  - 来源：[licenses.dev 上 react-remove-scroll 的依赖](https://licenses.dev/npm/react-remove-scroll/2.6.3)、[Base UI CSP Provider](https://base-ui.com/react/utils/csp-provider)（2026-10-24 查询）。
  - 静态托管的 Pages 给不了每次请求不同的 nonce。真冲突的话，E2E 的"控制台无 CSP 报错"会挡住 B1。
  - Motion 的 `AnimatePresence mode="popLayout"` 也会插 `<style>`（Motion 的 `MotionConfig` 有 nonce 参数，原因就在这里），需核实。
- **建议**：
  - B0 先拿 Radix Dialog 和 Motion 在带 CSP 的 `wrangler pages dev` 下跑一遍；
  - 冲突的话三选一：滚动锁自己写（不用 Radix 的 modal 滚动锁）、换一个不插 style 的弹层实现、或者 `style-src` 放开 `'unsafe-inline'`（风险较低，但要写进安全审查）；
  - 禁用 `popLayout` 模式。

**N5　首屏 150 KB 的预算，B0 用"空白 App"验收没有意义**
- **证据**：:343 B0 验收的是"空白 App 首屏 ≤150 KB"；:488 估算 React 约 60 KB，其他 50–60 KB。
- **为什么**：今天页真正的首屏还要带：
  - zod（架构约定 9.2 规定 IndexedDB 读出来的数据一律先过 zod），约十几 KB，需核实具体版本；
  - 当前语言的词典；
  - 本地拆分规则（打字预览要用）；
  - 农历数据（今天页显示农历的话）；
  - 提醒横幅、"＋"、提示条；
  - 如果首屏就用了 `<Appear>`，还有 Motion 的核心部分。
  
  这样算可行但很紧。另外，冷启动时对几千行数据逐行跑 zod，会拖慢 iPhone 的冷启动。
- **建议**：
  - 体积预算的硬验收挪到 B2，按真实的今天页测；
  - 词典按语言分包；
  - 农历数据放进单独的 chunk；
  - IndexedDB 只在写入时校验，并带 schema 版本号，读的时候信任本机数据，或者冷启动只校验第一屏要显示的行。

**N6　exe 方案 A：Tauri 的 IPC 可能被页面自己的 CSP 拦下（需核实）**
- **证据**：:1028 方案 A 吃网页的 `_headers`；:1233 的 `connect-src` 是 `'self' wss://lemomemo.com`。
- **为什么**：Tauri 2 在 Windows 上走 `http://ipc.localhost` 这类自定义协议通信，被 CSP 拦住后会退回 postMessage（这是我的了解，需核实），控制台会出 CSP 报错。全局快捷键弹出的打字框是第二个窗口，也要加进 `remote.urls` 的 capability。
- **建议**：
  - B6 技术验证加"IPC 在页面 CSP 下是否正常、控制台有没有报错"；
  - 需要的话，CSP 加 `ipc: http://ipc.localhost`（只在 exe 生效，或者网页也带上，影响很小）；
  - 第二个窗口写进 capability。

### 轻

- **L1　前端文件名混用 `.js` 和 `.ts`**。:1177 `platform/env.js`、:1034 `platform/desktop.js`、:1016 `ui/keys.js`、:461 `core/fmt.js`、:1191 `logic/ai-schema.js`、:1654 `functions/index.js`（:1262 写的是 `index.ts`）。:363 虽然有统一说明，但 :1191 的 ai-schema 已经改成 `shared/schema/ai.ts`，对不上。建议顺手统一。

- **L3　"带提醒的条目优先发送"会打乱先后顺序**（:698）。要写明：同一条记录的 insert 和 patch 不能颠倒；有外键依赖的（例如 note_images 依赖 notes）不能被提前。
- **L4　forked 之后要不要推进 base_rev 没写**。冲突后如果不推进，排在后面改 body 的 patch 会再次 forked。
- **L5　"减少动态效果"的默认值**。`ui.reduce_motion` 写"默认跟随系统"，但设置表是"一项一行"，要写明"不存就跟系统"，和 `cal.holidays` 一个写法。
- **L6　"回到今天"直接切换**（:1124），和 R-101 定的"今天"按钮行为要一起核对（并入 N1）。
- **L7　own_revs 超过 20 个的处理**。超过就按 conflict 处理，随手记会因此生成冲突副本。离线时连续编辑同一条随手记很容易超过 20 次，不过排队中的 patch 本来会合并，影响有限。建议契约测试加"在途期间编辑 30 次"。
- **L8　离线提醒的推送时机**。真机⑯的做法正确，但"回到前台第一件事就是发这些条目"受 30 秒发送周期和退避影响。建议回到前台时立即发一次，不等周期。
- **L9　自定义错误页需核实**。Cloudflare 的自定义错误页（1027）免费版能不能用，需核实；不能用的话，`/` 超额时只能接受默认错误页。
