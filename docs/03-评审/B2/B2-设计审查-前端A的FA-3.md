做得好的地方：
- 二级页的路由、返回和焦点跟注销页是同一套：进页把焦点放到 h1，`‹ 设置` 返回会退一步历史；直接打开地址时原地换回设置页，不多压一条历史。
- 入口行整行是按钮，44 高；按下变淡，不缩放；减少动态效果的两种开法（系统设置和 `data-rm`）都关掉了 transition，和设置页 10-31 的决定一致。
- 分段按钮 `aria-pressed`、单选用 `fieldset` 加 `legend`，读屏结构对；`::after` 把点按区扩到 44，和设置页同一种写法。
- 月格每格的读屏名字按项目汇总，包括没显示出来的件数；不靠颜色和简称传达信息（5.12 无障碍那条）。周视图色块读完整标题和当天的起止时刻。
- 农历行一直占着高度，农历加载完格子不跳动；韩文界面靠 `lunar.ts` 没有韩国数据，不出农历行（R-318）。
- 词典中韩键一一对应，`satisfies` 在编译期兜底；韩文全部标了 REVIEW(ko)。

## 问题清单

### 高（改完才能过）

**H1　项目色标签和周视图色块：底色和竖线用反了，文字对比度不够，深色模式几乎看不见**
`CalendarPage.module.css` 的 `.c0`～`.c6`（约第 208～240 行）写的是 `border-color: var(--pN); background: var(--pNs)`，文字是 `.mark`、`.block`、`.chip` 的 `var(--text)`。视觉稿的 `.lgtag`、`.wev` 是 `background: var(--pb)`（= `--pN`，浅色块）、`box-shadow: inset 2px 0 0 var(--pc)`（= `--pNs`，深色竖线）、`color: var(--on-p)`。令牌里 `--pNs` 是深色（简洁·浅色 `--p1s:#857200`），深色模式下 `--pNs` 反而是亮色（`--p1s:#E6D350`）。按令牌算：
- 简洁·浅色：`#141518` 对 `--p4s #6A4FC4` 约 3.1，对 `--p2s` 约 3.7，对 `--p1s` 约 3.8，都低于 4.5；
- 简洁·深色：`--text #F2F3F5` 对 `--p1s #E6D350` 约 1.4，基本看不见；
- 照视觉稿：`--on-p #141518` 对 `--p1 #F2DF4A` 约 13.4。
CSS 文件头的注释也写着“浅底 --p1s…”，说明是理解反了。改法：`background: var(--pN)`，左侧竖线用 `--pNs`，文字 `color: var(--on-p)`；月格的 `.mark`、周视图的 `.block`、`.chip` 三处都要改。竖线宽度用视觉稿的 2 px（现在是 3 px）。改完要把“竖线对格子底色 ≥ 3”“标签文字对标签底 ≥ 4.5”加进 check_contrast.py 的清单（5.12 对比度那条）。

**H2　简洁·浅色皮肤下，“今天”在月历里没有标记**
`.today .dayNum` 只写了 `background: var(--today-bg); color: var(--today-fg)`。简洁·浅色的 `--today-bg` 是 `transparent`，“今天”靠 `--today-ring: #141518` 画墨色细圈（R-132 方案 C）；视觉稿 `.mcal span.td` 有 `box-shadow: inset 0 0 0 2px var(--today-ring)`。现在少了这一行，默认皮肤下“今天”只多了一点加粗，基本找不到。加上 `box-shadow: inset 0 0 0 2px var(--today-ring)`。周视图的“今天”只是行头多两个字，线框里是同样的墨色细圈（`.wr .wd.t b`），也要补上。

**H3　日历页顶部没照 R-101 摆法 B 做**
负责人看过 3 个方案后选了 B（R-101，原话说“▾这个不醒目”）：标题做成胶囊“2026年10月 ⌄”，白底、圆角、细描边；“‹ 今天 ›”放在“周 / 月 / 纪念日”分段控件的右侧。现在：
- 标题是没有边框、没有“⌄”的纯文字按钮（`.title`），看不出能点；
- 分段控件和标题在第一行，“‹ 今天 ›”单独排在第二行、靠左；
- 分段是“月 / 周”，顺序和线框的“周 / 月 / 纪念日”反了。“纪念日”页如果不在 FA-3 范围，至少顺序要对，并在交付说明里写明“纪念日”这一格留给哪一段；
- 日历页的分段控件（有边框、方角切开）和设置页的分段控件（`--panel-2` 底、胶囊）是两套样子。
按线框改：第一行是标题胶囊（右上角头像不在本段范围）；第二行左边是分段，右边是“‹ 今天 ›”，三者间距 8 px。周视图的标题按线框写“10月19日–25日 ⌄”，现在周视图也显示“2026年10月”，看不出是哪一周。

**H4　年月选择器不是 5.12 和线框定的样子**
5.12 第 3 点写明：用 Radix Popover，里面是年份和 12 个月的格子，**不用滚轮**；方向键在月份间移动，回车选中，Esc 关闭；当前年月高亮，今天所在的月份加小点；点外面或再点一次胶囊收起；弹出用 `<Appear kind="popover">`。线框 sYM 和视觉稿 `.ympop` 还有底部“回到今天”，每格 44 px。现在 `MonthPicker` 是两个原生 `<select>` 加“确定”“取消”，嵌在页面里：
- 在 iPhone 上原生 select 弹出的就是滚轮，和“不用滚轮”正好相反；
- 选完还要再点“确定”，比线框多一步（线框是点月份就跳过去）；
- 没有 Esc 关闭，打开后焦点也不进到选择器里；标题按钮只有 `aria-expanded`，没有 `aria-controls` 或 `aria-haspopup`；
- 没有“今天”的小点，也没有“回到今天”。
年份范围 1900～2100 可以保留（公历本身没有限制）；但 R-319 定中国农历从 1901-01-20 开始，1900 年的格子不会有农历行，这一点正常。

### 中

**M1　周视图没有时间刻度，0～24 点的横轴看不出时间**
线框 s2 的手机泳道是 8～22 点，每 2 小时一条刻度线，顶部标数字；8 点前的事在行首写“‹7:30”，竖黑线是“现在”，每行右边是当天共几项、有逾期待办的加“逾”。现在 `.track` 只是一条灰底，没有刻度、数字和现在线，横轴是 0～24 点（按 375 宽的屏算，1 小时约 12 px）。色块的位置和长短是这个视图唯一的信息，没有刻度就读不出来。至少要补刻度、刻度数字和现在线；横轴范围用 8～22 加“‹ / ›”提示还是 0～24，要和视觉稿或负责人确认，不能自己定。

**M2　周视图的待办、全天事项和点一天的行为都和定稿不同**
- 架构 0.51 写的是：待办在泳道上画**空心圆**（有截止时刻画在那个时刻，没有的画在泳道末端），不占上下两排。现在是在泳道上面另起一行“小签”。
- 全天事项：5.12 写的是在行左端日期下面放一个“全天 N”小标签（N=1 时写简称）。现在每件事一个小签，而且全天小签没有加项目色（`allDayIds` 那一段没有 `colorClass`）。
- 线框里点一条泳道就选中那一天（整行灰底），下面列出这一天的全部日程和待办；“+N”点开也是看这个清单。现在没有选中状态、没有下面的清单，“+N”是不能点的 `<span>`。
如果这些计划放到 FA-3 的下一段，请在交付说明里写清楚哪些留到哪一段；本段不能当作已经照线框做完。

**M3　月历点一天的行为和线框不同；没有底部图例**
线框 s3 里点某一天是在月历下面列出当天的全部日程和待办（“和周视图一致”），往上拖列表时月历收成一周一行。现在点格子直接跳到那一周的周视图。线框要求月历底部常驻一行图例（“灰底：中国节假日（设置 › 日历 可改成韩国或两国）”“标签：一件事，写简称”“+N：还有 N 件”“◆ 纪念日”），现在也没有。图例同时也是告诉用户节假日在哪里改的唯一入口提示。

**M4　周末和节日名自己加了红色**
`.weekend`（周六、周日、放假日的日期数字）和 `.holName`（节日名）都用 `--danger-text`。线框和视觉稿都没有周末红字：放假只用灰底（`--hol-bg`），节日名是正文色。`--danger-text` 是错误和删除的颜色，拿来标周末，意思混了；按韩国的习惯，周六一般是蓝字，现在两国用户都会觉得别扭。删掉 `.weekend`，`.holName` 改用 `--text`（补班的 `.work` 可以保持 `--text-2`）。

**M5　纪念日标记是黄色小圆点，不是菱形，白底上看不清**
R-105 和线框写的是：月历格子里的纪念日是柠檬黄填充的菱形，浅色模式加墨色边，深色模式加浅色边。现在是 5 px 的 `--accent` 圆点，没有边：`#F2DF4A` 对白色格子约 1.4，低于非文字对比度 3。改成菱形加边。

**M6　“两国都显示”时只显示一个节日名**
R-97 和 5.12 写的是：本国节日名在前，另一国的用小一号写在第二行，放不下才只显示一个。`MonthGrid` 只取 `c.holidays[0]`。二级页的说明文字又写着“两国都显示时，本国节日名在前”，用户选了“两国都显示”后，在月历上看不到另一国。至少在格子高度够的时候画第二行；读屏名字里已经两个都有，这一点没问题。

**M7　点按区：周视图的小签、色块不到 44**
`.chip` 是 28 高，`.block` 是 24 高（分两排时更矮），都没有像设置页那样用 `::after` 扩点按区。线框说明里写“44px 最小点击区（小按钮外扩）”。泳道上的色块挨得近，不能每块都扩到 44，可以：小签用 `::after` 扩到 44；色块保持视觉高度，但让点一下泳道先选中那一天、在下面的清单里点具体哪一条（就是 M2 的线框做法），这样就不会误点。月格 1/7 屏宽，375 宽时约 50 × 76，满足要求。

**M8　设置 › 日历 二级页：单选圆点对比度不够，样子也和设置页其他行不一致**
`.choice input { accent-color: var(--accent) }`：浅色皮肤下选中的圆点是 `#F2DF4A`，对白色卡片约 1.4，低于非文字对比度 3，一眼看不出选的是哪一个。设置页其他地方选中都用 `--chip-on-bg`（简洁·浅色是墨黑）。另外三个选项挤在一个 `.row` 里，选项之间没有分隔线；`legend` 写在卡片里面，和线框里组标题（`.gt`）写在卡片上方的做法不同。建议：卡片上方用 `.gt` 写“节假日”，卡片里每个选项一行（44 高，有分隔线），选中的那一行右边打“✓”（墨色，`--text`），整行可点；读屏结构保留 `radiogroup` 的语义（可以用视觉隐藏的原生 radio，或者 `role="radio"` 加 `aria-checked`）。

### 低

- **L1　说明文字偏开发口吻，韩文语气不统一**：“没选过时跟界面语言……选过以后固定”是讲实现规则。二级页里已经亮着一个选项，用户不会知道“没选过”是什么意思。建议改成“默认跟界面语言。两国都显示时，和界面语言同一国的节日写在前面。”（“本国”这个说法对一位用中文界面、住在韩国的用户来说有歧义）。韩文 `holNote`、`saveFailed` 用的是합니다체（“따릅니다”“못했습니다”），而编辑页等其他韩文都是해요체（“저장하지 못했어요”），要统一成해요체。
- **L2　韩文换行**：全局没有 `word-break: keep-all`（`src/styles/` 里搜不到），线框 s18 要求韩文按词换行。二级页的韩文说明有两行多，会在词中间断开。这是全项目的问题，建议记进待办，在 base.css 里对 `:lang(ko)` 统一加，不在本段单独改。
- **L3　月格读屏名字里没有星期几**：星期表头是 `aria-hidden` 的，单独听一格是“11月3日，没有安排”，听不出是星期几。在 `cellLabel` 的日期后面加星期几。
- **L4　“日历”标题有两个词典键**：二级页标题用设置的 `settings.cal.title`，入口行用日历的 `cal.set.title`，两边以后改了容易对不上。建议二级页标题也从 calendar 的词典取，或者在测试里断言两个值相同。
- **L5　从二级页返回后焦点去哪了**：进页时焦点放到 h1，返回设置首页后焦点没回到“日历”那一行，读屏和键盘用户要从头找。注销页也是这样，可以一起记进待办，不算本段的回退。
- **L6　月历标签字号**：`.mark`、`.block` 用了 `--fs-10-5`。R-104 是负责人明确定的 9.5 px（有意低于 11 px 下限，架构写着“不要改”），令牌里有 `--fs-9-5`。大一点更好认，但要改就得先问负责人，不能自己改。
- **L7　离线提示**：5.12 写着离线时切到一个从没拉过的国家，月历上方提示“联网后显示节假日”。现在拉不到就不显示，没有提示。
- **L8　翻页没有跟手滑动**：5.12 的动效写的是滑动时格子跟手移动、松手后用 `--dur-ui` 滑到位。现在是直接切换。减少动态效果时直接切换是对的；正常模式下缺了动画，可以放到下一段，但要在交付说明里写明。

## 对前端 A 拿不准的 5 条的意见

**1. 线框没画日历二级页本身，照“未来 7 天的提醒”页写（左“‹ 设置”，标题居中），正文是节假日单选和每周第一天分段——同意顶栏这样做，正文要改。**
顶栏和 sR7 的写法（“‹ 设置”在左、17 号标题居中）一致，也和现有注销页同一个 `.top`（同一个 `view-transition-name`），这样做是对的。正文要按设置页的“组标题 + 卡片 + 44 高的行”来排：节假日用组标题加三行，选中的打“✓”（见 M8）；“每周第一天”一行，右边是分段按钮，和“界面语言”那一行同样写法，这个已经对了。说明文字放在卡片下面的 `.sn`，这个也对。

**2. “两国都显示”时摘要：中文“节假日：中国、韩国”，韩文“공휴일: 한국·중국”——可以接受。**
中文摘要整体是“农历 · 节假日：中国、韩国”，里面已经用“·”分隔了大项，国名之间用“、”不会和它混；韩文本国在前，和 R-97“本国在前”一致。长度在 375 宽的屏上放得下（大约 13 个汉字，13 号字）。可选：中文改成“节假日：中韩”更短，但不如“中国、韩国”一眼就懂，我倾向保持现在这样。韩文的“·”没问题，也可以写成“한국, 중국”，交给 R-106 韩文审校定。要做的是补一条测试，覆盖中文“两国都显示”时的摘要。

**3. 线框首页把几行合在一张卡片里，现在设置页每个分组一张卡片——要记进待办，但不是 FA-3 的问题，也不挡本段。**

## 新问题

**N1（中，过关条件）　手机上年月选择器背后没有变淡，宽度也不够**
前端 A 说“按线框，背景不变暗”，这是把线框读反了。线框 sYM 手机的两张图都叠了一层 `YMDIM`（半透明白色遮罩），说明里写着“背后内容稍微变淡”；**不变淡的是电脑版**（“电脑同一个浮层……背后不变淡”）。两张选择器截图里背后完全没变：右上角的“今天”被浮层盖住一半，看起来像露在外面的半个按钮，浮层和页面的层次分不清。宽度也不对：线框是 `left:16px; right:16px`，5.12 写的是“手机上 Popover 宽度占满屏幕减边距”，现在大约 300 pt 宽，右边露出一截月历。改法：窄屏时加一层 `--scrim` 遮罩（点遮罩收起，和点外面一样），浮层左右各留 16 px；宽屏保持现在的样子。

**N2（低）　周视图的现在线压住了色块里的字**
手机周视图截图里，现在线正好压在“牙医”色块上，“牙”字被切掉一半。建议现在线放在色块下面一层（色块的 `z-index` 比现在线高），或者现在线经过色块的那一段画成半透明。线框里也是一条竖黑线，没有要求盖在色块上面。

**N3（低）　“今天”不可点时和可点时看起来差不多**
在本月 / 本周时，“今天”只是字改成 `--text-2`，还是 600 粗。截图里它和两边的“‹ ›”几乎一样深，用户看不出它现在点了没用。线框里不可点时是浅灰（`--g3`）。建议不可点时改成 400 粗，或者把字的颜色再调浅（`--text-2` 对 `--panel` 仍要 ≥ 4.5，可以试 `--text-2` 加上 400 粗）。

**N4（低）　时间刻度没有标出轴的起点**
R-324 让时间轴按事项往外扩。周四 7:00 的“健身”让轴从 7 点左右开始，但刻度第一个数字还是 8，色块左边那一段没有数字，看不出它是几点。建议轴往外扩的时候，刻度也从新的起点开始标（比如 6、8、10…… 或者在最左端写起点的小时数）。

**N5（低）　年月选择器底部的提示在周视图里换行很难看**
周视图那张截图里，提示文字是“选好后跳到该月 1 日所在的那一周 · 小 / 点是今天”，“小点”被拆在两行。可以把“小点是今天”单独放一行，或者缩短成“跳到该月 1 日那一周”。改了 N1 让浮层变宽以后，可能就放得下了，改完再看一眼。

**N6（低）　“‹ 今天 ›”的点按区互相重叠 4 px**
三个按钮间距 8 px，`::after` 每个往外扩 6 px，相邻两个扩出来的部分重叠 4 px，点在两个按钮正中间时，响应的是 DOM 里后面那一个。设置页的写法是 `width: max(100%, var(--hit))`，按钮比 44 宽的方向不往外扩，就不会重叠。建议“今天”只在上下方向扩，“‹ ›”保持 44 宽、不再往外扩。

**N7（低）　对比度清单还缺“今天”的细圈**
`contrast-pairs.json` 新加了标签竖线、无项目标签、“✓”、选中框等 10 项，没有加 `--today-ring` 对 `--panel` 的对比度。简洁·浅色的墨色圈对白底肯定没问题，但以后改皮肤时没有检查兜底。建议补一项（非文字对比度 ≥ 3）。
