## 中

### M1　N1 的补帧让“要取到看得清的帧”恒成立，补帧又认不出“别的行直接跳上来”这种压字；机器忙时会把真回归放过去

- 位置：`tests/e2e/b2-motion-list.spec.ts:133`（补帧 `hitsOf(g, lastOthers)`），`:203`（`seen += 1` 不分来源），`:242`、`:258`（`expect(seen).toBeGreaterThan(0)`）。
- 原因：
  - 补帧拿离开那一项此刻的字，去比**上一帧**别的行、组标题的位置。上一帧里离开那一项还占着自己那一格，别的行也还在原位，所以只要离开那一项自己没挪（popLayout 正常），补帧就一定是 0 条命中。
  - 它能抓的只有“离开那一项自己跳位”这一种。“下面的行不走 FLIP、直接跳上来压住残影”是 N1 要防的主要回归，补帧认不出来。
  - 补帧的不透明度接近 1，又一定算进 `seen`。原来的不稳定就是 `seen = 0`（webkit 忙时一帧都没落进 110 ms 的淡出），现在这道守卫恒过。也就是说，原来是“取不到帧就挂、提示没测到”，现在变成“取不到帧就通过”。
- 复现（独立副本 `rv-n1`，端口 8798、inspector 9240、假后端 9192 / 9193，单独的持久化目录，跑完已停服务、删副本）：

  | 情形 | 结果 |
  |---|---|
  | 基线：N1 那几条，chromium + webkit 各 2 遍 | 20/20 过 |
  | 产品变异 NM1：AppearList 退场淡出 `dur.ui / 2` → `dur.ui * 2` | 12/12 挂（照常抓住） |
  | 产品变异 NM3：AppearList `layout="position"` → `layout={false}`（下面的行直接跳上来） | 8/12 挂。挂的明细里第一条命中是“松手后 27 ms，不透明度按 1.00 算（当帧 0.56），压到 没有日期”；补帧那一刻（< 27 ms）没有命中，和上面的分析一致 |
  | NM3，再在取样里模拟机器忙（`dt` 在 0～70 ms 之间的 rAF 帧不取，补帧照旧）| **N1 删除 3/3 通过**：产品确实在压字，用例没报 |
  | 对照：改前（HEAD）的用例，同样 NM3 + 同样的模拟 | 3/3 挂，报“要取到离开那一项看得清的帧（否则这条什么都没测）”，取样从 76 ms、0.02 开始 |

- 建议改法（任选一种）：
  1. 补帧只用来垫不透明度的历史（让之后 34 ms 窗口里的 rAF 帧按它算），**不计入 `seen`**：在样本上打个来源标记，`seen` 只数 rAF 帧。rAF 一帧都没取到时，在用例里重做一次删除或打勾，最多 N 次，不要直接通过。
  2. 或者不靠墙钟：离开那一项挂上 `leaving` 时，用 `document.getAnimations()` 把它和收拢的动画都暂停在几个固定进度（0、25%、50%），每个进度等一帧，再量画出来的位置。这样取样和机器快慢无关。
  3. 至少把补帧的局限写进文件头：它只能抓“离开那一项自己跳位”，抓不到“别的行跳上来”。并且 `seen` 不能只靠补帧凑够。
- 补充：补帧对检出也有正面作用。NM3 的明细里，43 ms 那帧当帧只有 0.20，是靠补帧的 1.00 垫进窗口才被算进来的。所以建议“留着补帧、只是不让它单独满足 seen”，不建议直接删掉。

#### N1 打勾那一条要不要另做变异：不用

- NM3 下打勾不挂，不是用例漏报，是这个变异在打勾路径上根本不产生压字：取样里离开那一项（todos-g-nodate 整组）从 1.00 淡到 0.02，全程没有一帧和别的行、组标题的字相交。打勾时“已完成”组什么时候往上收，不只由行级的 layout 决定（M1 那条用例钉着头 220 ms 不动）。具体是哪一层，本轮没往下追。
- 打勾已经有能产生真压字的变异：NM1 让残影淡得比收拢慢。NM1 在两个浏览器都能抓住打勾，加上忙机模拟也一样。所以打勾这一条的检出能力已经验证过，不需要再专门设计变异。
- 建议（可选）：在 b2-motion-list 文件头写一句“打勾的压字靠淡出和收拢的先后顺序防，layout={false} 这种变异在打勾上不产生压字”，免得以后有人重复去查。

#### ghostRun 重做的副作用

- 重做时整个 prepare 从头来（seed 会 goto 并重写 IDB），每一次里出现的压字都算进来，3 次都没取到看得清的 rAF 帧就挂。不会因为重做把压字洗掉。
