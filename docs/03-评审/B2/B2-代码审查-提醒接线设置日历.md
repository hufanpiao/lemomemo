## 高

### H1　从“未来 7 天的提醒”点一条去编辑页，回来后一层层返回会多压历史；在设置首页侧滑，又滑回“提醒与通知”

- 位置：`src/features/settings/ui/SettingsPage.tsx:171-189`（`pushed` 是组件里的 `useRef`，设置页卸载就没了）；出口在 `src/features/reminders/ui/RemindUpcoming.tsx:112`（清单行 `navigate('event'|'todo', id)` 会离开设置页）
- 原因：这个记号只在设置页挂载期间有效。RemindUpcoming 每一行都能点去编辑页（“点一条可以改”）。去了再回来，设置页会重新挂载，`pushed` 变成空的。于是两层返回都走 `replaceRoute`，历史里留下两条废的设置子页。
- 复现（在独立副本里跑过探针，结果确认）：
  1. 依次进入 `#/today` → `#/settings` → 点“提醒与通知” → 点“未来 7 天的提醒”，然后点一条进编辑页 `#/event/x`
  2. 侧滑返回，回到 `#/settings/remind/upcoming`（设置页重新挂载）
  3. 点“‹ 提醒与通知”：执行的是 replace，地址到了 `#/settings/remind`
  4. 点“‹ 设置”：还是 replace，地址到了 `#/settings`
  5. 在设置首页侧滑或按浏览器后退：探针得到的地址是 `#/settings/remind`，**又回到了提醒二级页**，正确的结果应该是 `#/today`。这就是 `router.ts` 的 `goBack` 注释里专门要避免的“设置、注销、设置”那种历史。
- 建议改法：别把“是不是点进来的”记在组件内存里，记到**那一条历史自己的 `history.state`** 里。
  - 推荐：在 `router.ts` 加一个参数，比如 `navigate(name, ...params)` 带一个 `{ sub: true }`，或者单独做一个 `navigateSub`。push 的时候写成 `{ lemoDepth, lemoSub: true }`；`backFromSub` 看 `history.state?.lemoSub`，是 true 就 `goBack()`，否则 replace 回上一层。
  - 这样浏览器前进后退、刷新、离开设置页再回来，记号都跟着那条历史走。`pushed` 这个 ref 和第 172-175 行的清理 effect 可以整段删掉。日历、注销二级页一起受益。
  - 补测试：用上面的复现步骤（cleanup 后重新 render 来模拟离开再回来），断言最后一次 `history.back()` 离开了设置。

## 中

### M1　前进后退混用、刷新时会多压历史，有一种走法还退不回去；日历、注销二级页比改动前倒退了

- 位置：`SettingsPage.tsx:172-175`（侧滑回到首页清空记号，回到提醒层删掉 upcoming 的记号）
- 改动前，`pushedSub` 侧滑回去以后不清零。这个“残留”的 true 恰好让“前进回子页再点返回”走 `history.back`，结果是对的。现在侧滑回去一定清掉，前进回来就没有记号了。
- 复现（探针确认）：
  - **P2　退不回去**：首页 → 提醒 → 未来 7 天，侧滑退到提醒，再浏览器前进回到未来 7 天。
    - 点“‹ 提醒与通知”：执行 replace（`history.back` 调用 0 次）。历史变成 [设置, 提醒, 提醒]。
    - 再点“‹ 设置”：这一层的记号还在，所以执行 `goBack()`，落到了**同一个地址** `#/settings/remind`。页面没动，要再点一次才能出去。
  - **P3　多压一条**：首页 → 提醒，侧滑回首页，再前进到提醒，点“‹ 设置”：执行 replace，历史变成 [设置, 设置]。在首页侧滑时会原地退一次，看起来没反应。
  - **P4　日历二级页倒退**：同样的走法在日历二级页上，HEAD 版的 `history.back` 调用 1 次（对），新代码 0 次（多压一条）。
  - **刷新**：点进提醒后刷新页面，再点返回，执行 replace，历史变成 [设置, 设置]。
- 不会退出 App：只有本次挂载里点进来过，才会调用 `goBack()`，所以上一条一定还在本 App 里。这一点检查过，没有问题。
- 建议改法：同 H1，改用 `history.state` 记号就一并解决。

### M2　“点进来的返回走 history.back”没有任何测试拦着

- 位置：`src/features/settings/__tests__/settings-remind.test.tsx:84-93`。用 `history.length === before + 1` 判断“没多压历史”，可是 push 一条再 replace 一条，长度同样是 +1，区分不出 back 和 replace。
- 变异结果（在副本里改源码，跑 settings、calendar、reminders 三个目录的全部测试）：
  - M1：`backFromSub` 一律 replace，**存活**
  - M10：`openSub` 不记记号，**存活**
  - 也就是说，二级页“返回会多压一条”这种回归，现在的提醒、日历、注销测试都发现不了。
- 建议：在“点进来再点返回”的用例里 `vi.spyOn(window.history, 'back')`，断言它被调用过；或者返回后再 `history.back()` 一次，断言地址离开了设置。H1、M1 的三种走法各补一条。

## 低

- **L1　回到首页后焦点丢失**（`SettingsPage.tsx` 首页分支）：从二级页返回首页时，焦点会落到 body，读屏要从头再读一遍。建议记下是从哪个入口点进去的，回首页后把焦点放回那一行，比如 `settings-remind-entry`。注销、日历二级页现在也是这样，可以一起做。

- **L8　`:empty` 不占位只在 jsdom 里看了 childNodes**：CSS 有没有生效，jsdom 里验证不了。建议在 `b2-*` 的 e2e 里加一条，日历页没有未同步记录时，断言 `.unsynced` 的高度是 0。
