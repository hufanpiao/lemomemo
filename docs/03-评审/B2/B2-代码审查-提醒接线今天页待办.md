## 逐项结论

### 1. armedSince 的生命周期

- **写入**：`useReminders.ts:218-223`，在引擎的挂载 effect 里写入 `since.current`，也就是 App 在 `RemindersFor` 第一次渲染时记下的时刻（`App.tsx:99`），和引擎判断“本次打开以后”用的是同一个值。
- **清除**：卸载时清成 null。换账号时 `RemindersFor` 以 userId 作 key 重新挂载：同一次提交里，旧引擎的 cleanup（写 null）先跑，新引擎的 effect（写新的 since）后跑，不会残留旧账号的值。StrictMode 下挂、卸、再挂，结果也一样。
- **刷新**：armedSince 只存在模块内存里，刷新后从 null 开始，不会残留。
- **会不会写入太早**：挂上那一刻，集合可能还没从本机库读出来，队列是空的，这时就已经写了 armedSince。不过 `missed` 会把 since 及以后到点、还没响过的都滤掉，所以列表后到的那一次渲染也不会闪。这一点用 T6 验证过：把写入挪到排队 effect 之前，测试照过，行为也没有变化。也就是说，头注释里“写在上面那个 effect 后面”这个顺序并不起作用，写着也无害。

### 2. missed(since) 能不能消掉闪

- **算法**：`reminder-model.ts:182` 只留下两种：`dueAt < since` 的，以及 rang 里有的（本次打开以后响过的）。`ringing` 的条件是 `dueAt ∈ [since, now]`，两边边界一致：`dueAt == since` 的归横幅，不算错过。
- **逐种情形看了一遍：**
  - 打开前就到点的：算错过，正确。
  - 打开以后到点、还没排进队列的那一次渲染：被滤掉，不闪。这就是 REMIND-missed-flash 的本体。
  - 收起的：rang 里有，又不在队列里，算错过。RemindViews 的用例验证过。
  - 响着的时候改了默认时刻（R-336 ②）：rang 里有、tag 变了，按当时实际响的时刻算错过，和原来一样。
  - 别的设备补建了一条、到点时刻已经过了、但在 since 之后的：会进横幅，不会进错过，也不会丢。
- **会不会漏**：一条提醒要“从不进 rang，又在 since 之后到点”，引擎就得在 `[since, now]` 期间一次都没跑过它。引擎每分钟都会跑一次，所以只有引擎没挂上时才会这样。这时 armedSince 是 null，`missed` 不做 since 过滤，照旧全算。不会漏。

### 3. 今天页会不会永远挂不上

- 引擎正常时，最晚约 5 秒挂上：首屏画完，再等空闲，最多到硬上限。
- 引擎出错时就永远挂不上，见 M1。
- 提醒功能本身没有“功能关掉”的开关，App 不看任何开关，`Reminders` 只看有没有 userId，所以这一点不成问题。

### 4. 未同步提示和行尾标记

- `today-notice` 常驻，带 `role="status"`，提示是后填进去的，读屏能播报（T10 被拦住）。待办页只有行尾标记，没有提示，和线框一致。
- 每行一个 `useSyncExternalStore` 加一个 Suspense，和日历页上一轮的 L4 一样，一天或一个列表的行数不多，可以接受。这一版没有重复订阅的问题。
- 但这两样东西只依赖 outbox，和引擎无关，却也等引擎挂上，见 M1。另外日历页的同一组件是不等引擎的，两边行为不一致。

## 你点名的两个重点

### QuietBoundary 会不会吞掉不该吞的错误、会不会重试死循环

- **范围**：React 的错误边界只接渲染、生命周期里抛出的错误，事件处理函数和异步里的错误接不到。它只包着提醒那几个懒加载块，也就是错过的提醒、未同步提示、每一行的行尾标记，不会把页面本身的错误吞掉。V1（不接错误）被 `today-remind-chunk-fail` 拦住。
- **不会死循环**：`failed` 一旦变成 true 就不再复位。`React.lazy` 加载失败后会把失败记住，之后再渲染也是当场抛同一个错，不会重新下载。离开今天页再回来，会重新挂载一次，当场再失败一次就停，最多一次。新出现的行，各自的边界也只失败一次。
- **问题见 N1**：吞掉的错误不记日志。

## 新问题

### 中

- **M2　弹层分包下载失败以后，再点也打不开，整个会话都是这样。**
  `MissedReminders.tsx` 第 32 行是模块级的 `const MissedSheet = lazy(loadSheet)`。React.lazy 第一次拿到被拒绝的 Promise 以后会把这个错记住，之后每次渲染都直接抛同一个错，不会再调 loader。所以 `loadSheet` 里的 `sheetLoad = null` 和 `<QuietBoundary key={tries}>` 换 key 重挂，对点开这条路都不起作用。第 4 行注释写的“重点一次重挂一次”并没有做到。
  探针（在独立副本里，让 loader 第一次失败、之后成功）：在**点开时**第一次下载失败，接着连点三次，loader 一共只调了 1 次，弹层一直没出来。如果是**预取**失败，就能恢复，因为预取直接调 loadSheet，没经过 lazy。
  影响：离线时点了一下“错过 N 条提醒”，之后恢复联网也打不开，只能刷新整页；那一行还一直留在今天页上。
  建议：每次重试都新建一个 lazy，例如 `const Sheet = useMemo(() => lazy(loadSheet), [tries])`；或者不用 lazy，自己用 state 管加载状态。再补一条测试：“点开时第一次下载失败，再点一次能打开”。
