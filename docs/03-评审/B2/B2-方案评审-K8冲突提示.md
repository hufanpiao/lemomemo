## 一、总体判断

方案的现状调查扎实：`main.tsx` 丢掉 facade、无人订阅 onEvent，gone 项常驻 outbox 可跨重启对账，“先入队后丢弃”的顺序，首屏 0 字节的取向，都是对的。**方案 A 的方向我认可**，但挂法缺几样和主 App 对齐的东西；恢复数据流有两处会出错（同一条记录多个 gone 项、非用户内容表也弹恢复卡），还有一处架构违规（跨功能 import `data/conflict-fields.ts`）。按现稿实现会过不了 lint，也会出现“恢复了一半修改”“被别的设备移除的设备行让用户恢复”这类问题。

**结论：不通过（6.5 / 10）。** 必改 6 条（H1～H3、M1～M3），改完只需复审改动部分。

## 三、重点问题的回答

### 1. 方案 A 还是方案 B；单独 createRoot 会不会脱节

- **选 A。** B 的代价不只是首屏约 0.2 KB（余量 0.6 KB 要留给 FA-7），还要在 `ui-store` 加字段、App 订阅，首屏多一份订阅代码；A 的门和宿主都不进首屏。另外，FA-7 方案写明 App.tsx 现在就归前端 A，“碰 FA-7”这条理由其实不成立，真正的理由是首屏字节。
- **单独 root 逐项核对：**
  - 深浅色、皮肤：皮肤变量在 `<html>` 上，跟随，不脱节。
  - 语言：`useT` 读 `useUi`（zustand 全局），切语言时宿主跟着重画，不脱节。
  - 动效：`Appear` 自带 `LazyMotion` 和 `MotionConfig`，单独 root 照样能用，方案说法属实。
  - 跳页：`router.ts` 的 `navigate`、`useRoute` 全局可用。
  - **会脱节的**：主 App 的 modal 弹层（M4）、页面内的撤销条（M5）、错误边界（L3）、路由感知（L4）、live region（M3）。都能在宿主一侧用 CSS 和极小改动补上，不需要进 App 树。
- **更好的挂法**：容器 `<div data-sync-notice>` 由 gate 在 after-paint 时**提前建好**（里面放常驻的空 live region），宿主下载后对这个容器 `createRoot`。这样同时解决 M3 的播报问题，DOM 顺序固定在 body 末尾、Radix Portal 之前（Dialog 的 Portal 后插入，层级在上，符合 M4 的预期）。不建议把宿主塞进 RemindHost 之类现有子树：职责混在一起，换账号时序也不一样。

### 2. 恢复数据流

| 情形 | 现稿 | 判断 |
|---|---|---|
| 正常 | 入队 → discard | 对，但要按记录合并（H1）、走 write.* 的原子入口（M2） |
| 同一记录多个 gone 项 | 分卡、各恢复各的 | **错**，会丢修改（H1） |
| 自己的修改是撤销 | 恢复成 undone: false | **错**，复活两边都要删的记录（M1） |
| 多标签页 | 第 1 步复查挡大部分 | 有空隙；原子入口后才真正只生效一次（M2） |
| 离线 | 入队成功、等联网发 | 对；但补拉没到时恢复会引出一张冲突卡（M6） |
| 校验拒收 | 卡上提示、可再点 | 临时失败对；永久拒收不该一直给按钮（M8） |
| discard 失败 | 内存记下，下次启动再出卡 | 不安全，可能复活后来又删掉的记录（M2） |
| 换账号 | write 回 switching，按失败处理 | 对；页面随即重载，卡不会留到新账号 |
| 行被硬删（墓碑、30 天清理） | dropServer 连带删 gone 项 | 对，卡随 subscribe 收起 |

会不会**重复恢复**：现稿在 discard 失败、两页并发时会；改成 M2 的原子入口后不会。会不会**丢修改**：现稿在 H1、M1 两种情况下会；其余顺序正确。

### 3. 交互与可访问性

- 一次一张、排队写“还有 n 条”：合理。gone 卡不自动收起、冲突卡 8 秒收起：合理，但计时只在可见、无弹层、卡真正显示时走（M3、M4），排队中的不计时。
- 同记录合并：conflict 要按列合并（L1）；gone 也要按记录合并（H1）。
- gone 卡长时间不收起会把后面的冲突卡压住：建议冲突卡排在 gone 卡前面显示（冲突卡 8 秒就走），gone 卡始终留在最后。
- 焦点：提示卡不抢焦点，对；“看对方的版本”用 kit Dialog，焦点进出和还焦点都已做好，对。键盘用户要能找到 gone 卡：容器加 `role="region"` 和 `aria-label`（“同步提示”），读屏可按地标跳过去。
- 读屏：见 M3。gone 卡第一次出现时播报 t1 + t2；“还有 n 条”只在数量变化时更新，不要每秒重播。
- 减少动态效果：`Appear` 已处理。

### 4. 架构规则
