## 零、结论

**有条件通过，8/10。**

防钓鱼句中韩都自然、口吻和正文一致（해요체、“～해 주세요”），接在结尾空一行读起来顺；五封加、③不加的取舍我同意；首尔、上海、东京三条固定说法韩文地道，时间整句读得通；没有串语言（在 Node 上）、没有重复、韩文标点和空格对。

**必改 1 条（改动很小）**：线上跑的 Deno 对部分表外时区给出拉丁字母混排的说法，例如 `Pacific/Honolulu` 在 Deno 2.9.8 下是“**Honolulu 시간**”“**Honolulu时间**”（Node 给的是“하와이 알류샨 표준시”）。这是韩文信 / 中文信里夹英文城市名，属于语言串了；而且 Deno 和 Node 不一样，现有单测（拿同一运行环境的 Intl 当期望）在 Node 上测不出来。要加一道“说法里有拉丁字母就不用”的判断（UTC 除外），并把夏威夷放进固定表。

其余是建议：中文固定说法“首尔时间”“东京时间”改“韩国时间”“日本时间”；把常用表外时区写进固定表（消掉 Node / Deno 差异和夏天写“표준시”的问题）；中文模板里“）”后面的半角空格去掉；中文防钓鱼句“柠檬记 App”统一成“柠檬记”。

## 一、防钓鱼句（NO_LINK_NOTE）

六封信（首尔时区）逐句读过，全文结构：正文 → 空一行 → 防钓鱼句；标题都不带这一句；只出现一次；中韩不串。

| # | 原文 | 建议改法 | 理由 | 严重程度 |
|---|---|---|---|---|
| N-1 | （韩）이 메일에는 링크가 없어요. 레모 앱을 직접 열어 확인해 주세요. | 维持 | 해요체，请求用“～해 주세요”，和五封正文同一口吻；“직접”点出“自己打开、不要点别处”，意思到位。接在每封最后一段后面空一行，读起来像信末附注，顺 | 通过 |
| N-2 | （韩）同上，接在“…레모 앱을 열어 로그인한 뒤 “계정 복구”를 눌러 주세요.”之后 | 可选：이 메일에는 링크가 없어요. 레모 앱에서 직접 확인해 주세요. | ②、②'、④、⑤ 的最后一段都是“레모 앱을 열어 …”，紧接着又一句“레모 앱을 직접 열어 …”，“앱을 열어”连出两次，略显重复。改成“앱에서 직접 확인”就不重复，意思不变。不改也能用 | 建议（可选） |
| N-3 | （中）这封邮件里没有任何链接，请直接打开柠檬记 App 查看。 | 这封邮件里没有任何链接，请直接打开柠檬记查看。 | 句子自然，“没有任何链接”语气够明确。但五封正文都只写“打开柠檬记登录”“打开柠檬记”，没有“App”；同一封信里前后叫法统一更像正版信。韩文正文本来就一律“레모 앱”，所以韩文不用跟着改 | 建议（低） |
| N-4 | 结构：`noted()` 用 `\n\n` 接在正文后 | 维持 | 各封最后一段之后都正好空一行，没有多出空行或少空行；导出信“지역: …”之后的空行结构也没被打乱 | 通过 |

**语气补充**：⑤导出信最后一段是“지금 바로 …눌러 주세요”（急），接一句平静的“직접 열어 확인해 주세요”，语气上是从“马上做”回到“确认方式”，没有冲突。

**可选的更强写法（不要求）**：现在这句只说“这封信没有链接”。如果想教会用户“凡带链接的都是假的”，可以写成制度句：“레모는 계정 안내 메일에 링크를 넣지 않아요. 레모 앱에서 직접 확인해 주세요.” / “柠檬记的账号通知邮件不会带任何链接，请直接打开柠檬记查看。” 好处是用户以后收到带链接的冒牌信更容易识破；代价是要改测试里钉住的原句。负责人觉得现在这句够用就不动。

## 二、“五封加、③不加”的取舍

**同意。**

- ①②②'④⑤ 都要求或可能要求用户去 App 里做事（恢复账号、退出其他设备），正是冒牌信最爱模仿的“请点这里处理”的场景，加这一句收益最大。
- ③“已注销”账号已删，App 里没有东西可看，“레모 앱을 직접 열어 확인해 주세요”放进去反而让人困惑（打开了也登录不了）。
- 唯一要注意的：冒牌信也可能冒充③（“账号已删除，点此恢复”）。如果以后改成第一节末那种“制度句”，③可以只加前半句（“레모는 계정 안내 메일에 링크를 넣지 않아요.”），不带“打开 App 确认”。现在的写法下③不加是对的。

## 五、前端恢复页（auth.restore.when / purgeWhen）

现状：`purgeWhen` 把 IANA 名原样塞进 `{zone}`，恢复页显示“2026년 11월 7일 12:00 (Asia/Seoul)에 완전히 삭제돼요”“2026年11月7日 12:00（Asia/Seoul） 后彻底删除”，和邮件口径不一致——用户先收到信写“한국 시간”，打开 App 看到“Asia/Seoul”，正是第一份审校担心的“信和 App 对不上”。

建议前端照改：

1. **`purgeWhen` 的 `zone` 改成时区说法，不再是 IANA 名**。说法和邮件**同一张表**：把 `fixedTzLabel` / `tzLabel`（含 3.3 的表、T-7 的拉丁字母判断）挪到前后端都能 import 的 `shared/`，邮件和恢复页共用，免得两边各维护一份。若要守 A20“文字只放词典”，就在 `auth` 词典里加时区键、`purgeWhen` 返回键名（表外的仍用 Intl 结果）：

   | 键 | ko | zh |
   |---|---|---|
   | `auth.tz.seoul` | 한국 시간 | 韩国时间 |
   | `auth.tz.shanghai` | 중국 시간 | 北京时间 |
