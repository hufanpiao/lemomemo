## 重点问题

### 1. 计数会不会漏减
按 9d40848 的 `AppearList.tsx` 逐条过了一遍：
- 进场：`onAnimationStart` 时开始记，`onAnimationComplete`（`entered`）时减。Motion 在 animate 等于 initial 时提前报一次“完成”，那次会先减、真正淡入开始时再开始记，次数是平的。
- 退场：exit 动画同样触发 `onAnimationStart`；播完以后元素被移除，卸载时的清理把还挂着的一份减掉。不会减两次，因为 `end` 先查 Map，没有这一项就直接返回。
- 动画被打断（新动画接着开始）：同一个 key 再 `begin`，只重置看门狗，不重复加计数。
- 结束回调没来（实例被换掉、Motion 没报）：2 秒看门狗兜底。
- StrictMode 开发版的“挂—卸—挂”：第一次卸载时 Map 还是空的，没有多减。
- `Math.max(0, …)` 防止减成负数；`typeof document` 判断让 SSR 和测试环境里也安全。
- 结论：找不到会一直关着的路径。剩下的一点风险：如果 `markAnim` 以后有了第二个调用方、开和关不配对，计数被别人减成 0，会把别人的标记也摘掉——见 L1。

### 2. 看门狗和多条动画重叠
- 看门狗按“每一项 × 每一类”各一个，计数是全局的，所以多条动画重叠时 `data-anim` 会一直挂到最后一条结束（或者它的看门狗到点）。
- 某一项的看门狗提前到点，只减掉它自己那一份，不影响别的项。
- 用户连续打勾时，`data-anim` 可能持续好几秒：这期间模糊一直关着，回到 M1，连续操作时看起来更明显。
- 看门狗只防“某一份一直挂着”，不限制 `data-anim` 总共挂多久，这是对的（动画确实一直在跑）。
- 2 秒对 0.3 秒左右的动画留了足够余量。CI 主线程很忙的时候，Motion 的结束回调可能晚于 2 秒，那时看门狗先摘、回调晚到时什么也不做，不会出错。

### 3. 打勾时模糊一关一开会不会闪
会，见 M1。补充：
- 顶部两层也跟着关，而顶部这一块状态栏下面多半有字，比底部更容易看出来；
- `data-vt` 那一档是上一轮切页时已经接受的（底栏换实色、切页本来整页在变），和打勾这种局部小动作不一样，不能拿来类比说“看不出来”。

## 低 L

- L1 `src/motion/index.ts`（补丁新加的 `markAnim`）：计数是全局的，又对外导出，以后谁多调一次 `false` 就会把别人的标记摘掉。可以改成返回释放函数（`const release = holdAnim()`，重复释放不再减），比裸的 `markAnim(true/false)` 更不容易配错。
- L2 `AppearList.tsx`：`useAnimMark` 里的 `m` 和外层导入的 `m`（`motion/react` 的 `m`）同名，局部遮住了外层，读的时候容易看混，可以改个名。
- L3 `<html>` 上的属性一变，WebKit 可能整页重新算样式；每次动画开始和结束各一次，代价不大，CI 上测性能时顺带看一眼。
