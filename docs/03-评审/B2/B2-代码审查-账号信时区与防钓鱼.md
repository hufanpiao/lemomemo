### 1. 照抄、不走注入：可以接受

- `safeTz` 只依赖 Intl、没有表，抄过来的是三行同样的 Intl 调用，比给四封信再加一个注入参数简单。理由和文件头一致：这份要在 Vitest 和 tsc 里跑，那时 `_shared/gen/` 还没生成。
- 一致性断言（`account-mail-nolink.test.ts`：23 个输入逐个比 `safeTz(z) === canonicalTz(z) ?? 'Asia/Seoul'`）能拦住大部分走样。变异 M2（`safeTz` 退回“只校验、原样回”）红 2 条。
- **不足**：输入里没有“前后带空白”的写法（`'Asia/Seoul '`、`' Asia/Seoul'`）。变异 M1 让 `canonicalTz` 先 `trim()`、`safeTz` 不跟着改，两边已经走样，**一致性断言照样通过**。最后是 `tz-canonical.test.ts` 里“`'Asia/Seoul '` 回 null”那条把它拦住的，靠的是钉住 canonicalTz 这一边，不是比两边。
- 另外，长度上限 64 两边各写一份（`TZ_MAX_LEN`、字面量 64）。改成 128 时，因为 Intl 本来就不认这么长的名字，两边结果仍一样，不算真走样。
- 建议（L5，低）：一致性输入补 `'Asia/Seoul '`、`' Asia/Seoul'`、`'\tUTC'`、`'Asia/Seoul\n'`，以后哪边改了空白处理，这条都会红。

### 2. 运行环境不同，说法会不会对不上

- **邮件这边**：`safeTz`、`tzLabel` 跑在 Deno（V8，和 Node 同一套 ICU），会把别名归到规范名，比如 `ROK→Asia/Seoul`、`US/Eastern→America/New_York`、`Asia/Kolkata→Asia/Calcutta`。Deno 和 Node 的结果逐条一致，上面的 Deno 测试已证实。
- **恢复页这边**：跑在用户浏览器里。iPhone 的 WebKit 只统一大小写、别名原样返回（上一轮实测）。于是同一个别名，两边可能出现不同说法：
  - `US/Eastern`：邮件是“美国东部时间”；iPhone 恢复页 `fixedKey` 对不上，落到 Safari 的 Intl 说法。
  - 说法退回 IANA 名时：邮件写 `Asia/Calcutta`，iPhone 写 `Asia/Kolkata`。
- **实际影响小**：
  - `current_tz` 是 App 用本机 `resolvedOptions().timeZone` 写进去的，iOS 给的一般是规范 IANA 名，别名很少见；
  - 恢复页本来就用本机时区、邮件用 `current_tz`，人在外地时两边时区就可能不同，这是原来的设计；
  - `ROK`、`PRC`、`Japan` 等别名 `fixedKey` 里已有分支，WebKit 下也对得上。
- 结论：不是本批引起的问题。上一份审查的 T2（`fixedKey` 补 `US/*`、`GB`、`Asia/Saigon` 等常见别名分支，只加 case 不加词条）同时解决这一点，仍然是低建议。

### 3. L4 解析会不会误判

- **做法**：先去掉注释，在 `Deno.serve(` 之后找 `handle(req, {`，按括号深度和引号切出对象字面量的顶层成员。自测覆盖了注释、嵌套对象、字符串、对象在 `Deno.serve` 之外这几种情况。
- **变异 M3**：把 `tzLabel` 挪进 `extra: { tzLabel }`，红。
- **已知的局限**：
  - 正则字面量里的引号（如 `/['"]/`）、模板字符串 `${}` 里再套反引号，会让“引号状态”判断错；
  - `handle(req,{` 少一个空格就找不到对象。
- **这些局限都偏安全**：判断错时只会把后面的成员吞掉，或者返回 null，结果是测试变红（误报），不会凭空认出一个不存在的 `tzLabel`（漏报）。再加上 `Deps.tzLabel` 是必填，有 `deno check` 兜底，可以接受。
- 建议（低，可不改）：在注释里写明“判断错只会偏红”，免得以后有人当它是完整解析器。

### 7.2 顺带查出的问题（存量问题，不是这次引入的）

做“有没有错归”时，我把表外时区也一起比了，发现 `intlGeneric` 用 `formatToParts(0)` 取通称。也就是说，它按 **1970 年 1 月 1 日** 那天的时区归属来说。Node 实测，418 个时区里有 162 个在 1970 年和现在的说法不同，其中有些会被说成别国的时间：

- Europe/Kyiv（Kiev）、Riga、Tallinn、Vilnius、Chisinau、Kaliningrad，都被说成“莫斯科标准时间 / 모스크바 표준시”，按现在的归属应该是东欧时间。WebKit 和 Chromium 的结果一样，基辅三端都说“莫斯科标准时间”；
- Asia/Gaza、Asia/Hebron 被说成“以色列标准时间”，现在应该是东欧时间；
- Asia/Thimphu 被说成“印度时间”，应该是不丹时间；Asia/Pontianak 被说成印尼中部时间，应该是印尼西部时间；
- 还有很多时区，按现在的归属取不带“标准”二字的通称，但取 1970 年会拿到“…标准时间 / …표준시”，比如 Europe/Amsterdam、Asia/Beirut，这和文件开头“不写 표준시 / 标准时间”的初衷相反。

账号信是防钓鱼的安全提醒，把乌克兰、波罗的海用户的时区说成“莫斯科”，把加沙说成“以色列”，既说错了，也敏感。修法只要一行：取通称时改用当下时刻（`formatToParts(Date.now())`），或者传入信里那个时间点。然后补一条用例，断言 Europe/Kyiv 的说法不含“莫斯科 / 모스크바”。
