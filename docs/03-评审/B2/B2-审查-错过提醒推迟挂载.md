## 二、重点四件事

### 1. 引擎一直不 armed、也不报错：会永远不显示（必改 M1）

- `armedSince` 只在 `useRemindEngine` 的挂载 effect 里写（useReminders.ts 第 148～151 行）；`remindDown` 只在 App 的 ErrorBoundary `onError` 里写（App.tsx 第 168～173 行）。
- RemindHost 分包的 import **挂住不返回**（弱网、强制门户、TCP 卡住，浏览器的模块请求没有超时）时，Suspense 一直等，既不 armed 也不报错。`app-remind-host.test.tsx`“提醒分包一直没到（R5）”就是这个状态，测试只断言页面照常，没断言错过的提醒。
- J1 口径下这时还会按 openedAt 显示；改成 P2 以后，这一种情况下“错过的提醒”在这次打开里永远不出来，而引擎没挂上、提醒也不响——正是 L9 担心的“页面上唯一的信号”没了，只是触发原因从“出错”换成了“卡住”。
- 后面接 `remind_seen` 以后 armed 要等 IndexedDB 读完，IDB `open` 被别的标签页的升级挡住（onblocked）时也会一直不返回，方案写的“读失败照常 armed”盖不住“读不返回”。
- 改法（任选，需主持人点头的话先问）：RemindersFor 在 ready 以后起一个看门狗（比如 15 秒）没 armed 就写 `setRemindDown(true)`（或另设 `remindLate`，按 down 的口径显示）；armed 以后清掉。补两条用例：pending 模式下过了看门狗时间 remindDown 为真、今天页挂出错过的提醒；在时限内 armed 的不触发。IDB 读那一步也加超时，超时按读失败处理。

### 2. 引擎出错这条路：基本覆盖

- 渲染出错、分包 reject 都进 ErrorBoundary → `setRemindDown(true)`；`app-remind-host.test.tsx` 有“出错记进 remindDown、换账号清掉”。分包 reject 没有单独用例（替身只有 throw / pending），但 React.lazy 的 reject 和渲染抛错走同一个边界，不扣分。
- 今天页：`today-remind.test.tsx`“引擎出错（M1）”断言 remindDown 时挂、清掉时撤；MissedReminders：RemindViews 两条断言不筛、快照空也照样显示。
- 出错时先写 down、后在被删除的 RemindHost 的 effect 清理里写 `armedSince = null`，两者同一次提交里发生，`missedOn` 不会出现一帧 false；没发现闪退。
- useRemindEngine 里异步出错（Promise 被吞）不会进边界，但 armed 在挂载时已经写了，这时按 armed 口径显示，不会“永远不显示”。

### 3. 改测试口径时有没有删掉能抓错的断言

- 新口径的断言都在，而且能抓回退：TodayPage 退回 `openedAt !== null` → today-remind“只有 openedAt 不挂”失败；去掉 `|| remindDown` → “引擎出错（M1）”失败；MissedReminders 不看 remindDown 或不传 since → RemindViews 的 L9 和“只算 E2”失败。
- **丢了一处覆盖（必改 M2）**：`today-remind-chunk-fail.test.tsx` 只调 `setRemindOpenedAt(1)`，新口径下 `MissedReminders` 根本不挂，“错过提醒的分包下不来时只把那一块去掉、整页不换出错页”这条已经不再被测到（测试照样绿，等于空测）。改法：beforeEach 里改成 `setRemindArmed(1)`（再加一条 `setRemindDown(true)` 的，正好是“引擎坏了 + 分包也下不来”的离线组合），并断言 `today-missed` 容器在、里面没有按钮。
- 其余：RemindViews 的“错过的提醒照线框”用 `armedSince = MAX_SAFE_INTEGER` 不筛，只用于版式，可以接受；“引擎出错：有打开时刻也不按它筛”里的 openedAt 现在没人读，这条断言实际只在测 remindDown，不算错但标题会误导（建议改标题）。

### 4. 分包下载失败时怎么处理

- MissedReminders 分包失败：外层 `QuietBoundary name="missed"` 吞掉、记一次日志，那一块不画，`.missed:has(> button)` 不留 8px。这次打开不重试：`MissedReminders` 是 index.ts 顶层的 `lazy`，React.lazy 记住失败，换账号重新挂也还是同一个失败的 lazy。以前首屏就下载（在线时多半成功），现在推迟到 armed 以后，下载时机更晚，离线概率略升。属于已接受的取舍（QuietBoundary 头注释写了），建议：失败后像 MissedSheet 那样换新 lazy，下次 armed / remindDown 变化时重试一次。
- 弹层分包（MissedSheet）：预取失败清掉、点开换新 lazy 重下，再失败只那一下没反应、那一行在，`MissedSheetLoad.test.tsx` 覆盖，没问题。
