## 协调者点名的六个问题

**1. 洛杉矶夏令时（3/8、11/1）落进跳过时段或重复时段：处理正确，有测试。**
- 全天提醒走 `msAt`，规则是：落在拨快跳过的那段，按拨快后的时间算（02:30 → 03:30）；落在拨慢重复的那段，取先出现的那一次。
- 20:00 和 09:00 本身不会落进这两段。只有用户把 `remind.default_time` 设成 02:xx 或 01:xx 才会碰到，测试里两种都有（第 72、75 行）。
- 切换日当天的“前一天 20:00”，和前一天的提醒只差 23 小时，也测了（第 67 行）。

**2. 免打扰推迟后“今天 / 明天”的判断：正确。**
- `notifyText` 用 `allDay.at`，也就是推迟以后的时刻，按 `current_tz` 和日程日期比是哪一天。
- 前一天 20:00 被 19:00～07:00 的免打扰推迟到当天 07:00，会写“今天”。这符合实际：收到通知时已经是当天了。
- 推迟到日程过后（比如 `default_time` 23:30，免打扰推到第二天）会只写名称，符合“其余只写名称”。
- 本机通知传的是 `r.dueAt`，它已经经过 `applyDnd` 推迟；tag 里仍然用推迟前的时刻，和服务器一致。

**3. `remindAtOf` 加第 6 个参数后，原来只传 5 个参数的调用：有时刻的日程和待办行为不变；全天日程从“不提醒（null）”变成“按 09:00 算”，这是这次要做的事。**
- 待办分支没动。有时刻的日程分支不看 `tz` 和 `defaultTime`，结果和原来一样，测试第 111 行验证过。
- 只传一行、不传 tz 的旧 `eventRemindAt(row)` 仍然返回 null（第 104 行）。
- 现在仍只传 5 个参数的调用点有三处：`event-edit.ts` 第 183、188 行和 `today-actions.ts` 第 44 行。它们只用结果判断“还会不会响”，全天当天提醒按 09:00 判断，见 L1。

**4. 本机通知和服务器文案能不能一致：shared 这边做到了，服务器要按同一个约定接。**
- 两边共用 `notifyText` 和同一套词典键。本机 `localText` 传 `allDay: { date, at: 推迟后的 dueAt }`。
- 服务器那边要满足三点：
  - 传 `allDay: { date: 日程日期, at: 推迟后的 due_at }`；
  - tz 用 `current_tz`；
  - 有时刻的日程不传 `allDay`。
- `push-dispatch/index.ts` 第 28 行已经把 `defaultTime` 传进去了。
- 后端增量审查时要核对的一点：`supabase/functions/_shared/gen/` 下的 `logic/notify-text.ts`、`i18n/zh.ts`、`i18n/ko.ts` 现在还是旧副本，没有 R-334 的三个键和分支（`logic/remind.ts` 已经同步）。要在提交前跑 `copy:shared`，否则服务器发出的隐私模式文案会和本机不一样。

**5. `today-actions` 从写死 'UTC' 改成 `current_tz`，有没有影响别的路径：没有。**
- 原来传的 'UTC' 只有 `remindAtOf` 会用到，而有时刻的日程分支不看这个 tz，所以有时刻日程的结果不变。只有全天日程会用到新传进来的 tz。
- 两个调用方（`useToday.ts:71`、`useTrash.ts:23`）都传 `currentTz()`。待办这一支（`remindAfterDelete`）本来就收 tz，没改。
- 测试补了全天日程删除、恢复的五种情况。
