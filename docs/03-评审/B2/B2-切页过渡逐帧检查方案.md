# B2 切页过渡逐帧检查方案

> 测试评审员（只读）写于 2026-11-06。起因：负责人在 iPhone 主屏幕版从“今天”切到“日历”时截到过渡中途的画面（`底栏透明度截图/真机-70d94f5-切页过渡残影.png`），有三个问题，现有 Playwright、vitest 和设计评审都没抓到：
>
> - **P1 旧页残影**：旧页的字（“11月6日 周五”“今天没有日程”“今天的安排”“今天没有安排”）半透明压在新页（月历）上；
> - **P2 直角灰块**：底栏 `.bar` 和“＋” `.fab` 后面各露出一块直角灰色矩形，比圆角胶囊大一圈；
> - **P3 药丸糊成一团**：底栏选中液滴（药丸）停在“今天”和“日历”之间，看着像两颗叠在一起、边缘发糊。
>
> 本文只讲“怎么在过渡途中逐帧查出来”，不讲怎么修；前端 B 正在改 `src/`，下面提到的 CSS 行号以 11-06 傍晚的版本为准，可能已经变了。

## 1. 现有测试为什么漏掉

### 1.1 逐条看断言

| 测试 | 断言的是什么 | 为什么抓不到 P1～P3 |
|---|---|---|
| `src/motion/__tests__/view-transition-css.test.ts` | 读 `base.css` 文本：`::view-transition-old/new(root)` 的时长是 `--dur-sheet`、曲线是 `--ease-standard`；`page-head` 先出后入的关键帧百分比；减少动态效果时不起过渡；起过渡那一刻 Pressable 带 `data-snap` | 只查“写了哪个令牌”，不查画面。整页 root 的新旧两份**同时**交叉淡入淡出（380 ms），50% 时旧页字还有约一半不透明——这本来就是 CSS 写出来的样子，测试反而把它当成“正确”锁住了。`page-head` 那套“先出后入”只用在设置几屏的顶栏，今天/日历/待办的正文没有 |

### 1.2 R1 那条截图测试的四个漏洞

1. **只查“少了”，不查“多了”。** 判据是“中途那张更像没画底栏的那张”，灰块是多出来的东西，不在判据里。
2. **圆角外的像素被排除了。** 只数“画着”和“没画”差 > 32 的像素（`dist(q, z, j) <= 32` 就 `continue`）。胶囊圆角外面那 4 个角，过渡结束后画着和藏起来都是页面底色，差 ≈ 0，**正好被剔掉**——灰块恰恰就长在这里。底栏外一圈（灰块比胶囊大的那部分）也不在截图 clip 里。
3. **停的时刻是 0%，不是中途。** `waitForFunction` 一看到伪元素动画就 `pause()`，此时 `currentTime ≈ 0`；后面 `waitForTimeout(700)` 只是等液滴（真元素的 CSS transition，不归 VT 管）滑完。所以截到的是“旧页 100%、新页 0%”的那一刻，底栏又是“液滴已滑到位”，P1（50% 前后的叠影）和 P3（过渡前段旧快照里的液滴 + 新快照里正在滑的液滴叠在一起）都不在这一帧里。
4. **引擎画不出 P2。** `B2-底栏透明度-真机差异排查.md` 根因 2 已记：Playwright 在 Windows 上的 webkit 根本不画 `backdrop-filter`。灰块推测是 iOS 合成器把带 `backdrop-filter` 的元素截成快照时，把背景模糊区（可能连阴影的 ink overflow 一起）截成了矩形——这一步桌面 webkit 和 Chromium 都可能不复现。另外 chromium 项目用的是 `Desktop Chrome` 设备改 375 宽，不是触屏、DPR 1。

### 1.3 设计评审为什么也没抓到

- ②b 动效审查要求“证据必须是录屏或性能分析截图”（`docs/00-团队/人员名单.md` 136 行），但没规定**切页过渡要逐帧看**。380 ms 的过渡以 30 fps 录屏只有 11 帧，正常速度看过去只会觉得“闪了一下”。
- iPhone 清单 P2-10 已经写了“切页约 0.4 秒里底栏玻璃里的内容和背后短暂对不上，是已知可接受的”——这句话等于预先把“过渡中底栏看着不对”归为可接受，负责人和评审都容易放过。建议改写（见第 4 节）。

## 2. 可行的自动检查

### 2.1 核心手段：把过渡定在 25% / 50% / 75%

新建 `tests/e2e/b2-vt-frames.spec.ts`（名字可改），375×812，`loggedIn: true`，chromium 和 webkit 两个项目都跑。

```ts
// 点页签前装好：一出现过渡就全部暂停（含液滴的 CSS transition、果冻 WAAPI），记下过渡总时长
async function freezeOnStart(page: Page) {
  return page.waitForFunction(() => {
    const all = document.getAnimations();
    const vt = all.filter((a) => String((a.effect as KeyframeEffect | null)?.pseudoElement ?? '').startsWith('::view-transition'));
    if (vt.length === 0) return 0;
    for (const a of all) a.pause();
    return Math.max(...vt.map((a) => Number(a.effect?.getComputedTiming().endTime ?? 0)));
  }, undefined, { timeout: 2000, polling: 'raf' }).then((h) => h.jsonValue() as Promise<number>);
}

// 定到过渡的 frac（0～1）；所有动画按同一条“真实时间”对齐：
// VT 380 ms、液滴 550 ms，真机上第 t 毫秒两者各走到 t/380、t/550，不能各自按百分比定
async function seek(page: Page, total: number, frac: number) {
  await page.evaluate(([t]) => {
    for (const a of document.getAnimations()) a.currentTime = t;
  }, [total * frac]);
  await page.evaluate(() => new Promise((r) => requestAnimationFrame(() => requestAnimationFrame(r))));
}
```

要点：

- **不要只暂停 VT 的伪元素动画**（现有 R1 的做法），要把 `document.getAnimations()` 全部暂停、按同一绝对时间定位；否则液滴会自己滑完，P3 的那一帧永远截不到。液滴的 `pointerdown` 比 VT 开始早几毫秒，误差 ≤ 1 帧，可接受。
- 如 `currentTime` 在某引擎对 VT 伪元素无效（Playwright webkit 的 `pause()` 已证实有效，`currentTime` 需第一次跑时确认），退路是 `playbackRate = 0.05` 让过渡放慢 20 倍，再按 `performance.now()` 算到 25/50/75% 时截图。
- 每帧截整屏（`animations: 'allow'`），沿用 R1 的 CSP 截图豁免写法和空白页解码 PNG 的办法。
- 同时开 `recordVideo` + `playbackRate = 0.1` 录一段 3.8 秒的慢放视频挂到报告里，给 ②b 当证据。

### 2.2 三项像素判据

每个切页组合、每个时刻（25%、50%、75%）都查。参照图：同一组合过渡放完、停稳后的整屏（记作 END），以及点之前的整屏（记作 START）。

**判据 A：底栏和“＋”圆角外 4 个角点是背景色（对应 P2）**

1. 点之前读 `.bar`、`.fab` 的 `getBoundingClientRect()` 和计算后的 `border-radius` r。
2. 每个角取 3 个采样点：从外框角往里 `(0.25r, 0.25r)`、`(0.15r, 0.4r)`、`(0.4r, 0.15r)`——都在圆弧外、外框内；再在外框外 4 px 的四条边中点各取 1 点（查“比胶囊大一圈”）。
3. 每个点在 25/50/75% 帧里的颜色和 END 帧同一点比：各通道差 ≤ 12（阴影本来就落在这些点上，END 里也有，所以比 END 而不比纯 `--bg`）。
4. 再加一条“直边”检测：沿外框上沿下方 2 px 的横线，从 `left − 8` 到 `left + 0.3r` 取一串像素，相邻像素差不得出现 > 8 的台阶（圆角胶囊这里应是渐变的阴影，灰块会在外框线上出一条直边）。
5. 门槛 12、8 是估值，**第一次跑要用 bug 版本校准**：在独立副本（worktree，不在共享工作区改）里把修复退回到 70d94f5 的 CSS，确认判据会红；修好的版本确认会绿。

**判据 B：旧页文字区在 50% 以后看不见（对应 P1）**

1. 点之前在 START 上收集旧页的文字框：`main` 里所有非空文本节点用 `Range.getClientRects()` 取矩形（今天页至少有日期标题、“今天的安排”、空状态那几行）。
2. 在这些矩形里找“文字像素”：START 和 END 同一点差 > 40 的像素（新旧两页这里不一样的点）。
3. 50%、75% 帧里，这些像素中“离 START 比离 END 近”的比例必须 < 2%；25% 帧只记录、不判（看修法是“先出后入”还是“不交叉”而定，跟前端 B 对齐后再定 25% 的门槛）。
4. 便宜的 DOM 辅助判据（两引擎都能跑，不靠截图）：在 50% 时读 `::view-transition-old(root)` 那条动画的 `effect.getKeyframes()` 和 `getComputedTiming().progress`，算出当前不透明度应 ≤ 0.05。截图判据红而 DOM 判据绿，说明是引擎画法问题，转真机。

**判据 C：选中药丸只有一颗、位置连续（对应 P3）**

1. 点之前读每个页签 `a[data-tab]` 的中心 x，以及液滴 `.drop` 的颜色（START 帧液滴中心取样）。
2. 在每帧沿底栏中线（`bar.top + bar.height/2`，再加上、下各 6 px 共 3 条线）横扫，标出“像液滴颜色”（与液滴色差 ≤ 16 且与 END 里同位置的非液滴底色差 > 16）的像素，求连通段。
3. 要求：每条扫描线上只有 **1 段**，宽度在一格页签宽的 0.8～1.25 倍之间（果冻拉伸会变宽，上限按 `--ease-drop` 的过冲再定）；段中心 x 在 25% → 50% → 75% 单调地从旧页签移向新页签，不回退、不分叉。
4. 旧快照里的液滴和新快照里正在滑的液滴叠在一起时，会出现 2 段或 1 段过宽，判据红。

### 2.3 哪些 Linux webkit 能测、哪些只能真机测

Playwright 的 WebKit 在 Linux 上是 WPE/GTK 端口，和 iOS 的 CoreAnimation 合成器不是一套；Windows 上的 webkit 已知不画 `backdrop-filter`。第一次接入时先跑一个探针（同根因 2 的“有无切页名字对比”：同一位置去掉模糊，截图有无差别），确认 Linux webkit（CI）画不画 `backdrop-filter`，再定下表最后一列。

| 检查 | chromium（本机/CI） | webkit Windows（本机） | webkit Linux（CI） | 只能真机 |
|---|---|---|---|---|
| 判据 B 旧页残影（截图 + DOM） | 能 | 能 | 能 | 再看一眼即可 |
| 判据 C 药丸一颗、连续 | 能 | 能 | 能 | 再看一眼即可 |
| 判据 A 灰块（截图） | 能跑，但大概率不复现（Chromium 快照不按这个方式截模糊区）——作回归防线 | 不画模糊，测不出 | 待探针：画模糊的话可作参考，但合成器不同，**绿了也不能当通过** | **是**：灰块以真机为准 |
| 判据 A 的结构替代：带 `view-transition-name` 的元素同时带 `backdrop-filter`、`box-shadow` 时，必须在 base.css 里对它的 `::view-transition-old/new` 有明确处理（例如登记在一个白名单并附真机截帧日期） | 静态 vitest（像 `vt.test.ts` 那样扫 CSS）即可 | — | — | — |
| 切页途中点按 | 已有（R4、b2-vt-taps） | 已有 | 已有 | 再看一眼 |
| 深色、自动深浅（`data-ad`）、减少透明效果（`data-rt`）、减少动态效果（`data-rm`）下的三项判据 | 能（用 `colorScheme` 和 data 属性切） | 能（A 除外） | 能（A 除外） | 灰块各主题都要真机看 |
| 首屏后备档（GlassBarFx 未到）vs 到了以后 | 能（冷启动第一次切页 vs 之后） | 能 | 能 | 真机冷启动看一次 |

注意：Playwright webkit 设备是 `iPhone 15` 仿真，只是 UA、视口、DPR、触屏仿真，渲染仍是桌面 WebKit，不等于 iOS Safari。

### 2.4 跑法和端口

- 不新开环境：沿用 `playwright.config` 的 webServer（`wrangler pages dev`，端口按配置）。评审员本次没有跑，避免动 `.wrangler/state-e2e`；以后单独试跑脚本，端口只用 8850–8859。
- 新 spec 每个组合截 3 帧 + 2 张参照，12 个组合 × 2 主题约 120 张，webkit 4 并发时给 `test.setTimeout(180_000)`；失败时把 25/50/75% 三帧和 END 拼成一张挂到报告（`test.info().attach`）。

## 3. iOS 真机检查清单

### 3.1 怎么看

- iPhone 主屏幕版（不是 Safari 标签页），设置 › 辅助功能 › 动态效果里“减少动态效果”关。
- 控制中心开屏幕录制，每个组合切 3 次；录完在电脑上抽帧：`ffmpeg -i 录屏.mp4 -vf "select=between(t\,开始\,开始+0.5)" -vsync 0 帧_%03d.png`，或在相册里拖进度条一帧帧看。过渡约 0.38 s，60 fps 录屏约 23 帧，**至少看过渡开始后第 3、6、11、17 帧**（约 15%、25%、50%、75%）。
- 每个问题截一帧存 `docs/03-评审/B2/底栏透明度截图/真机-<提交号>-<组合>-<主题>.png`。

### 3.2 组合

| # | 从 → 到 | 说明 |
|---|---|---|
| 1–6 | 今天 ↔ 日历、今天 ↔ 待办、日历 ↔ 待办（双向） | 主场景；负责人发现的是“今天 → 日历” |
| 7–9 | 今天 / 日历 / 待办 → 随手记 | 随手记“即将推出”、没有“＋”：看“＋”的快照怎么消失（`:only-child`） |
| 10–12 | 随手记 → 今天 / 日历 / 待办 | “＋”从无到有 |
| 13 | 今天 → 设置（右上角头像）→ 返回 | 底栏整条消失/出现 |
| 14 | 日历月视图 ↔ 周视图切换后再切页 | 日历页高度不同，灰块位置和背后内容不同 |
| 15 | 待办页滚到中间（底栏背后有字）→ 切到今天 | 背后有内容时灰块和模糊最明显 |
| 16 | 冷启动后第一次切页（首屏后备档） | GlassBarFx 还没到 |
| 17 | 切页途中连点第二个页签 | 打断：液滴不分叉、不跳回 |

### 3.3 主题和设置

每个组合在 **浅色** 和 **深色** 各做一遍；组合 1、2、15 额外做：底栏停在深色项目卡片上（自动深浅 `data-ad=dark`）、系统“降低透明度”开（实色档）、“减少动态效果”开（应直接切换、没有过渡，三项都不该出现）。

### 3.4 每帧看什么

| 点 | 通过 | 不通过（截帧） |
|---|---|---|
| A 灰块 | 底栏、“＋”四个圆角外和外沿一圈和页面底色一致，只有柔和阴影 | 有直角矩形、比胶囊大一圈的色块、矩形直边 |
| B 旧页残影 | 50% 以后看不到旧页任何字；前半段如有淡出，字不压在新页字上读得出来 | 旧页字半透明叠在新页上 |
| C 药丸 | 任何一帧只有一颗液滴，边缘清楚，从旧页签滑到新页签 | 两颗叠影、中间糊成一团、跳回再滑 |
| D 底栏在 | 每一帧底栏和“＋”都在，图标和字清楚 | 某几帧消失、闪白 |
| E 收尾 | 过渡结束那一帧没有“跳一下”（颜色、模糊、位置突变） | 结束瞬间底栏变样 |
| F 其他元素 | 页头分段控件（周/月）、日期胶囊不出现双影 | 有双影 |
