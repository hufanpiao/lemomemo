- 审查人：独立设计审查员（只读，默认不通过，10 分制，8 分及以上才算通过）
- 日期：2026-11-04
- 标准：review-animations（有理由才动、频率合适、ease-out、≤ 300 ms、可中断、只动 transform 和 opacity、减少动态效果、进出不对称）
- 依据：

  - 截图：`docs/02-设计/当前界面截图-1104/` 里的 6 张“动效-…-连续帧”

## 结论：7/10，不通过

单个零件做得规范：打勾圆圈、行进出场、按下回弹、弹层快收，用的都是 ease-out 或抽屉曲线，单段都不超过 247 ms，只动 transform 和 opacity，两种减少动态效果的开法都处理了，离开途中的行不接点按。

问题出在几段动画**串起来**的时候：
- 打勾时，“已完成”组先往下让出一块空白，过了约 440 ms 又往上收，同一块内容来回动了两次；
- 撤销恢复的第一帧，新出现的行和下面的标题叠在一起；
- 打勾这种高频操作，从点下去到页面完全停稳约 650 ms，偏长。

下面 M1～M3 修掉、重交连续帧，我预计能到 8 分。

## 一、问题

### 中

- **M1 待办页打勾：新行还看不见就先占了位置，“已完成”组先往下跳、后往上收。**
  - 连续帧《待办打勾》：22 ms 时“回邮件”紧贴在“已完成”标题下面；89～206 ms 它已经往下挪了约 20 px，标题和它之间空出一行，这时“整理照片”还没出现（它的进场晚 `--dur-ui` 才开始）。
  - 到 440 ms 以后，“没有日期”整组卸载，“已完成”组又整体往上收。
  - 原因：`AppearItem` 的 `delay` 只推迟了 opacity 和 transform，元素一挂上就占了布局，`layout="position"` 让下面的行立刻 FLIP 让位。
  - 结果：圆圈还在填满时，下面先出现一块空白在动，用户的视线被拉走，正好和“先看到打勾、随后才离开”的设计意图相反。
  - 建议：打勾时新行等 `--dur-ui` 以后再挂进“已完成”组（推迟的是挂载，不是动画），或者用 `AnimatePresence mode="popLayout"`，让离开和进入同一刻换位。
- **M2 撤销恢复：新行淡入的头几帧，压在下面的“已完成”标题上。**
  - 连续帧《撤销恢复》32 ms：“已完成”四个字和正在淡入的“买牛奶”叠在同一个位置，字压着字。
  - 原因：新行一挂载就占了位置，下面的行被 FLIP 拉回旧位置再滑下去，这段时间两块重叠；新行的 opacity 用的是 ease-out，前段升得快，所以叠在一起的样子看得见。
  - 建议任选一种：
    - 新行的淡入晚约 1/3 再开始（等下面的行让开一部分）；
    - 新行进场时盖在上层、带页面底色（z-index + 背景），让被拉回的行从它下面滑过；
    - 新行只淡入、不加上移，并把 opacity 曲线换成前慢后快。
- **M3 打勾整段约 650 ms，三段完全串行，对高频操作偏长。**
  - 两页的连续帧一致：
    - 0～220 ms：圆圈填满；
    - 220～440 ms：这一行（今天页是整组）淡出；
    - 440～630 ms：下面的行再收上来。
  - 圆圈填满后停一下再离开，这个停顿有理由，见第三节第 1 条。但“淡出播完才开始收拢”这一段可以去掉：建议收拢和淡出同时开始（`popLayout`，或者离开那一刻就把它移出文档流），整段压到约 440 ms。
  - 删除也是同样的串行（淡出 0～220、收拢 220～440）。删除是用户主动的一次性操作，440 ms 可以接受；改成 `popLayout` 后会一起变快。

### 低

- **L1 打勾时同一条待办短暂出现两份。** 待办页 272～389 ms：“没有日期”里那条还在淡出，“已完成”里那条已经出现。时间很短，看起来像“挪过去”，可以接受；M1 改成推迟挂载以后，两份同屏的时间会更短。只记一笔。
- **L2 离开途中不能再点圆圈反悔。** 行进入 leaving 以后不接点按（这样防误点，是对的），所以点错了以后有约 440 ms 改不回来。如果打勾没有撤销条，请确认这是负责人认可的行为；有撤销条就不算问题。

## 三、主持人要我判断的问题

1. **打勾后约 280 ms 行才离开，节奏对不对：对。** 圆圈在约 100～150 ms 已经基本填满（ease-out 前段快），用户先看到“勾上了”，停一下再离开，能分清“确认”和“挪走”两步；如果立刻离开，用户会以为点没点上就消失了。这个停顿留着，问题在后面的尾巴（M3）和停顿期间下面的行先动了（M1）。
2. **删除时下面的行收上来，会不会和别的动画叠：删除本身不叠**（淡出播完才收拢，两段串行；撤销条在页面另一处、各管各的）。**打勾时会叠**：新行一挂载，“已完成”组就先让位，之后上面的组卸载时它再收拢，同一块内容来回动了两次（M1）。**撤销恢复时会叠**：让位的 FLIP 和新行淡入的头几帧压在一起（M2）。
3. **打勾这类高频操作的动画是否过多：数量不多，时间偏长。** 圆圈填满是必要的反馈；行离开、挪到“已完成”是必要的空间说明，都有理由。要减的是时间和多余的位移：去掉 M1 的提前让位，把收拢和淡出并到一起（M3），整段约 440 ms，并且整段只有一次位移。别再加别的效果（比如勾号描线、行背景闪一下）。
4. **今天页、待办页布局有没有被动效改坏：停稳以后没有改坏。** 连续帧最后一帧和改动前的布局一致：行距、组标题、右侧 ×、“没赶上”的红框卡片都正常；包了 m.li 和 m.section 以后，原来的 className 没丢。只在过渡途中有 M1 的空白和 M2 的重叠。
