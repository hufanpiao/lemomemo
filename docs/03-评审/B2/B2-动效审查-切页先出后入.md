## 四个重点逐条

### 1. 先出后入的时长、曲线，空白那一下像不像闪屏

像。原因不是“先出后入”本身，而是曲线：`--ease-standard` 是一条重减速曲线，套在旧页 0–40% 这一段上，旧页 100 ms 时已经只剩 5%，后面 50 ms 都在“淡一个已经看不见的东西”；套在新页 40–100% 这一段上，开头又是慢启动，新页到 170 ms 才 9%。两头一夹，约 66 ms（60 fps 下 4 帧）整屏只有纯底色，正常速度下读起来就是“闪一下白”。交付说明写的 30–40 ms 偏乐观。

另外，底部四个页签是最高频的操作，380 ms 的整页淡入淡出本身就偏长；同类产品（iOS 原生 Tab 栏）切页签是不做过渡的。缩到 `--dur-ui`（220 ms）是建议，不是必改，交设计定。

### 2. 底栏“实色 → 玻璃”在过渡结束时是不是硬跳

是硬跳。`:active-view-transition` 一摘，`backdrop-filter` 和着色同一帧换回去；复现图 `bar-chromium` 第 2 行“379 ms → 结束后 380 ms”底栏从不透明白一下变成透出后面的条纹。真 App 里日历页底栏后面正好压着“11月6日 周五 · 农历九月廿八”那张卡，这张卡会在过渡结束那一帧突然从底栏里冒出来，正好落在逐帧方案第 3.4 节 E 点（“结束瞬间底栏变样”）。而且这时液滴还在滑（液滴 550 ms，过渡 380 ms），底栏材质的跳变和液滴运动叠在一起，更显眼。

开头那一下（玻璃 → 实色）也是硬切，但它是为了让旧快照截到实色，必须同一帧发生，可以接受；而且开头用户的注意力在手指和液滴上。

修法（复现页已验证可行，见 `bar-chromium` 第 4 行“结束后 220/260/320 ms”是渐变）：不直接改着色层，在 `.bar`、`.fab` 里加一层实色遮罩，过渡中 `opacity: 1` 且 `transition: none`，平时 `opacity: 0` 且带 `transition: opacity var(--dur-glass) var(--ease-out)`。这样进入是瞬间的（满足截快照），退出是 300 ms 淡出；模糊在遮罩下面一帧恢复，被遮罩盖住看不出来。

### 3. 液滴在过渡中是否还是一颗、连续地移向新页签

- **Chromium：通过。** 新的那份 `::view-transition-new(tabbar)` 是实时画面，实色着色把旧快照里的液滴完全盖住，任何一帧只有一颗，位置从“今天”单调滑向“日历”（复现 `bar-chromium` 前两行）。
- **Windows 版 webkit：不连续。** 整个过渡期间液滴一直停在“今天”，过渡结束那一帧直接跳到“日历”附近（复现 `bar-webkit` 前两行；前端 B 的 `-webkit.png` 下排也是液滴从 0% 到 99% 都停在“今天”，选中文字也一直是“今天”）。原因就是 base.css 里已记的“webkit 过渡期间不画新的那份”：看得到的只是旧快照，而它现在是不透明的，所以是一颗，但是冻住的。
- **iOS 真机：未确认。** 修前真机截图里药丸停在“今天”和“日历”之间且两颗叠着，说明 iOS 会画新的那份；那么修后应当和 Chromium 一样是一颗、连续。但这一条只能真机逐帧确认（逐帧方案 3.4 的 C 点，组合 1–6、17）。真机若和 Windows 版 webkit 一样冻住再跳，这条升为必改。

### 4. 减少动态效果

通过。`src/motion/index.ts` 的 `transition()` 在 `prefersReducedMotion()`（系统设置或 `data-rm="1"`）时直接执行、不起 View Transition，所以既没有空白帧，也不会进入 `:active-view-transition` 的实色；液滴在 `prefers-reduced-motion` 和 `data-rm='1'` 下 `transition: none`、不放大，两条来源和 `reduced.ts` 一致。减少透明效果（`data-rt`）时平时就是 `--glass-solid`，过渡前后一致，没有跳变。

### webkit 截帧不能证明 iOS 上不叠字（S3 补充）

前端 B 的 `第二版-webkit.png` 里，新页 35% 那一帧已经是完全不透明（Chromium 同一帧还近乎全空）。我上一轮的复现图 `UI4复现-先出后入-full-webkit.png` 更明显：40 ms 时新页就已经完全不透明，旧页是叠在它上面淡出的。也就是说，Windows 版 Playwright webkit 不按 `lemo-head-in` 画新页，和底栏那条“webkit 过渡期间不画新的那份”是同一个原因。

### 新增：顶部状态栏衬底（html::after）跟着整页淡掉

**判断：要处理（M5）。**

- **影响：** `html::after` 是状态栏白字的衬底（R-349，主屏幕版、浅色皮肤 `--status-scrim: rgba(20,21,24,.42)`；深色皮肤是透明的，不受影响）。它在整页快照里，所以跟着旧页淡出、跟着新页淡入。叠起来算，衬底强度 = 1 − (1 − 旧)(1 − 新)：
  - 低于一半的时间约 135 ms（约 30–165 ms）；
  - 低于 80% 的时间约 180 ms。
- **为什么要管：** 状态栏的时间、信号是系统画的，不在快照里，一直是白字。这 135 ms 里，白字底下只剩浅色页面底色，几乎看不清，每切一次页签顶部就“闪”一下。负责人主要用 iPhone 主屏幕版、浅色，正好是受影响的组合。这一下比整页空白的 36 ms 长得多，也更靠近视线。
- **为什么不能当已知代价放过：** 衬底本来就该是“不随页面变”的东西（和底栏一样），跟着页面淡出属于归错了快照，不是先出后入本身必须付的代价。

**改法（任选其一，都只改 base.css）：**

1. **推荐：** 在 `::view-transition` 上铺同一条衬底渐变，例如 `background: linear-gradient(to bottom, var(--status-scrim) 0, var(--status-scrim) calc(var(--inset-top) * 0.7), transparent var(--inset-top)) top / 100% var(--inset-top) no-repeat;`。
   - 原理：`::view-transition` 在整页新旧两张快照下面，快照不透明时盖住它（快照里本来就有一份衬底），快照淡没时露出它。合成结果在整个过渡中保持一份衬底的浓度，不会变成两份叠加。
   - 自定义属性从 `html` 继承下来，`--inset-top` 能用；减少动态效果时不起过渡，不受影响。
2. 把衬底从伪元素挪到一个真元素上（放在 `#root` 外），给它一个登记过的 `view-transition-name`，比照 tabbar 写 `animation: none`。改动比 1 大，要同步改 `vt.ts` 的名字登记。

验收：Chromium 定格 35%、40% 两帧，顶部 `--inset-top` 高度内的颜色和 0%、99% 一致（可以用 `--inset-top` 模拟成 47px 来看）；真机浅色录屏逐帧，状态栏时间每一帧都清楚。

顶部模糊带（`html::before`、`body::after`）同样在快照里会一起淡，但淡掉时它下面的页面内容也在淡，看不出差别，不用处理。

- **B 报的那一处（Chromium 20%–35% 状态栏区能看到旧页内容，糊得比平时轻）：** 属实，原因也清楚。具名元素在过渡层里是单独画的，它的 `backdrop-filter` 取不到底下整页快照的完整背景，所以这段时间模糊比平时弱，透出的是正在淡出的旧页。不拦，理由三条：
  1. 只出现在旧页淡出的那一段（0–35%，约 130 ms），透出来的内容本身已经降到一半以下的不透明度，而且还在继续变淡；
  2. 35% 以后旧页没了，新页刚进来时顶部一般是页头和底色（新页都从顶部开始），没有内容压在带子下面，看不出模糊强弱；
  3. 要彻底消除，就得在过渡中给顶部带补一份模糊，成本和收益不成比例。
  
  它不是上一轮那种“每次切页顶部闪一下”，记为已知代价即可。

**仍需真机确认（并入 S3，不新增必改）：**

1. iOS 上带 `backdrop-filter` 的具名元素截进过渡快照，正是 P2“直角灰块”的成因。底栏为此在过渡中关掉了模糊。顶部两层现在也是“具名 + `backdrop-filter`”，宽度占满整屏，看不到圆角处的直角，但 iOS 可能不按 `mask` 截，**在带子下沿（安全区 + `--top-fade` 处）出一条硬边的灰带**。
   - 真机浅色、深色各切几次，看顶部带下沿有没有直边或灰带。
   - 有的话，照底栏的做法，在 `:root:is([data-vt], :active-view-transition)` 下给 `.lemo-top-8`、`.lemo-top-2` 设 `backdrop-filter: none`。代价是过渡中顶部不模糊，和现在 Chromium 上“糊得轻”的观感差不多。
2. 删了灰色衬底以后，状态栏白字只靠模糊衬托。这是负责人的决定（备用底色 `--status-tint` 默认关），静止时白字是否看得清，要上真机看，不归本次动效审查。

**本轮必改：无。** 真机逐帧（S3，含上面第 1 条）仍是 B2 验收前必做。

### 结论

**Block（不通过）——6.5 / 10**

- 底部带：通过。
- 真机反馈的第一条（底栏先不透明再透明）：确实没了。
- 拦的原因：方案 A 换来了一个更显眼的问题——液滴在过渡结束那一帧瞬移。并且“冻住的快照换回实时玻璃”在 iOS 上大概率也是一帧跳变。

这两处都是方案 A 本身的结构决定的，修补的余地有限，所以本节最后建议走方案 B。

### 1. 液滴先停住、后接着滑：不能接受（N1，必改）

“结束后接着滑”与实际不符。液滴的 CSS 过渡从按下那一刻就开始了，用的是 `--dur-drop` 550 ms 和 `--ease-drop`，并没有因为 View Transition 暂停：

- 旧快照在起过渡时截下，液滴这时只走了约 8%–15%（`--ease-drop` 在 10–20 ms 时的进度是 0.08–0.15）；
- 过渡 380 ms 期间，画面上的液滴一直冻在这个位置；
- 过渡结束换回真底栏时，液滴的 CSS 过渡已经走到 380 / 550 = 69% 的时间，`--ease-drop` 在这里的进度是 **1.045**，已经冲过了目标；
- 剩下 170 ms 只是从 1.045 回弹到 1.0。

所以用户看到的是：液滴在旧页签停 0.38 秒，然后**一帧之内跳过约 90% 的距离**，再轻轻回弹一下。今天 → 日历跳一个页签宽度，今天 → 随手记跳三个。前端 B 的 Chromium 证据正好如此：“过渡 99%”液滴还在“今天”，“结束后 50 ms”已经在“日历”。选中页签的字重（600）也在同一帧从旧页签换到新页签。

液滴是底栏上唯一表示“我点到了哪里”的东西，它在 0.38 秒里不动、然后瞬移，比上一版的“不透明一下”更像出错。这是 0.38 秒内唯一在动的反馈，不能冻。

在方案 A 里能做的补法（需要预览验证，本次没验证）：

- 给液滴单独起一个 `view-transition-name`（例如 `tabbar-drop`，登记进 `VT_FIXED`）。它就不在底栏的快照里了，有自己的组。
- 组默认会把位置从旧矩形补间到新矩形，时长、曲线写成 `--dur-sheet`、`--ease-drop`；新快照同样设 `opacity: 0`，只画旧快照（webkit 本来也不画新的）。
- 起过渡时（`data-vt`）把真液滴的 `transition` 设成 `none`，让它直接到位。过渡结束换回真液滴时，位置正好对上。
- 代价：过渡中没有果冻；webkit 上旧快照随组移动这一点必须在 Playwright webkit 和真机上都确认。

### 2. 冻住的快照换回实时玻璃：会跳（N2，必须真机确认）

- **Chromium：** 旧快照里烘进去的是点按那一刻、旧页内容的模糊（证据里 0%–20% 底栏里是“NEOX 第 15/16 条”的糊影），结束那一帧换成新页内容的实时模糊。底下内容不同时会换一下；液滴瞬移、字重换位也在同一帧，几处叠在一起更显眼。
- **iOS：** 按 WebKit bug 302256，过渡期间根本不画 `backdrop-filter`。旧快照是具名元素单独截的，等于只有 62% 的白色着色、没有模糊，下面正在淡入淡出的页面会**不加模糊地**透出来；结束那一帧模糊一下子回来。日历页底栏后面正好压着日详情卡，这就是“底栏后的字先清楚、后变糊”的又一个来源，和负责人这次反馈的第二条是同一类观感。
- Windows 版 Playwright webkit 不画模糊，判断不了，只能看真机 60 fps 录屏逐帧，重点看结束前后各 3 帧。
- 能做的补法很有限：结束后让 `backdrop-filter` 从 `blur(0)` 过渡到原值，大约 `--dur-glass`。这只对 iOS 有意义，在 Chromium 上反而会制造一次反向跳变；`backdrop-filter` 做过渡也贵。不建议在方案 A 上继续堆补丁。

### 3. 底部带的清晰度曲线：通过

- **改后单调，没有回升：** 两条曲线（底栏这一列、底栏和“＋”之间）从带子顶边（约 74 pt）一路往下降，约 110 pt 起贴近 0，一直保持到底；只有最后 2 pt（198 pt 以后）露出一点，在 Home 指示条那一带，可以忽略。
- **改前的两处毛病都消失了：** 85–95 pt 有一段停在 15 不再变糊；底栏和“＋”之间过了底栏顶边以后完全不糊（55）。
- **斜率均匀：** 下降段大约 35 pt，没有台阶，往上拖时不会再“先清楚、一下子变糊”。
- **真机确认：** 条纹测的是 Chromium；三层模糊的叠加在 iOS 上应该一致，但要在真机录屏里再看一次往上拖的那段，录屏条带第 342–357 帧那种跳变不应再出现。

### 对方案 B 的意见：值得做，建议采用

方案 B：页签切换不走 View Transition，用 WAAPI 给 `main` 做过渡，底栏一直是实时的。

从动效上看，B 一次性去掉了这一路所有问题的根源。这一路的问题——直角灰块、液滴叠影、实色遮罩、冻结快照、液滴瞬移、过渡中没有模糊、顶部带在快照里变轻——全是“底栏和顶部带被截进 View Transition 快照”这一件事带出来的，而且都卡在 WebKit 的 bug（302256、不画新快照）上，没有可以等的修复。B 让底栏、液滴、顶部带都不进快照：

| | 方案 A（现在） | 方案 B |
|---|---|---|
| 底栏材质 | 过渡中冻住，iOS 上没模糊，结束时跳回 | 一直是实时模糊，没有切换点 |
| 液滴 | 停 0.38 秒后瞬移 | 按 `--dur-drop` 和 `--ease-drop` 连续滑，带果冻，可以被下一次点按自然打断 |
| 灰块、叠影 | 靠裁圆角和只画旧快照压住 | 不存在 |
| 顶部模糊带 | 具名快照，前段变轻 | 实时 |
| 页面 | 先出后入，有约 36 ms 空白 | 见下面的建议做法，没有空白 |

建议的 B 做法：

- 只对四个页签互切走这条路，其他切页（设置、注销、详情）照旧用 View Transition。
- 不做旧页淡出，避免为了淡出把旧页面 DOM 留着、并多等一段。直接换成新页面，然后给 `main` 做一次淡入：`opacity 0 → 1`，`--dur-ui` 220 ms 或更短，`--ease-out`（可以加 4–6 px 的 `translateY`，交设计定）。页签切换是最高频的操作，快、直接、没有两页同屏，最合适；iOS 原生 Tab 栏连淡入都没有。
- 打断：再点一次就 `cancel()` 上一个动画、从当前帧开始新的，WAAPI 天然支持；减少动态效果时不放动画。
- 只动 `main`（不透明度，合成层属性），不碰带 `backdrop-filter` 的元素，主线程负担比 View Transition 截整页快照还小。

代价在工程侧：`router.ts` 的 `commit()` 要为页签开一条路，`b2-tabbar-transition`、`b2-vt-taps`、`vt-press-snap` 等依赖 View Transition 的测试要改写。这个工作量我判断值得，否则 iOS 上底栏在每一次切页都要带着妥协。要不要做由主持人定。

### 本轮必改

- **N1：** 液滴在过渡中冻住、结束时一帧瞬移约 90% 的距离。改法二选一：按上面第 1 条给液滴单独起名字补间（需 webkit 和真机验证），或者采用方案 B。
- **N2（真机确认，可能升为必改）：** iOS 过渡结束那一帧，底栏从“无模糊的着色”跳回“实时模糊”；Chromium 则是烘进去的旧模糊换成实时模糊。方案 A 里没有干净的修法，采用方案 B 就不存在。
- 底部带：通过，不用改。

### 2. 新页只淡入、不做旧页淡出，220 ms 合不合适：合适

- 按 `--ease-out`（`.23,1,.32,1`）算，从 1/60 秒处起播，各时刻的不透明度依次为：

  | 时刻 | 17 ms | 33 ms | 50 ms | 100 ms | 150 ms |
  |---|---|---|---|---|---|
  | 不透明度 | 0.31 | 0.56 | 0.74 | 0.95 | 0.99 |

  名义上 220 ms，**眼睛感受到的约 100 ms**：第一帧就有内容，3 帧过半，6 帧基本到位。测量图里 Chromium 最低 0.31，webkit 最低 0.58（帧取样晚一点），都没有空白帧。
- 不做旧页淡出是对的：旧页一点即走，手指落下后的第一帧就是新页，响应感最好；也就不需要为了淡出留着旧页面的 DOM。这是高频操作该有的分寸：比 iOS 原生的直接切换只多了一点“软着陆”，不拖沓。
- 跳过第一帧的写法（`currentTime = FADE_SKIP_MS`）解决了“opacity 0 那一帧整页空白”，对。不建议再加位移，保持现在这样就好。
- 连点时 `cancel()` 后在新页上从 0.31 重新起播，前一页的淡入被打断，不会两个动画抢同一个元素；液滴的 CSS 过渡会自然改向，从当前位置滑去新目标。
- 分包没到时，React 先留着旧页（webkit 实测约 50 ms），`fadeSwap` 只认换上来的新 `main`，等到再淡，最多 1.5 s，超时就不淡。逻辑对。
- 减少动态效果：只换页、不动，液滴 `transition: none`。通过。

### 3. 液滴末尾约 4 pt 的回弹：接受

- `--ease-drop`（`.34,1.45,.5,1`）在约 55% 时间处冲到目标的约 104.5%。一格页签约 65 pt，回弹 3–4 pt，测量图上峰值约 88.5、终值约 84.5，和计算一致；大约 300 ms 到峰，520 ms 落定。
- 这是“液滴”的性格：有一点惯性才像液体，而且幅度小于液滴自身宽度的 6%，不会被看成“冲过头再退回来”的错误。
- 注意回弹按距离放大：今天 → 随手记（3 格，约 195 pt）的回弹约 9 pt，仍在可接受范围，但已经接近“看得出来”。真机连切三格时看一眼；如果嫌大，可以对长距离把 `--dur-drop` 用满、曲线不变，或另设一档过冲更小的曲线。只是建议，不是必改。

### 4. 走 View Transition 的切页（今天 → 新建日程）：没有回退，但有一处硬切（V1，必改）

- 没有回退：整页先出后入、35% 起 `--ease-out` 淡入照旧；Chromium 逐帧 40% 那一帧近乎全空、60% 新页已清楚，和第二版一致。旧快照组裁圆角、补阴影，只有一边有底栏时组上的阴影计算值为 `none`，没有“空阴影壳”。
- **V1 底栏在新页上停满 380 ms，结束那一帧整条消失。** 两个内核的 20%–99% 帧里，底栏和“＋”都完整地压在“新建日程”表单底部，“结束后”那一帧一下子没了。原因是 `::view-transition-old(tabbar / tabbar-add)` 一律 `animation: none`，在只有旧的一边有底栏时也是。点“＋”进新建页是最高频的路径之一，底栏在整页淡出后又多留 0.2 秒，再硬切，很显眼。这个行为从 FA-7 起就有，前几轮我没有指出，这次补上。
- **改法：** 只有一边有底栏时让它跟着整页走：
  - 进新建页时：`::view-transition-old(tabbar):only-child`、`::view-transition-old(tabbar-add):only-child` 用 `lemo-head-out`（时长、曲线继承 root 那条：`--dur-sheet`、`--ease-standard`），和旧页一起在前 40% 淡完；
  - 从新建页返回时：`::view-transition-new(...):only-child` 用 `lemo-head-in`。webkit 不画具名元素的新快照，返回时底栏可能仍要到过渡结束才出现，需要在 Playwright webkit 和真机上确认，最低要求是进新建页那一侧不再硬切。
  - 两边都有底栏的情况现在只剩页签互切，已经不走 View Transition，所以 `:only-child` 不会误伤其他情形。

### 需要真机看的一处（不是必改）

webkit 页签互切的逐帧图里，17–300 ms 底栏下面一直是满浓度的“11月6日 周五 · 农历九月廿八”“给客户回电话确认报价 1”（日详情卡在底栏后面），而上面的月历还在淡入。Chromium 同一位置看不出这种差别。可能是 Windows 版 webkit 不画模糊造成的画法问题：底栏和底部带取背景时取到的是没乘不透明度的 `main`。要在 iPhone 上看：页签互切时，底栏、底部带里透出来的内容是否和页面一起淡入。如果底栏里先出现满浓度的内容，影响也只是一块模糊区，不拦。

### 本轮必改

- **V1：** 进新建页这类“只有旧的一边有底栏”的 View Transition，底栏和“＋”跟着整页在前 40% 淡出（`:only-child` 用 `lemo-head-out`）。返回那一侧尽量用 `lemo-head-in`，webkit 上做不到的话记为已知限制。

### 2. 方案 B 加了 M8、M9 以后：观感和可打断性都通过

- **M8 吞点按：**
  - 只拦 `main` 里、换页后 100 ms 以内按下的点按（以及按在窗口里、松开在窗口外的那次 click），底栏不在 `main` 里，**连点页签完全不受影响**，液滴照样可以被下一次点按改向。
  - 100 ms 内新页的不透明度刚到约 0.95，人还没看清就点下去，基本是“顺手又点了一下旧位置”，吞掉是对的。被吞的点按没有按下反馈，这在 100 ms 里感觉不到。
  - `pointerdown` 上 `preventDefault` 不会挡住触屏滚动（挡滚动的是 `touchstart` 和 `touch-action`），这个窗口里开始的滑动照常。
- **M9 `cancelFade()`：**
  - 起整页过渡前先停掉页签淡入，`opacity` 回到 1，旧快照截到的是完整画面。等分包期间点了“＋”或头像，也不会把编辑页、设置页当成新页再淡入一次。
  - 同页内切换只停等待、不打断正在播的淡入，分寸对。
  - 停掉淡入时 `opacity` 会从当时的值一帧回到 1，但紧接着整页就开始淡出，看不出来。
- **观感：** 和方案 B 那一轮一样，第一帧约 0.31、体感约 100 ms，连点时每次在新页上从 0.31 重新起播，没有两个动画抢同一个元素。

### 3. 底部实色带：通过

- **渐隐：** 24 px 从透明到 `--bg`。“字往下滑进带子”10 帧里，字每帧均匀地淡一点，第 4–7 帧那一段（0–24 px）从清楚到看不见是连续的，没有上一版“先清楚、一下子变糊”的台阶。原来 54 px 半透明加 3 层模糊的“糊而不没”也没了。
- **下面是实色：** 底栏后面、底栏和“＋”之间、底栏下面都看不到字，浅色、深色、今天、日历四张都一致，深色下渐隐没有发灰的边。
- **减少透明效果：** 硬边，符合“减少透明”的本意（不做半透明过渡），通过。
- **少了 3 层 `backdrop-filter`，** 滚动时合成负担也小了。
- **建议（不是必改）：**
  1. 24 px 用的是线性 alpha，渐隐起点那条线在浅色大面积纯色上可能隐约看得出来。可以在中间加一个停点，让起点更软，例如 `transparent 0, color-mix(in srgb, var(--bg) 50%, transparent) 40%, var(--bg) 100%`，实际只是把曲线拉成缓入。真机看了再定。
  2. 玻璃皮肤页面底是 `--scr-bg` 渐变、带子是 `--bg` 纯色，底部颜色会差一点。这是设计问题，前端 B 已经写在排查文档第 11 节，不归动效。

### 4. 顶部外框：静态通过，过渡中待补一帧

- 静态诊断图里，套外框以后，顶部带下面的竖条纹照样糊；去掉两层模糊的对照是清楚的条纹，说明外框没有变成背景根，两层模糊照常起作用。
- **切页时会不会随快照淡掉：**
  - 页签互切已经不走 View Transition，顶部两层一直是真元素，不涉及快照；
  - 走 View Transition 的切页（进新建页、设置）里，两层仍各自带 `top-blur-8` / `top-blur-2` 的名字、`animation: none`。外框 `.lemo-top` 自己没有名字，也不写 opacity、filter 这类会改变截图方式的属性，所以和 M5 复查时的结论一样，不随整页快照淡掉。
