## 四、首屏瘦身 U7（第 4 点）

- **口径错了**：硬约束 2、U7-1、V2、约定 3 都用 `node build/check_size.mjs`。它只量“入口 + 静态 import”，本机产物 127.3 KB；149.8～149.9 KB 是 `tests/e2e/b2-first-screen-budget.spec.ts`“今天页出现之前开始下载的 JS”口径（B2 剩余清单第 49 行、FA7 方案第 117 行、spec 头注释都写明）。照任务单验收，V2 第一天就“通过”，起不到约束作用；真正会超线的是 e2e 口径。
- **“改成按需下载”不一定省**：e2e 口径算的是“今天页出现之前开始下载”的块。若改成 `import()` 但仍在今天页出现前触发，数字不变；还要同步 `build/check_first_paint_chunks.mjs` 的 `FIRST_PAINT_DYNAMIC` 名单和 `tests/build/first-paint-graph.test.ts`。
- **会碰首屏结构**：“首屏词典里非首屏的词条”是拆 i18n 加载方式，属首屏结构改动，0.25 人日做不完，且可能带来首帧文字闪动（G10）。任务单已写“超出就停”，但应直接把它列为“本批不做，除非包体分析证明其余几项凑不够 3 KB”。
- **撞线可能**：今天页（`TodayPage.module.css` 类名表、`Pressable`、`CheckCircle`）都在首屏块里。U4-1 换共用 CSS 模块，若今天页同时 import 两份模块（共用 + 页面私有剩余部分），类名表反而变大。每个 PR 要贴 e2e 口径数字，不是 `check_size`。
- B2 自己的返工（真机问题）也可能加首屏字节，3～5 KB 余量由谁占用没写。

## 六、和 B2 返工并行的风险（第 6 点）

### 二、主持人点名的问题：电脑端输入字号 15 → 16

**这是没人定过的视觉变化，不应该默认带进来。**

- 现状：`Form.module.css:59` 电脑上用 `--fs-15`，触屏靠 `:65～71` 改成 16；`Form.module.css:62～63` 的注释写明“只在触屏上调到 16px，电脑上仍是 15px”。这是 11-06 修 G11（iOS 聚焦放大）时的做法，负责人当时要的是“点框不放大、不横移”，没有要求电脑上也改字号。
- 影响比任务单写的大：
  - 表单 `.input/.select/.area` 在电脑上从 15 变 16，和同一行的字段名（15）不再一样大；
  - 提醒时刻框 `.time` 用 `font: inherit`，电脑上现在继承 `.timeLbl` 的 14（`RemindSettings.module.css:320～328`），会从 **14 变 16**，比旁边的说明字大两号；
  - 电脑版（B6）的编辑页整体会显得字大一号。视觉稿电脑版编辑页字段值是 14（`.fld .v`），离 16 更远。
- 没必要为过单测而改：`input-font-size.test.ts` 本来就认“触屏媒体查询里的 `font-size`”（单测第 4～6 行注释，第 158～162 行有用例），现在的代码已经全绿。第一轮 P1-5 给的另一条路——“输入框统一引用 `--fs-15`，加一条共用的 `@media (any-pointer: coarse)` 改成 `--fs-16`”——单测不用改，电脑字号也不变。
- **建议**：U1-2 改回“电脑 15、触屏 16”，媒体查询只写在 `Form.module.css` 一处；提醒时刻框和登录框复用同一个类或同一条规则，电脑上的字号写明是 15（时刻框从 14 到 15 属于“统一零件”，可接受）。这样就**不用问负责人**。
- 如果主持人或设计坚持“电脑也 16”，那就是新的视觉决定，要出电脑版编辑页、提醒页的 15 / 16 对照图请负责人定，不能写成“单测不改”的附带结果。

### 三、本轮还剩的小问题（P2）

- **P2-a 返回按钮名单**：`CalendarSettings.tsx` 里没有返回按钮（文件第 3 行注释写明顶栏和返回由设置页画），应删掉这一项。设置二级页和注销页的返回是 `SettingsSub.tsx:38`、`DeleteAccountView.tsx:52` 用的 `.backBtn`，样式在 `SettingsPage.module.css:335`（B 的文件，已列）。漏了 `FullReminderPage.tsx:72～73` 的“‹ 返回”，它在 A 的提醒目录里，应补进 U3-6 A 的那一半。
