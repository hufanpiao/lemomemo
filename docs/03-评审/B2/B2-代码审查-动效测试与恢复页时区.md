## 二、动效测试推帧（appear-transform-end、features-async-cold-list）

### 原因判断属实

`node_modules/motion-dom/dist/es/frameloop/frame.mjs`（motion 14.7.1）在模块加载时执行 `createRenderBatcher(requestAnimationFrame, …)`，把当时的 rAF 函数存进闭包。之后再调 `vi.useFakeTimers` 换掉全局 rAF，它也看不到。所以原来“假时钟推满 3000 ms”时，Motion 的帧其实还跟着 jsdom 的真实 rAF 走，机器一忙就可能一帧都没处理。这正是 CI 报“推了 3000 ms 动画时间还没到”的原因。

### processFrame 是正经 API，时间来源一致

- `processFrame` 是 motion-dom 公开导出的“手动处理一帧”接口（`frameloop/process-frame.mjs`）。官方注释写明：真实 rAF 照常也会处理帧。
- 时间戳默认取 `time.now()`，也就是 `performance.now()`，已被假时钟接管，所以动画时间轴就是测试推的时间。
- 真实 rAF 偶尔插进一帧时，`processBatch` 读的同样是假的 `performance.now()`。时间戳相同，delta 被夹到 1 ms。Motion 的 JS 动画按时间戳算当前值，同一时刻多算一次，结果一样。
- jsdom 没有 `Element.animate`，不会走 WAAPI，所以没有“跟着浏览器时钟”的分支。

### 实测

| 实验 | 结果 |
|---|---|
| 原样连跑 5 次（两个文件 14 条） | 5/5 全过 |
| A：把真实 rAF 放慢到 200 ms 一帧（`vi.hoisted` 在 Motion 加载前替换），用现行修法 | 13 条全过 |
| B：同样放慢，去掉 `processFrame()`（即原来的做法） | N1 的 sheet、toast 两条都红，稳定复现 CI 的失败 |
| C：产品代码回退 N1（`Appear.tsx` 关闭时一律当“已停稳”，`(leftSettled.current ?? false)` 改成 `true`） | 两条都红，报错是“闪回原位了：关之前 46.9，序列 16.24, 37.54 …” |

### 会不会掩盖真实问题

不会。

- 这两条用例测的是 Appear 的取值序列：退场方向、不闪回、终点。帧由谁来驱动不在它要证明的范围里。实验 C 证明真实回退照样拦得住，而且报的是正确的原因。
- 真实帧循环仍有覆盖：同一文件里其余用例（播完清 transform、减少动态效果、停稳后退场等）用的是真定时器加 `waitFor`，走的还是 Motion 自己的 rAF 循环。e2e 也在真浏览器里跑动效。
- 剩下的盲区：只有“Motion 自己的 rAF 调度出问题”这一类测不到，但那是库内部的事，不归这两条用例管。

## 三、恢复页时区说法

### 正确性

- `purgeWhen(iso, loc, tz?)` 只改了括号里的那一项：`zone: tzLabel(zone, loc)`。日期、时刻的拆法不变。
- 时区经 `safeZone` 校验，通不过就按首尔，然后才交给 `tzLabel`，和邮件 `safeTz` 的口径一致。
- `usePurgeWhen` 从 `useUi` 取 locale。登录页入口 `src/auth/main.tsx:28` 在渲染前就 `setLocale`，和页面其余文案（`useAuthT`）用的是同一个来源，不会出现“正文韩文、括号中文”。
- `auth.restore.ask` 去掉“{when} 后”中间的空格，和邮件 W-4 的写法一致（“）”后面不留半角空格）。
- 新测试覆盖 8 个时区 × 中韩共 16 组，和邮件 `fmtWhen(…, tzLabel)` 逐字比对，包括非法时区按首尔、`Asia/Kolkata` 这类表外时区。
- 登录页的包原本就带 `shared/i18n`（`useAuthT`、`ui-store`、`doc-locale`），新加的 `tz-label.ts` 只多了一个小函数，没把 zod 之类拉进来。
- `tsc -p tsconfig.app.json` 0 错。改动文件 eslint 0 错；仅有的 3 条警告在 `src/core/__tests__/boot.test.ts`，是原来就有的。

## 六、复审（2026-11-05：canonicalTz，上一份邮件审查 L1 / 本文 T1 的前端那半）

做法同前（scratchpad 独立副本，做完已删）。

- **改动**：`shared/i18n/tz-label.ts` 新增 `canonicalTz(raw)`。非字符串、空串、超过 64 个字符、Intl 抛错时回 null，否则回 `resolvedOptions().timeZone`。`tzLabel` 先过它再查固定表；`account-gate.ts` 的 `safeZone` 改用它，通不过就按首尔。
- **测试**：Node 下 `tests/shared/tz-canonical.test.ts`、`account-gate.test.ts`、`account-mail-nolink.test.ts` 共 59 条通过；`deno test tests/shared/tz-canonical.test.ts` 10 条通过。
- **变异 1**：`canonicalTz` 不规范化、原样回传，6 条红。
- **变异 2**：`safeZone` 校验通过后回原值而不是规范名，没有用例红。这不是漏洞：`tzLabel` 内部还会再规范化一次，Intl 拆出来的日期时刻也一样，`safeZone` 里那次规范化其实是多余的保险。
- **真实浏览器实测**（Playwright 自带内核，Firefox 本机启动不了，没测到）：

  | 输入 | Chromium | WebKit |
  |---|---|---|
  | `asia/seoul`、`utc` | 归成 `Asia/Seoul`、`UTC` | 同样归一 |
  | `ROK`、`PRC`、`Japan`、`US/Eastern`、`Asia/Chongqing` | 归到规范名 | **原样返回，不归并别名** |
  | `Asia/Kolkata` | 归成 `Asia/Calcutta` | 保持 `Asia/Kolkata` |
  | `Asia/Seoul `（带尾空格） | null | null |

  也就是说，WebKit 只统一大小写，不归并别名。注释里“Safari 可能回 IANA 现行名”的说法要改成“WebKit 原样返回别名”。
