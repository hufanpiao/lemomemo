## 点名的四个问题

### 1. 换账号、退出登录时会不会残留上一个账号的状态（L8）；没有会话时会不会误挂
- **没有会话不挂：对。** `Reminders` 在 `getBoot()?.userId` 为空时返回 null，测试第 47 行覆盖了。
- **换账号会整个重新挂载：对。** `ErrorBoundary key={userId}`。key 一变，RemindHost 卸载，引擎的清理函数清掉 `rangStore`、`sessionAcked`、`laterAcks`，补写的订阅也设了 `alive = false`。`remind-host-remount.test.tsx` 验证了换 key 以后 `rangSnapshot()` 清空。`app-remind-host.test.tsx` 第 53 行验证了换账号会重新挂载、同一个账号换页不会。
- **实际上起作用的是整页重新载入：** `getBoot()` 不是响应式的，`userId` 只在启动时定下来。网页版退出走 `location.replace('/app/auth/')`，exe 等会话删掉以后整页重新载入（`platform/session.ts` 第 465～481 行）。所以在真实环境里，换账号一定伴随整页重新载入，模块级状态随页面一起没了；`key={userId}` 是第二道保险，测试里用 rerender 验证它。两道一起，没有残留。
- 残留的小窗口（低，R3）：exe 退出时，主窗口最多要等 3 秒才重新载入，这期间 RemindHost 还挂着，每分钟检查一次的引擎碰上整分钟可能还会弹一条本机通知。不过退出流程先清了本机库，集合已经空了，实际上弹不出来。写进注释即可。

### 2. ErrorBoundary 和 Suspense 的位置：RemindHost 出错会不会拖垮整页，会不会让启动画面过早收起
- **不会拖垮整页。** `Reminders` 在页面的错误边界外面，有自己的 `ErrorBoundary fallback={null}`。RemindHost 渲染出错，或者分包加载失败，都只是不显示提醒，页面照常。
- **不会让启动画面过早收起。** `Reminders` 放在 App 最外层的 `Suspense` 里，和页面在一起，页面分包没到时整块都不画，提醒横幅不会抢在页面前面画出来。RemindHost 自己的分包晚到时，内层 `Suspense fallback={null}` 什么也不画，也不会触发收起启动画面。
- 代价有两条（低）：
  - R1：切到一个分包还没加载的页面时，外层 `Suspense` 会把整块藏起来，正在显示的提醒横幅会短暂消失，分包到了再出来。RemindHost 不会卸载，状态不丢。
  - R2：错误边界的 key 只在换账号时变。RemindHost 出错一次（包括离线时分包加载失败），这次打开就再也没有提醒了，没有自动重试，用户也看不到任何提示。`ErrorBoundary` 有 `componentDidCatch`，但错误码要等 B1 才接进日志。

### 3. remind 路由的地址只由 `openReminder`、`reminderHash` 生成，`?due=` 不会被转义
- **对。** 全仓库调 `openReminder` 的只有横幅、“错过的提醒”、整页提醒的“下一条”三处。`openReminder` 在 `/app/` 里时直接 `l.hash = reminderHash(...)`，不经过 `hrefOf`、`navigate`；不在 `/app/` 时用 `reminderPath` 整页跳转。没有任何地方用 `hrefOf('remind', …)` 或 `navigate('remind', …)`。
- `parseHash` 会把地址拆成 `name = 'remind'`、`params = ['event', '<id>?due=…']`，App 据此挂整页提醒。页面自己用 `useSyncExternalStore` 读 `location.hash`，交给 `parseReminderHash` 严格校验，不依赖 router 的 params。
- 同一个页面里点“下一条”：`pageKey` 都是 `'remind'`，页面不会重新挂载，但页面订阅了 hash，内容会更新。
- 测试第 68 行覆盖了“带 `?due=` 的地址能进整页提醒，RemindHost 拿到的路由是 `remind`”。

### 4. `.layer` 铺满视口但不接点按，会不会挡住页面点击，读屏会不会受影响
- **不挡点击。** `.layer` 是 `pointer-events: none`，只有直接子元素（横幅、按钮条、提示）设回 `auto`。横幅和按钮条以外的区域，点击会穿过去落到页面上。
- **为什么要这一层：** Appear 的 toast 进场以后，外层留着 transform，`position: fixed` 的子元素会按这一层定位。把外层本身铺满视口，子元素的 fixed 就等于按视口定位。截图 1 里横幅贴顶、按钮条贴底，位置是对的。
- **层级：** `.layer` 是 40，`.layerNote` 是 41。弹层 Dialog 是 70、Popover 80、版本横幅 50，都在提醒上面；撤销条 30 在提醒下面。这和接线之前横幅、按钮条各自的 z-index 一致。
- **读屏不受影响。** `.layer` 是一个没有 role 的 div，不会给读屏增加东西；横幅、按钮条（`role="group"`）、提示（`role="status"`）的语义都在里面，读的顺序是 DOM 顺序，在页面之后。
- 小问题（低，R4）：退场动画那一小段时间里（toast 退场），子元素仍然可以点。Dialog 是按 `data-state="leaving"` 不接点按的，这里没有。可以给 `.layer[data-state='leaving'] > *` 加 `pointer-events: none`。
