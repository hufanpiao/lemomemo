# 节假日数据（tools/holidays/）

月历显示的中国、韩国节假日（架构 5.12 第 1 点、5.4；B2 BE-5）。数据是静态 JSON，前端按要显示的国家和年份拉取，服务器不用（推送不看节假日）。

## 放在哪

```
src/public/holidays/cn/<年>.json    中国（放假日 + 调休补班日）
src/public/holidays/kr/<年>.json    韩国（공휴일 + 대체공휴일 + 임시공휴일）
```

构建后对应网址 `/app/holidays/<cn|kr>/<年>.json`。文件不带哈希、不进预缓存，SW 先联网、失败才用缓存，所以改了文件不用发新版 App。

## 格式

```json
{
  "country": "cn",
  "year": 2026,
  "days": [
    { "date": "2026-01-01", "kind": "off", "name": { "zh": "元旦", "ko": "신정" } },
    { "date": "2026-01-04", "kind": "work", "name": { "zh": "元旦补班" } }
  ]
}
```

（上面只是说明格式的样子，日期不代表真实安排。）

| 字段 | 必填 | 说明 |
|---|---|---|
| `country` | 是 | `"cn"` 或 `"kr"`，必须和所在目录一致 |
| `year` | 是 | 数字，必须和文件名一致 |
| `days` | 是 | 数组，按日期从早到晚排；一天一条，两个节日撞在同一天就写两条（名称不同） |
| `days[].date` | 是 | `YYYY-MM-DD`，必须在这一年里 |
| `days[].kind` | 是 | `"off"` 放假；`"work"` 调休补班（只有中国有，必须是周六或周日） |
| `days[].name` | 是 | `{ "zh"?: 中文名, "ko"?: 韩文名 }`，本国语言那份必填（中国填 `zh`，韩国填 `ko`），另一种可不填，界面缺了就显示本国语言的；每个 1～40 个字符 |
| `days[].sub` | 否 | 只有韩国的대체공휴일写 `true`（必须是工作日、`kind` 为 `off`）；不是就不写 |

- 放假期间的每一天都单独列一条，包括落在周末的那几天（例如春节连休 8 天就写 8 条），这样格子里每天都标“休”。
- 韩国的공휴일落在周末也照样列；因此产生的대체공휴일另列一条，加 `"sub": true`，名称写成“대체공휴일(어린이날)”这类。
- 整份写成 `[]`，或者 `days` 为空数组，表示“这一年没有节假日”。
- **中国下一年还没公布（架构 5.12）**：有了真实的当年数据之后，中国下一年的通知没公布前放一个 `days` 为空的文件，并写上 `"pending": true` 注明“未公布”，例如 `{"country": "cn", "year": 2027, "pending": true, "days": []}`；公布后换成真实数据，同时去掉 `pending`。`pending` 只能和空的 `days` 一起出现，前端不读它，照“这一年没有节假日”显示。**韩国不放空文件**：按《월력요항》写明年的文件，没写之前不放。
- 不为了消掉 W2 警告编造任何数据。
- 除上面这些字段外不许有别的字段；文件存成不带 BOM 的 UTF-8，单个文件不超过 16 KB。

前端读法见 `shared/logic/calendar/holidays.ts` 的 `parseHolidayFile`（多出来的 `sub` 前端现在不读，不影响显示）。

## 数据从哪来

只用官方发布的原文，逐日抄录，**不按惯例推算、不从第三方网站转抄**。每个文件提交时在提交说明里写清出处（文件名、发布日期、网址）。

| 国家 | 来源 | 什么时候公布 |
|---|---|---|
| 中国 | 国务院办公厅《关于 YYYY 年部分节假日安排的通知》（中国政府网 www.gov.cn），放假日和调休补班日都以它为准 | 一般在前一年 10～12 月 |
| 韩国 | 「관공서의 공휴일에 관한 규정」（국가법령정보센터 law.go.kr）定哪些日子是공휴일、哪些适用대체공휴일；阴历节日（설날、부처님오신날、추석）的公历日期按 KASI（한국천문연구원）每年发布的《월력요항》；임시공휴일 按政府（국무회의 의결）的公告临时补 | 월력요항一般在前一年 6 月前后；임시공휴일不定期 |

韩国的설날、추석一律按韩国阴历算，中国的春节、中秋一律按中国农历算，和每条纪念日选的阴历版本无关（架构 5.4）。

## 怎么更新

1. 拿到官方原文后，按上面的格式写 `src/public/holidays/<国家>/<年>.json`。
2. 跑 `npm run check:holidays`，校验结构、日期、年份和文件名是否一致、放假和补班是否撞日、补班是否在周末、대체공휴일是否在工作日。
3. 跑 `python -I build/check_arch.py`，看 W2 那条“缺明年的节假日文件”是不是没了。
4. 按平常的流程提交、审查；提交说明里写清出处。

## 每年谁来更新

- 后端负责维护。每年 **11 月初**查一次中国明年的通知；12 月底还没公布就记进负责人的待确认清单，公布后再补。
- 韩国：每年 **7 月**根据《월력요항》写明年的文件；政府宣布임시공휴일后一周内补进当年的文件。
- 平时 CI 里 check_arch 的 W2 会对“缺明年文件”报警告，不会让构建失败。

## 校验脚本

`tools/holidays/check.mjs`：导出 `validateHolidayJson(json, country, year)`、`checkFile(path, country, year)`、`checkDir(dir)`；
命令行 `node tools/holidays/check.mjs [--root <目录>]`。单测在 `tests/build/holidays-check.test.ts`，用的都是明确标为样例的假数据。
